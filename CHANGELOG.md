# Changelog

One line per layer per notable change. Versions here track the project's own `v0.x` designation, not any single schema's version number (those are tracked in the schema files themselves — `ontology_version`, `kit_version`, and so on).

## Unreleased (this session, 23 Aug 2026 onward — WP-0.1 through in-progress work)

- **Consolidation (WP-0.1).** v0.6 extracted onto disk as the working tree; `Plan Examples/` (26 reference images) folded in; git initialized; stale duplicates and superseded generations identified and moved off the tracked tree (see `docs/reports/wp-0.1-repo-consolidation.md`).
- **Documentation (WP-0.2).** `README.md` counts corrected and made generatable (`build/gen_readme_counts.py`); `mcp_server/README.md` regrouped to list all 23 tools by layer; `docs/open-questions.md` items 1, 2, 12, 13, 17, 23, 24, 25 resolved and recorded; `docs/README.md` index added.
- **Behaviour tests (WP-0.3).** `tests/` — 35 pytest tests pinning validator, composer, kit cascade, proportion engine, and geometry behaviour against the docs' own claims (two counts corrected where they'd drifted); `build/check_all.py` / `make check` as a single entry point over all data checkers plus pytest. OQ 26 raised (undocumented `EQUIVALENT` room-alias groups).
- **Constraint rule language (WP-1.1).** `schema/constraint.schema.json` (reuses the fault corpus's `test` pattern per OQ 24, extended with `one-of` and `scope`); `build/constraint_vocabulary.py` (68 named variables); `build/check_constraints.py` (new 14th check, wired into `check_all.py`); worked-example migration of 140 constraints across the `english-classical` and `american-colonial` families (106 tested, 34 honestly `scope: judgment`); `docs/constraints.md`. Remaining ~520 constraints across ~25 families not yet migrated. OQ 27 raised (tagging judgment-scope constraints blocked by OQ 22 specifically).
- **Correction to WP-0.2's own record.** `docs/open-questions.md` items 12, 13, and 17 falsely claimed "Executed in WP-1.3" — WP-1.3 had not run. Found and corrected in place (with dated correction notes) while migrating constraints; `docs/reports/wp-0.2-documentation-reconciliation.md` carries a matching correction. See `docs/reports/wp-1.1-constraint-rule-language.md`, "what was found."
- **Kit schema operators (WP-1.3).** Ontology bumped 0.4.0 → 0.5.0 (93 → 95 slots): `wall_thickness_masonry`/`wall_thickness_frame` (OQ 12, the fourth and last trade split), `derives_from_module` cross-references on `cornice`/`frieze`/`modillion_dentil`/`crown`/`chair_rail` (OQ 13). `build/resolve_kit.py`'s `rule_append` merge operator now actually resolves (OQ 16); a new `docs/inheritance.md` section on regional-conditionality mechanism choice, applied to reconcile `service_zone_strategy`'s Tidewater duplication (OQ 17); `--date YEAR` date-conditional variant resolution (OQ 22). `docs/inheritance.md` also had independent stale prose (slot counts, a Constraints section describing a rule language that didn't exist yet) corrected in passing. See `docs/reports/wp-1.3-kit-schema-operators.md`.
- **Validator reads constraints (WP-1.2, closing Phase 1).** `build/plan_check.py`'s STYLE LAYER now evaluates a migrated constraint's `test` object via `mcp_server/core.py`'s `_eval_test` (extended with `one-of` direction support) against `plan.measurements` plus five values `derive_constraint_vars` reads off unambiguous plan structure — a pass is silent, a fail is a finding at a severity `CONSTRAINT_SEV` maps from the constraint's hard/soft/advisory, a constraint with a missing variable is an honest `info` finding, never silently passed. `result["constraint_summary"]` reports present/clear/unjudged. Both shipped example plans' pinned fatal/serious/minor counts are unchanged; the deliberately-wrong-Tidewater-pitch case PLAN-OF-ACTION.md's own acceptance criterion names is pinned directly. `mcp_server/core.py` gained `check_style_constraints` and `measurement_vocabulary` now folds in constraint-sourced variables (23 → 24 MCP tools, new `tdl_check_style_constraints`); `compose.py`'s scoring already covered a failed hard constraint with no code change (verified, pinned). 13 new tests. See `docs/reports/wp-1.2-validator-reads-constraints.md`.
- **Reference corpus (WP-2.1, opening Phase 2).** 14 plan records under `plans/reference/` transcribed from `Plan Examples/` (all 8 Bad Examples files, as 7 records — two files are one two-level house; 7 of 20 Good Examples). Two room-catalogue gaps found and evidenced with pinned tests: `gallery-corridor` is missing from `plan_check.py`'s `EQUIVALENT` entrance-hall alias group, and `primary-bedroom`'s must-adjoin rule for `primary-bathroom` has no `via` allowance for a dressing room — both recur independently across different source drawings. ROOM and FURNITURE layer findings skew markedly toward the bad examples (45 vs 6, 63 vs 23 fatal+serious); ADJACENCY does not, mostly because of the two gaps above plus this transcription's own porch-typing and window-survey limitations, discussed honestly rather than read as a validator weakness. No validator or catalogue file edited — proposals only. See `docs/reports/wp-2.1-reference-corpus.md`.
- **Site layer (WP-2.4).** `schema/plan.schema.json` and `schema/brief.schema.json` gained a `site` object (street bearing, three setbacks, slope direction, cross-slope, prevailing summer wind, piazza bearing, party-wall condition) additive to the pre-existing `context.lot_width_ft`/`lot_depth_ft`/`entrance_faces`, which stayed put rather than move and break the reference corpus. `build/compose.py`'s `footprint()` now caps a candidate's bay count to what the stated lot can hold and drops (not merely outscores) a candidate that cannot reach even its own minimum bay count, recorded in a new `dropped_lot_infeasible` list; `build/geometry.py`'s independent bay-grid solver needed the identical fix a second time, discovered by an end-to-end render smoke test that showed a "24 ft" candidate solved 50 ft wide, straddling its own lot line — both are pinned against a 30 ft-usable-lot brief that reproduces PLAN-OF-ACTION.md's own worked example (a 24 ft town-house parti, not a five-bay Georgian). `build/plan_check.py`'s `derive_constraint_vars` now reads all of `plan.site` into the constraint namespace, which is what actually made the two already-migrated site-scope constraints (the Charleston piazza bearing, the Pennsylvania bank house's cross-slope) evaluable for the first time — the WP-1.2 mechanism was already generic enough, it just had nowhere to read site data from. `build/render_plan.py` draws the lot boundary, a setback envelope, and a north arrow with the street bearing when a plan states one, unchanged when it doesn't. Kit-slot consumption: 5 of the 7 site-and-settlement slots were already flowing through the pre-existing `canonical_choices()`; the other two (`orientation_rule`'s editorial prose, `setback_rule`'s deliberate `open`) gained a new `site_kit_log()` so they reach the decision log instead of vanishing. 29 new tests. See `docs/site.md`.
