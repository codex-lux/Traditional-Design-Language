# OQ 69 — a session-scoped test fixture gates every test file that sorts after it

*Status: CLOSED 26 AUG 2026 · Raised in: Reissued 26 August 2026 — ids 64 and 65 collided a second time*

**CLOSED 26 Aug 2026 — the token is configured per test, and a guard sorts last to keep it that way.** Ruled: stop the fixture mutating process-wide state, keep exercising the real gate. The two constraints were never the same constraint. The CLIENT must stay session-scoped — `session_manager.run()` raises if entered twice, so the lifespan may be entered once per process. The TOKEN only needs to exist while a request in that file is in flight, and `monkeypatch` is exactly that: function-scoped, restoring after each test, invisible outside the test that asked. The fixture's original note said env was set directly "because monkeypatch is function-scoped", which was true of the client and merely assumed of the token. **Not done as literally ruled, for a reason worth recording:** a client carrying a default `Authorization` header cannot coexist with `test_bearer_is_required`, which proves the gate by sending no header at all — so the header stays on the requests that mean to be authorised and off the one that does not, and what changed is that the server-side token is configured for one test instead of for the process. **`workbench/server/tests/test_zz_auth_leak_guard.py`** asserts that no gate variable survives into it and names the cause and the remedy in its failure message; the `zz` is load-bearing, because a guard against "something earlier leaked" only works if it runs after everything it guards. Proved by reintroducing the leak: the guard fails naming the variable, beside the downstream 401 it explains. *Original entry follows.*<br><br>**OPEN — a session-scoped test fixture gates every test file that sorts after it.** `workbench/server/tests/test_mcp_http.py::live` sets `WORKBENCH_API_TOKEN` in `os.environ` directly and restores it at **session** teardown. The direct assignment is deliberate and its docstring explains why — monkeypatch is function-scoped, and a function-scoped fixture tore down when the runner left the file and could not re-enter it, turning seven tests into spurious errors. But the consequence reaches outside the file: from the moment that fixture first runs, `auth.required()` is true for the rest of the session, so **every test file sorting after `test_mcp_http` runs against a gated server**, and any plain `client.get("/api/…")` in one gets a 401 that has nothing to do with the route under test. Found because `test_search_index.py` passed alone and failed in the suite; it now states its own unauthenticated baseline explicitly, with the reasoning in place, which is a workaround and not a fix. Three ways out, none obviously right: give the fixture its own `TestClient` with a bearer header and stop touching the environment at all (cleanest, but the fixture's whole point is to exercise the real gate); restore the environment in an autouse function-scoped fixture *within that file only*; or accept it and make "state your own auth baseline" a documented convention for endpoint tests. The first is probably correct and is a rework of a file whose reasoning is sound, so it wants a ruling rather than a drive-by.
