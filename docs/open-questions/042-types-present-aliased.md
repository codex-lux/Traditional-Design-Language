# OQ 42 — `types_present` is not aliased

*Status: CLOSED 24 AUG 2026 · Raised in: From the real solver (WP-2.3, 25 Aug 2026)*

**CLOSED 24 Aug 2026 — the sentence is corrected, the severity deliberately is not, and measuring it changed the answer.** `types_present` is now aliased for the one question it decides: whether the claim *and the plan models none* is true. Across all 129 composable styles, **542 completeness findings now say the true thing** instead of a false one, and the catalogue's fatal count does not move.
**What the measurement changed.** The obvious fix — alias it and let the finding fall through to the adjacency branch at the rule's own strength — was the one this entry originally proposed. Measured across the catalogue it turns **170 of those findings FATAL across 87 styles**, which would leave two thirds of the corpus unable to return a clean plan. The cause is that EQUIVALENT is **asymmetric in practice and symmetric in the code**: a primary bathroom satisfies a request for a bathroom, and a hall bathroom does not satisfy a primary bedroom's request for a primary bathroom. Until each pairing states which direction it satisfies in, promoting these is trading 774 false minors for 170 false fatals. So the finding stays `minor`/`completeness` and says what it can actually see: *"wants to adjoin an entrance hall; the plan models centre passage and stair hall instead, which the catalogue treats as equivalent, and does not reach any of them."*
**And a room cannot satisfy its own rule through its own alias group** — the modelled set is computed without the room doing the asking. Without that, the kitchen's rule to adjoin a scullery was answered by the kitchen being a kitchen: true of the group, nonsense as a statement about the plan. That is why 542 and not 774. The directional question is **OQ 43**. *Original entry follows.*<br><br>**`types_present` is not aliased.** Found under OQ 37 and deliberately not fixed there. `plan_check.py` runs every adjacency target through `_alias()` when asking what a room is next to, but the "the plan models none" branch — which decides whether an unmet rule is a *completeness* finding or an *adjacency* one — tests `rule["room"] not in types_present` against raw types. So `plans/tidewater-georgian-careful.json`, which has a centre passage on its ground floor, still reports "Powder Room wants to adjoin a entrance hall and the plan models none" after `centre-passage` joined that group. The finding is minor and the claim is simply false. The fix is one line and its blast radius is a shift of some minor findings from *completeness* to *adjacency*, which is a change in what the validator SAYS about a plan, not only in how many things it says — so it wants measuring against the reference corpus before it is made, not folding into an unrelated package.
