# OQ 12 — `window_head` wants splitting

*Status: CLOSED 24 AUG 2026 · Raised in: From authoring the Georgian kit*

**CLOSED 24 Aug 2026 — all four splits exist; the ruling's naming was amended to the corpus, not the corpus to the naming.** `window_head`, `corner_treatment` and `window_surround` were split by trade in ontology 0.3.0 (pre-session, Georgian-kit authoring); WP-1.3 added the fourth, `wall_thickness_masonry` / `wall_thickness_frame`, and `elements/slots.json` now stands at 0.5.0 with all eight ids live and none deprecated. The ids read `window_head_masonry`/`window_head_wood`, `corner_quoin`/`corner_board`, `window_surround_masonry`/`window_surround_wood` — not the `_carpentry` naming this ruling wrote. **Deliberately not renamed.** The ruling names trades; the ids name materials, which is what every downstream kit binding, constraint and fault already says. Renaming eight live ids to match the wording of the question that asked for them would spend a migration and eight `deprecated_in_favour_of` records on nothing a reader would notice. The mapping is recorded here instead. `window_surround` was split in two rather than kept single with an added `none` value; the design intent survives by a different mechanism — `window_surround_masonry` carries `none-opening-cut-in-the-mass` as an example value, so masonry's correct answer is still a stated none and not an absence. Pinned by `tests/test_ontology.py`. *Original entry follows.*<br><br>**`window_head` wants splitting.** A gauged brick jack arch is made by the mason, is structural, is cambered by opening/96, is four courses deep, and is laid on a centre before the wall closes. A moulded wood cap is made by the carpenter, is non-structural, and is nailed on afterwards. They share nothing but the opening. The same disease affects `wall_thickness_expression`, `window_surround` (whose correct masonry value is `none`, which is an answer and not an absence), and `corner_treatment` (which conflates the quoin, an order element, with the corner board, a trim element — and that conflation is why `facade-classical` was applying an 18-inch masonry rule to a 6-inch framed condition). **Ruling: split all four by trade.** `window_head` → `window_head_masonry` (jack arch / lintel, structural) + `window_head_carpentry` (moulded cap, non-structural); `corner_treatment` → `corner_treatment_masonry` (quoin, an order element) + `corner_treatment_carpentry` (corner board, a trim element); `window_surround` keeps its id and gains `none` as a legitimate value for bare masonry openings; `wall_thickness_expression` splits by construction trade.
**Correction, 23 Aug 2026:** this entry previously (and wrongly) said "Executed in WP-1.3." WP-1.3 has not run. Checked directly against `elements/slots.json` while migrating constraints (WP-1.1): three of the four splits already exist, but they predate this ruling and this session entirely — `window_head_masonry`/`window_head_wood`, `corner_quoin`/`corner_board`, and `window_surround_masonry`/`window_surround_wood` were split in ontology **0.3.0**, part of the original pre-session Georgian-kit authoring. They don't match the ruling's own naming: the carpentry slot is `window_head_wood`, not `window_head_carpentry`; the split pair is `corner_quoin`/`corner_board`, not `corner_treatment_masonry`/`corner_treatment_carpentry`; and `window_surround` was split into two ids rather than kept single with an added `none` value — though `window_surround_masonry` already carries `none-opening-cut-in-the-mass` as an example, so the underlying design intent (masonry's correct value is a legitimate none, not an absence) is already satisfied by a different mechanism than the one this ruling specifies. `wall_thickness_expression` has no split, and no slot by any wall-thickness name currently exists at all. Ontology is still 0.4.0 and kit schema still 0.2.1 — neither bumped. WP-1.3 needs to either rename the three existing splits to the ruling's naming (a real migration: `deprecated_in_favour_of` on the old ids) or amend this ruling's wording to match what already exists and document the mapping — and, either way, actually build the missing `wall_thickness_expression` split, which nothing on disk currently does under any name. *(Superseded by the closure above — WP-1.3 has since run and built the fourth split. Kept as the record of what was true on 23 Aug, and of why the naming mismatch was found rather than assumed.)*
