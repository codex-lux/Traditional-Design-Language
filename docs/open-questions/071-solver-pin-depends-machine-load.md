# OQ 71 — a solver pin that depends on machine load

*Status: CLOSED 26 AUG 2026 · Raised in: Reissued 26 August 2026 — ids 64 and 65 collided a second time*

**CLOSED 26 Aug 2026, then CORRECTED the same day by an adversarial audit of the closure itself.** The first fix asserted neither the proof nor the count. Its skip matched the sentence `geometry.py` emits for EVERY unsolved status, so a structurally invalid CP model skipped exactly like a loaded machine — the one assertion between the corpus and a silently degraded solver, disarmed by the regression it names (proved by patching `solve_cp` to return `MODEL_INVALID`: skipped, pytest exit 0). And its "proven-or-carried" check pinned two string literals lifted from the source, of which the `PROVEN` branch is never reached at 60 s — 17 restore attempts, 8 OPTIMAL, 9 UNKNOWN, 0 INFEASIBLE — so making `geometry_cp.py` emit `"proven"` unconditionally, i.e. deleting the bookkeeping the test claims to guard, left it green. Now: `geometry.py` names its fallback (`budget` vs `engine`) so the two cases are separable in fact rather than in wording, and the test asserts against `attempts`, the reinstatement pass's own record — a note may claim proof only for a pin that run actually proved infeasible. Verified by mutation. The bound is also tightened from `< declared` (which permitted 34 of 35) to half. *Original closure follows.*<br><br>**CLOSED 26 Aug 2026 — it asserts the proof now, and says so when it cannot judge.** Ruled: assert the proof, not the count. The count was a proxy for the property that matters and a bad one, because how many pins survive the reinstatement pass is wall-clock-dependent — that pass restores each downgraded pin alone at the drawn footprint and needs 2.5 s of remaining budget apiece, so a loaded machine carries pins it would otherwise have restored or individually proved. The property is that a downgrade is never SILENT: every pin must carry a stated refinement naming its room and wall, and that refinement must say which of the two things it is — proven infeasible alone, or carried from the core and explicitly not re-proved. A third, unstated path is the failure the test exists to catch, and so is a pin with no note at all. That holds under any load, being a property of the report rather than of the clock. The other direction keeps a bound, but a load-independent one: fewer pins downgraded than the plan declares, or the model has stopped enforcing walls and started narrating them. **Found while proving the fix, and fixed with it:** under 4x CPU oversubscription CP-SAT does not run at all and the dispatcher falls back to the hill-climb, so the test's other assertion — that the engine is cp-sat — failed. Same species of error, so the same discipline applies: a budget fallback now skips as COULD NOT EVALUATE with the dispatcher's own stated reason, while a fallback for any other cause still fails. Verified at three loads: idle passes, 3 spinners on 4 cores (the realistic full-suite condition that produced the flake) passes, 12 spinners skips. *Original entry follows.*<br><br>**OPEN — a solver pin that depends on machine load.** `tests/test_solver.py::test_check_plans_solve_with_stated_downgrades` asserts at most 8 downgraded wall pins on `tidewater-georgian-careful` and intermittently measures 9. Not a regression and not new: the identical failure reproduces at commit `12e1dd0` in a clean worktree, and the test's own comment predicts the mechanism — *"engine identity near the budget edge is wall-clock-dependent (a loaded machine turns a 30s OPTIMAL into UNKNOWN → heuristic fallback)"*. Observed failing under `build/check_all.py` on three consecutive runs and passing on a direct `pytest tests/` of the same tree, which is the signature. The pin is defending something real — *"downgrade-without-proof is the failure this pin exists for"* — so raising the bound to 9 would blunt it, and the honest options are to give this one test a time budget generous enough to be deterministic on a loaded machine (the 60 s already there is evidently not), to assert on the *proof* rather than the count, or to mark it as a known-flaky check with its own state in `check_all.py` the way the missing-library case got `N/EV`. Raised from WP-5.6, which did not touch the solver and only needed to establish that it had not broken it.
