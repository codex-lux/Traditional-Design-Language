# OQ 75 — 497 MB of the image, 85.5% of its dependency layer, is three libraries that every endpoint is designed to work without

*Status: OPEN · Raised in: From the infrastructure audit (27 August 2026)*

**OPEN — 497 MB of the image, 85.5% of its dependency layer, is three libraries that every endpoint is designed to work without.** Measured with `pip install --target`: the server, rail and MCP need 84 MB; adding `ezdxf`, `ifcopenshell` and `ortools` takes it to 581 MB, and they drag in `pandas` (76 MB), `numpy` (73 MB), `fontTools` (28 MB) and `shapely` (12 MB) behind them. All three are optional AT RUNTIME by explicit design — `geometry.solve` falls back to the heuristic and says so in `geometry_report.solver`, and `/api/export` refuses with a stated 501 rather than an empty file. So the corpus already knows how to be honest about their absence, which is exactly what makes this a real question rather than a rhetorical one: a slim image would work, would deploy faster, and would silently stop offering CAD export and CP-SAT proofs to anyone who did not read the refusal. Worth noting that the refusals are per-endpoint, so the degradation is legible rather than mysterious. Options: ship everything (today); ship slim and lose two features; or build two images and let the deployment choose, which doubles the CI matrix for a corpus that has one deployment.
