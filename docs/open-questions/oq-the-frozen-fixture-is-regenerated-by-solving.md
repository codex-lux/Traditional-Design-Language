# oq/the-frozen-fixture-is-regenerated-by-solving — the contract fixture's own README says why that cannot work, and its generator does it anyway

*Status: OPEN · Raised in: WP-11.6, the record says what it means (5 September 2026), found in ordinary work*

**OPEN — `tests/fixtures/sheet_symbols/` freezes a placement so two renderers can be held to one
contract. `tests/fixtures/sheet_symbols/README.md` states the reason in its own words. Its
generator then produces that placement by calling the live solver on `engine="auto"`, which is
CP-SAT under a wall-clock budget, so the fixture is not reproducible and the regeneration the
README instructs is mostly solver noise.**

## The contradiction, quoted from one file

`tests/fixtures/sheet_symbols/README.md`:

> Freezing matters: the live solver picks CP-SAT or the hill-climb depending on whether CP-SAT
> answers inside its budget on *this* machine, so **a fixture generated by solving would pin the
> machine as much as the code.**

and, eleven lines later:

> Regenerate with `python3 tests/fixtures/sheet_symbols/generate.py` and read the diff before
> committing it: a fixture that changes because a renderer changed is the record of that change,
> and a fixture edited to make a test pass is the guard being removed.

`tests/fixtures/sheet_symbols/generate.py:40` is `solved = geometry.solve(plan)` — no `engine`
argument, so `auto`.

## The measurement

On the **pristine tree**, with no code change of any kind, regenerating both fixtures:

```
2 files changed, 825 insertions(+), 804 deletions(-)
```

`spec-builder-colonial.json` moves as much as `tidewater-georgian-careful.json`. Two consecutive
regenerations on the same tree produced diffs of the same size against the committed copy, so the
committed fixture is not what this machine solves today and has not been for some time.

The consequence is precisely the one the README warns about: **"read the diff before committing
it" hands the reader eight hundred lines of solver output with the renderer's change buried
somewhere inside it**, and the fixture in git records whichever machine last ran the generator.

## Why WP-11.6 did not simply fix it

The obvious repair — `engine="heuristic"`, which is deterministic and identical on cold runs
everywhere in this repo that needs a stable number — is one word, and it rewrites both fixtures
once. That changes the frozen placement both `tests/test_sheet_symbols.py` and
`workbench/app/src/derive.test.mjs` derive their contract from, on a package about stacking
claims. It is a separate change with its own blast radius and it deserves its own commit and its
own reading of the resulting diff.

WP-11.6 therefore **left the fixtures untouched** — it neither regenerated them nor edited them —
and its own record change does not require them to move, because the fixture is contract INPUT
and is never re-solved by the suites that read it.

## What must be ruled

1. **Which placement should the contract freeze?** The three candidates are not equivalent:
   - a `heuristic` solve, reproducible everywhere, and a re-run is then a real signal;
   - a hand-authored placement, which owes nothing to any engine and can be shaped to exercise
     the awkward cases (a door at a corner, a window meeting a jamb) that a solver may never
     produce;
   - the current arrangement, i.e. keep `auto` and accept that the fixture is a snapshot of one
     machine, in which case the README's paragraph should be corrected rather than the code.
2. **Should regeneration be checkable?** `gen_open_questions.py --check` and
   `gen_sheet_font.py --check` both exist so a committed artefact can be proved current. That is
   only possible for a deterministic generator, so this question is downstream of (1).
3. **Is the drift itself a finding about the renderers?** Nobody has read the 800-line diff. Some
   of it is the placement moving; some of it may be `derive_openings` answering differently. Until
   (1) is ruled there is no way to tell those apart, which is the real cost.

## The rule this is an instance of

A generated artefact nobody can rebuild identically is an artefact nobody can verify —
`build/gen_sheet_font.py`'s `recalcTimestamp=False` finding (WP-11.5), one directory over and in
a place where the file's own documentation had already worked out why.
