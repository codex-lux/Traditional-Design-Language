# OQ 73 — the container ships in the open configuration by default, and only a variable a person must remember closes it

*Status: OPEN · Raised in: From the infrastructure audit (27 August 2026)*

**OPEN — the container ships in the open configuration by default, and only a variable a person must remember closes it.** `Dockerfile` sets `WORKBENCH_HOST=0.0.0.0`, and `auth.required()` is `bool(password() or api_token())` — so an image built and deployed with no `WORKBENCH_PASSWORD` binds every interface with `authorised()` returning True for every request. `__main__.py` prints a warning and `/api/health` reports it in words, which is honest and is not a control. This is not hypothetical: commit `bc2dfec` read `auth: {"required": false}` off the live deployment on 26 August. The obvious fix — refuse to bind a non-loopback host with no gate configured — is the right safety property and is also a change that takes the live site down on its next deploy if the variable is still missing, converting a silent exposure into a loud outage. That is a trade only Lucas can make, and it wants a decision rather than a default: (a) refuse and fail loudly; (b) bind but serve a hard-coded "unconfigured" page on every route until a gate exists; (c) leave it, on the argument that the warning plus `/api/health` is enough for an operator who reads them. Note that (a) and (b) both need a documented escape for someone who genuinely wants an open instrument on a private network.
