# OQ 39 — the record's vertical opening data is thin and half-dormant

*Status: HALF CLOSED 26 AUG 2026 · Raised in: From the export layer (WP-5.1, 25 Aug 2026)*

**HALF CLOSED 26 Aug 2026 — the door half is built; the window half is unchanged and the judgment this entry asks for is untouched.** Plan schema 0.3.0 (WP-6.2) gives a door a `height_ft`, which is the field this entry says had none. It is written by the composer from the kit's own graduation (`principal 84 in, secondary 80 in, service 78 in`) by way of the opening grammar's `rank`, so three faults that test a door height and could not be evaluated from a plan record at all — `six-eight-door-in-a-tall-room`, `every-door-the-same-door`, `door-too-wide-for-its-surround` — now have a number to read. **What is NOT closed:** `window_sill_ft` is still the elevation layer's judgment and the IFC still defaults it at 2.5 ft, marked editorial; and the question this entry actually asks — whether those figures should be authorable record fields or stay a derivation — is answered for doors by having been built and remains open for windows. *Original entry follows.*<br><br>**OPEN — the record's vertical opening data is thin and half-dormant.** A plan record states a window's `width_ft`, `height_ft` and sometimes the room's `window_head_ft`; the schema has carried an optional `sill_ft` per window since 0.1.0 but **no plan in the corpus uses it and (until WP-5.5) no build code read it** — the IFC exporter now prefers it when present. Door leaf heights have no field at all. The classical elevation generator derives all of this from its packs — but only inside its own scope gate, and the IFC export (WP-5.1) needs a number for every opening it gives a body. Today it uses editorial defaults (2.5 ft sill, 6 ft 8 in door leaf), each named `editorial` in the element's own TDL Pset rather than laundered as record data. The question: should `window_sill_ft` / `door_leaf_height_ft` join the plan schema as authorable fields, or stay the elevation layer's judgment with the IFC honestly defaulting? Surfaced by WP-5.1; worked around in the open, not silently.
