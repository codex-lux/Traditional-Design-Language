# OQ 49 — a node can need one rule of a pack without being an instance of the pack's type, and the binding model cannot say so

*Status: CLOSED 25 AUG 2026 · Raised in: From the real solver (WP-2.3, 25 Aug 2026)*

**CLOSED 25 Aug 2026 — a binding can be scoped to slots, and the corpus reached 132 of 132.** Ruled as proposed: an optional `slots` array on `proportion_packs[]`, which is OQ 36's mechanism one layer out — that ruling scoped a `hybridizes_with` edge so a donor could transmit one aspect rather than an entire kit; this scopes a BINDING so a pack can supply one rule to a node that is not an instance of its type. Absent means the whole pack, which is the historical behaviour and stays the default. `build/resolve_kit.py::eval_packs` filters on it, which is the only place it can be enforced — everything downstream reads `by_slot` and cannot tell where a rule came from, which is exactly how `role: optional` plus a note in prose failed to scope anything.
**Slot-level granularity alone would not have served the cases that motivated it**, and finding that out changed the field. `jetty-overhang` writes `material_change_rule` once, so a bare slot id is right there. But `facade-portada` writes `ornament_vocabulary` FOUR times and only its rationing rule applies to `mission-revival`, and `facade-peristyle` writes `column` seven times of which two fit `egyptian-revival`. A scope admitting three rules nobody asked for would have been a smaller version of the problem the field was added to solve, so an entry is either a bare slot id or `slot/dimension`.
**The three bindings.** `french-normandy-revival` ← `jetty-overhang` scoped to `material_change_rule`: it states that rule almost verbatim and has no jetty. `mission-revival` ← `facade-portada` scoped to `ornament_vocabulary/event_count`: it carries a rule about that pack's subject stating there is none. `egyptian-revival` ← `facade-peristyle` scoped to `column/front_count` and `column/intercolumniation_roman` — **and the exclusions are what make it defensible rather than a way of reaching 132.** The whole pack would have handed it a peristyle count it has no peristyle for, a Vitruvian column-height function, a stylobate curvature, a corner contraction, and an ENTASIS its own c04 forbids outright. Six of the eight `column` rules are excluded, including the one the node prohibits. `DELIBERATELY_UNBOUND` is now empty and is kept rather than deleted, because the mechanism it names is still right for a node that genuinely fits nothing.
**A checker, for the failure the field could itself cause.** A scope naming a slot the pack does not write is a silent no-op: the node gets nothing and the binding still reads as though it delivered a rule. `check_pack_bindings.py` errors on it.
**And closing this opened OQ 51**, which is larger. Verifying the `egyptian-revival` binding showed that `facade-peristyle` was ALREADY reaching that node from five ancestors through the lineage cascade, unscoped, entasis included — so the deliberate refusal had been cosmetic all along. See there.
*Original entry follows.*<br><br>**OPEN — a node can need one rule of a pack without being an instance of the pack's type, and the binding model cannot say so.** Found while binding `jetty-overhang` for WP-4.6. `styles/french-normandy-revival.json` states one of that pack's rules almost verbatim — a vertical change of wall material must occur "at a floor line, a water table, or a jetty, with a minimum 4 in. horizontal offset" — and `styles/tudor-revival.json` states the same rule in nearly the same words. Tudor Revival also jetties, so it is bound and gets the rule. French Normandy Revival does **not** jetty: it names a jetty as one permitted datum for something else. It is a CONSUMER of one rule and not an instance of the type, and binding a jetty module to it would make the corpus assert a framed overhang on a style that does not have one — a false claim about the building, made in order to deliver a true rule about a detail.
**The workaround available today is worse than the gap.** `role: optional` still says the pack applies; a note saying "bound only for `material_change_rule`" is prose that no resolver reads, and `build/resolve_kit.py` would hand the node the whole pack's fifteen rules including a jetty projection. That is the same class of problem as `hybridizes_with` transmitting a donor's entire kit (the trap CLAUDE.md already records and OQ 36 partly closed for hybrids), arriving now through bindings instead of through lineage.
**It is not a one-off.** The same shape is visible wherever a pack owns a rule about a device rather than the device itself: `storey-graduation`'s dormer rules are wanted by styles with no graduated storeys, `facade-arcade`'s springing rule by styles with one arch and no arcade, `opening-mullioned`'s light-count quantisation by styles with a single fixed light. Each is currently either bound whole, or left unserved and the rule restated in the node — and restating it in the node is exactly the duplication this library exists to remove.
The concrete proposal, so the next person does not re-derive it: give a binding an optional `slots` array scoping which target slots it may contribute — `{"pack": "jetty-overhang", "role": "optional", "slots": ["material_change_rule"]}` — which is the same mechanism OQ 36 built for `hybridizes_with`, applied one layer out, and would reuse its checker shape. Cost is a schema field on `proportion_packs[]` and a filter in the resolver. The alternative, and it is defensible, is to say that a rule wanted by nodes outside its pack's type does not belong in that pack at all and should be lifted into a small shared one — which is cleaner in principle and would mean deciding, for each such rule, whether the device or the rule is the real subject.
