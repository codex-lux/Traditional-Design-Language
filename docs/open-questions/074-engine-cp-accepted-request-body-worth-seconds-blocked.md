# OQ 74 — `engine: "cp"` is accepted from a request body and is worth 25–30 seconds of a blocked thread

*Status: OPEN · Raised in: From the infrastructure audit (27 August 2026)*

**OPEN — `engine: "cp"` is accepted from a request body and is worth 25–30 seconds of a blocked thread.** `app.py`'s `plan_evaluate` validates the engine NAME against `("heuristic", "cp", "auto")` and refuses anything else with a stated 422 — the comment says why, and it is about typos. It does not validate the COST. `geometry.solve`'s own docstring says `time_limit_s` "is a target, not a hard wall… a 15 s limit can take ~20 s of wall clock on a hard record before falling back", and the budget this route passes is 25 s (`geometry.BUDGET_INTERACTIVE_S`; WP-11.8 split the constant in two and `solve()`'s own default is now the 40 s BATCH budget, so a caller reaching `solve` by any route that does not name the interactive one is worth forty seconds rather than twenty-five). Any caller may therefore turn one request into half a minute of a threadpool thread, sixty times an hour per identity, on a server whose measured evaluate throughput is 2 per second. The endpoint offers `cp` deliberately — proving is an explicit act on the bench, and WP-2.3 built the CP engine precisely so a person could ask for a proof — so removing it would take away a real feature. The options are to keep it and meter it separately from the heuristic path, to route it through the compose job queue where long work already belongs and return a job id, or to leave it and accept that a proof costs what a proof costs.
