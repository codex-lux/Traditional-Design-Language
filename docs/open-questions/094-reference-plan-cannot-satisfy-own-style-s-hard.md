# OQ 94 — the reference plan cannot satisfy its own style's hard constraint, and only a person can say who fixes it

*Status: OPEN · Raised in: From the plan-semantics program (WP-6.1 / WP-6.2, 26 August 2026)*

**OPEN — the reference plan cannot satisfy its own style's hard constraint, and only a person can say who fixes it.** `styles/tidewater-georgian.json` c03 is `hard`: *"Centre passage 10-14 ft wide with exterior doors at both ends, aligned on axis and both operable. This is a ventilation device, not a hallway."* `groupings/centre-passage-core.json` says the same: *"Both ends of the passage have doors, and they are aligned."* **`plans/tidewater-georgian-careful.json`'s passage declares ONE exterior door and a window on its north wall.** WP-6.2's `op-passage-axis` now seats that one door at the end that is not already reached through the porch — the north end — so the rear door is drawn where it belongs and the front is entered through the porch, which is the correct reading of the plan as written. The constraint still is not satisfied, because there is only one door. Three ways out and each belongs to a different person: **correct the record** (add the second door — a change to a shipped reference plan, which is Lucas's to make); **let the composer author it** (a passage whose type demands doors at both ends gets both, which is the composer inventing plan content and is the thing it is built to refuse); or **let the drawn layer fail it** (report the missing door as a finding on every centre-passage plan, which is honest and would fire on a reference plan the corpus holds up as good). Nothing was done on the strength of it: the door that exists is placed correctly and the one that does not is not invented.
