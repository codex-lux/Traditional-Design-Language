# OQ 44 — The solver's answer depends on how fast the machine is

*Status: CLOSED 24 AUG 2026 · Raised in: From the real solver (WP-2.3, 25 Aug 2026)*

**CLOSED 24 Aug 2026 — reproducible by default, and the measurement is why.** Ruled after measuring the cost on both reference plans at a 20 s budget: the deterministic run costs between 0 and 33% more wall time (17.5 s against 18.1 s on one plan, 22.9 s against 17.1 s on the other), returns the **same score**, and on the busier plan explores **more** topologies — 6 against 4 — because it is not cut off part-way. The old default already reproduced on an idle machine, which is exactly why the defect passed every time anyone checked it. `deterministic=True` is the default of `solve()`; `deterministic=False` and `build/geometry.py --wall-clock` remain for when a person is waiting, and the record says which trade was taken. The MCP tool does not expose the switch: everything arriving there is a plan somebody will keep or compare. *Original entry follows.*<br><br>**The solver's answer depends on how fast the machine is.** Found by `tests/test_solver.py::TestDeterminism` failing intermittently, under a docstring that reads *"a suite that cannot reproduce a layout cannot pin one either."* The test was right and the solver was wrong. `build/solver.py`'s topology loop stops starting new topologies once the next one could not finish inside the budget, and that check reads the **wall clock** — so a loaded machine tries fewer topologies than an idle one and a different layout wins. The same seed, the same plan, a different house. Nothing hid it (`topologies_tried` has always been in the record) and nothing said it either, and it passed whenever anyone checked, because checking one test is exactly when the machine is quiet. **Half-fixed, and the half that remains is a judgment.** `solve(..., deterministic=True)` now runs every topology, bounds each phase by CP-SAT's own deterministic time — work done rather than seconds elapsed — and keeps the wall-clock limit only as a tenfold outer guard; the answer is then a function of the inputs. The default is unchanged, because a person waiting for a plan wants the promise about time kept, and the record now carries `deterministic` and a note saying which trade was taken. What is unruled is **which should be the default**, and it is a real choice rather than an oversight: reproducibility is worth more for anything pinned, compared, re-derived or shipped as a plan record, and wall-clock bounding is worth more for anything a person is waiting on. A third option nobody has costed: make the topology count itself the budget (`topologies=N`) and drop the time bound entirely, which would make the promise about *work* instead of about *seconds* and is the only version in which the two stop competing.
