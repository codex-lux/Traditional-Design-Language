# OQ 93 — every door is hinged `low` and no rule decides the hand

*Status: OPEN · Raised in: From the plan-semantics program (WP-6.1 / WP-6.2, 26 August 2026)*

**OPEN — every door is hinged `low` and no rule decides the hand.** Plan schema 0.3.0 gives a door a `hinge` (`low`/`high` along its wall's own axis) and a `swing_into`, and `build/openings.py` writes `low` for every door in the corpus. The swing SIDE is derived — into the far room, off the two rooms' centroids, which is a real rule the renderers have used since WP-2.2 — but which jamb carries the hinges is not, and it matters: a leaf hinged at the wrong end opens against the wall it should open along, blocks the light switch, and on a bathroom door swings across the lavatory. The corpus has the makings of a rule and has never stated one — `rooms/bathroom.json` carries "door swing" as a furniture item 28 in square, which is a clearance rather than a direction, and `rooms/butlers-pantry.json`'s offset rule is about position rather than hand. The honest inputs are the fixture layout (now in the record), the window wall, and which way a person is walking when they arrive, and the last of those is not modelled at all. Left written as a constant so that it is visibly a constant rather than quietly derived from nothing.
