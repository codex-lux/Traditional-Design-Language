# OQ 96 — `_shared`'s first-match-wins ordering can report a corner kiss as a shared edge

*Status: OPEN · Raised in: From geometry truth (WP-6.3, 27 August 2026)*

**OPEN — `_shared`'s first-match-wins ordering can report a corner kiss as a shared edge.** Found while proving that `_absorb` cannot break a door contact (it cannot; see the WP-6.3 report). `build/render_plan.py::_shared_run` and `geometry_cp.py`'s `hard_fact_violations` both test the E/W adjacency before the N/S one and return the first that matches within a 0.4 ft tolerance. Two rooms meeting at a corner satisfy both degenerately: measured, a pair whose true contact is a **0.256 ft corner overlap** reported 0.256 ft on one wall pre-rounding and 0.010 ft on another post-rounding, because a 0.01 ft coordinate shift changed which branch matched first. Nothing draws on it today — 0.256 ft is 21x short of `required_wall_ft` for the narrowest door in the corpus (2.9 ft), so every such pair is refused an opening long before the ambiguity matters, and the WP-6.3 door floor made that margin wider rather than narrower. It is recorded because the tolerance and the ordering are load-bearing in three files now (both renderers and the CP arbiter), and because the honest fix — return the LONGEST shared run rather than the first one found — is small and nobody has ruled whether a corner contact should be a shared wall at all.
