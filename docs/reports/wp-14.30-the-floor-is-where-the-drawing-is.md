# WP-14.30: the floor is where the drawing is

*25 September 2026. Phase 14, tranche 2, wave 4. Ruled by Lucas the same day: the reading
surfaces reflow so nothing scrolls sideways at 1280 px, and the plan sheet, the Drawing Set (the
Round among it) and Transcription keep a floor, with the masthead held to the window. The contract
is `docs/prd/phase-14-tranche-2.md` §E, with §0.3 default 1 (Transcription keeps a floor, Export
reflows). Cite this report by filename; a Phase 14 number does not disambiguate a package in this
repository.*

## What it is for

Until this package the whole shell had one floor. `#root{min-width:1380px}` in `tokens.css` held
every page at 1380 px, and `App.jsx` released it for exactly two surfaces by a hard-coded pair, the
front door and the Glossary (WP-14.8). On a 1280 px laptop that meant three things on 17 of the 19
addresses measured, one or two per surface:

- the document scrolled sideways by exactly 100 px;
- the masthead was drawn 1380 px wide;
- its "Keys ?" button stood at x = 1364, off the right edge of the window.

A reader of a style's dossier, a fault or a room record met a sideways scroll before a word, for a
floor whose only reason is that three surfaces draw.

## I. What was built

**The table.** `workbench/app/src/state/layout.js` holds `SURFACE_WIDTH`, keyed by the router's
surface id, beside the pane defaults, as §E asks. `surfaceWidth(id)` reads it. An id the table does
not hold answers `'floor'`, never `'reflow'`: a floor scrolls sideways inside `<main>` at worst, where
a drawing reflowed by accident is squeezed with nothing saying so.

| Surface id | Width | Why |
|---|---|---|
| `overview` | reflow | the front door |
| `style` | reflow | the Styles index and every dossier section, the kit among them |
| `proportions` | reflow | |
| `faults` | reflow | |
| `phylogeny` | reflow | the tree and the map |
| `glossary` | reflow | |
| `brief` | reflow | |
| `candidates` | reflow | |
| `export` | reflow | a form (§0.3, default 1) |
| `elements` | reflow | |
| `room`, `massing`, `grouping`, `parti` | reflow | every record page |
| `compare` | reflow | WP-14.26's, named by §E before its route lands |
| `workbench` | **floor** | the Plan Workbench sheet |
| `drawings` | **floor** | the Drawing Set, the Round among it |
| `transcription` | **floor** | traces a drawing (§0.3, default 1) |

**The floor.** `MAIN_FLOOR_PX = 800`, and it is not a new number. Under the old shell floor, with
both shell rails open at their shipped widths, `<main>` was 1380 − 236 − 344 = 800 px. That was
measured, not assumed: the splitters render zero-wide, and `<main>` read 800 at a 1380 px window
with the assistant open. 800 is therefore the narrowest column the three drawing surfaces were ever
given in a shipped layout. Holding them at it takes nothing away and invents no minimum.

Two larger figures were considered and refused:

- 1118, the width the bench got at 1280 under the old floor, would bind at 1680 with the assistant
  open (`<main>` 1100), a layout that did not scroll before;
- 1380 would reinstate the defect one element down.

**The mechanism.** `App.jsx`'s effect is the one hunk this package owns in that file.

- It marks `#root` with `data-reflow` or `data-floor` from the table.
- It writes `--main-floor` from `MAIN_FLOOR_PX`.
- It is a layout effect, because a plain effect paints a floored page for one frame without its
  floor.

`tokens.css` puts the floor on `<main>`'s grid track:

```css
#root[data-floor] main{display:grid!important;grid-template-columns:minmax(var(--main-floor),1fr);grid-template-rows:minmax(0,1fr);overflow-x:auto}
```

So `<main>` scrolls sideways inside itself while the masthead, the crumbs and both rails keep the
window's width. `!important` is needed because `<main>` carries an inline `display:flex`. The
floor is on the TRACK and not on the surface's own box, and that was measured into the rule rather
than chosen (finding 2).

**One inner minimum loosened, and only one.** Scope item 2 allows loosening only where the walk
measures a residual sideways scroll on a reflow page, by wrapping or `minmax` and never by removing
content. Exactly one residual was measured in the default layout: the family tree's filter strip,
158 px over at 1018 px (58 px over even at the old 1118).

- `Chrome.jsx`'s `FilterStrip` gains an opt-in `wrap`.
- `Phylogeny.jsx` takes it, and the strip takes two lines.

Every other caller's strip draws as it did. It gains only a `data-filter-strip` attribute saying
which kind it is, and its `gap` became `columnGap`, which is the same thing on one line. The
screenshot was looked at: the second line carries *show claimed ancestry* and the compare hint, and
reads.

**Prose corrected.** The stale `tokens.css` comment about `#root[data-reflow]` releasing a floor
now says what is true. So do the WP-14.8 comments in `Glossary.jsx` and `Overview.jsx`, the
`NARROW_FOLD_PX` comment in `layout.js`, and `docs/workbench.md`'s shell section. That section read
*"the working surfaces keep `tokens.css`'s 1380 px floor by ruling ... That is recorded, not
fixed."* Each of these described a floor that no longer exists. A sweep of the live docs for the
number finds no other; the reports that mention it are dated records and are left as written.
WP-6.4's rule: *"until X lands"* is a lie the moment X lands.

## III. Findings

**1. THE DOCUMENT'S SCROLL WIDTH IS BLIND HERE, BY CONSTRUCTION.** The shell's outer frame is
`height:100vh; overflow:hidden`. With the floor off `#root`, `document.scrollingElement` therefore
reads 0 over on every page, whatever the page does: inner overflow is either clipped by the frame
or scrolls in a pane of its own. §E's measurement, `scrollWidth − clientWidth ≤ 1`, taken on the
document alone, passes a page whose content is cut off at the right edge. So the walk judges a
reflow page three ways: the document, `<main>`, and every element inside `<main>` that scrolls or
clips sideways. The family tree's strip is exactly the case this catches: the document reads 0 and
the strip was 158 px over.

**2. THE FIRST FLOOR WIDENED EVERY FLOORED EMPTY STATE, AND ONLY A MEASUREMENT SAW IT.** The first
version put the floor on the surface's own box, `main > *{min-width: var(--main-floor)}`. The bench,
the Drawing Set and Transcription each have an empty state capped at `maxWidth: 720`, and
`min-width` beats `max-width` in CSS. So all three empty states were drawn 800 px wide, off their own
measure, in the one layout where the floor does not even bind. The grid track holds the COLUMN at
800 and leaves each surface's own caps alone. U14 below drives the old rule back in, and it is red.

**3. THE LEAD'S NAMED FAULTCORPUS MUTATION IS A NO-OP ON THIS TREE.** The brief names *"restoring
`minWidth: 460` in `FaultCorpus`"* as a mutation the walk must catch. That minimum was never
removed, and it does not bind in the default layout: the detail pane is 688 px wide there against
a 460 px minimum. It binds only with the assistant open, where it is the +112 px in 370
above, which is printed and not judged. "Restoring" it changes nothing, and W3a runs it to show
that. The guard is proved on a BINDING equivalent instead, W3b, which raises it to 700 and is red.
**A mutation that cannot change the page cannot test the guard**, and reporting it green or red
would have told the lead nothing either way.

**4. ANOTHER PACKAGE'S GUARD READ PROSE, AND THIS PACKAGE'S COMMENT TRIPPED IT.**
`journeyBar.test.mjs`'s *"App mounts the bar once, above `<main>`"* located `<main` with `indexOf`
over `App.jsx`'s raw source. The new effect's comment mentions `<main>` above the JSX, so the test
went red on a comment. Rewording the comment around the guard was available and is the wrong fix: a
guard that reads comments is a guard any comment can blind or trip. The test strips comments before
it reads now. Both of its own mutations were driven against the re-cut: J1 mounts the bar below
`<main>` and J2 mounts it twice, and both are red.

**5. THE RULING NAMES A WINDOW AND NOT A LAYOUT, AND THE TWO READINGS DIFFER BY SIXTEEN PAGES.**
§E says *"no sideways scroll at 1280 × 800"*. With nothing stored, every reflow page meets it. With
the assistant open, which is a layout a reader may choose and the store then keeps, 16 of 39 reflow
addresses scroll inside themselves at a 700 px `<main>` (table above). Two readings, both defensible:

- *the laptop default*: the store folds the assistant below 1500 px precisely so a reading surface
  gets the window;
- *every layout*: a reader who opens the assistant at 1280 is still on a 1280 px laptop.

This package reads the first. The walk JUDGES the default layout and PRINTS the other, rather than
passing it silently or failing a page on a ruling nobody has given. The work the second reading
would need is the list above: section strip, filter strips, the fault detail's two columns, the
kit's two panes. **Raised for the lead to file as a named open question.** It was not filed here,
because adding a register entry moves `CLAUDE.md`'s derived open-question list, which this package
may not edit, and `tests/test_wp46_packs.py` would go red on the difference.

**6. A FLOORED SURFACE GOT NARROWER BY DEFAULT, AND ITS OWN STRIP NOW HIDES "RE-SOLVE".** Under the
old shell floor the bench was drawn at 1118 px on a 1280 px laptop, with the page scrolling 100 px.
It is drawn at 1018 now, because the 800 px floor does not bind with the assistant folded. The Plan
Workbench's `FilterStrip` needs 1085 px, measured with a placed record. At 1118 it fit exactly. At
1018 it is 67 px over and scrolls inside itself, which puts **re-solve**, a primary act, behind a
thin scrollbar at the right edge. The Drawing Set's sheet strip needs 1237 px and was already over
at 1118, so that one is not new.

**Not changed**, for three reasons:

- scope item 2 loosens only REFLOW surfaces;
- `PlanWorkbench.jsx` is not in wave 4's ownership;
- the state is not new to the surface. The old floor reached it at every window below about
  1665 px with the assistant open, where `<main>` is 800 to 1085 px.

The fix is one word, `<FilterStrip wrap ...>` in `PlanWorkbench.jsx`, on the same opt-in this
package added. **Named for the lead.**

- every row is `reflow` or `floor`, the floored set is exactly the three that draw, and `export`
  reflows;

## V. Deliberately not done

- **No inner minimum on a floored surface was loosened** (finding 6). The bench's strip wraps with
  one word, and that word is somebody else's to write.
- **The assistant-open layout's sixteen pages were not reflowed** (finding 5), and are printed
  rather than judged, pending a ruling on what §E's window means.
- **No open question was filed** (finding 5), and the reason is stated there.
- **`compare` is in the table before its route.** The walk reads it the moment
  `SURFACE_PATHS.compare` exists, and the layout test admits it as the only id the router may lack.
  When WP-14.26 lands, that admission becomes a no-op rather than a failure.
- **No count or literal width is written into a test or into JSX.** The walk derives its figures
  from `MAIN_FLOOR_PX` and the table.
