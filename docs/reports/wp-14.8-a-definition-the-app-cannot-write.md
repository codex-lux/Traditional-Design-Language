# WP-14.8: a definition the app cannot write

*24 September 2026. Branch `wp-14.8`, taken from `b4172f8`. Scope: PRD
`docs/prd/phase-14-the-dossier-and-the-journey.md` §0, §A, §C.1–C.2, §E, §I.1–I.4, §I.10, §J
and §K. Every figure below was measured in this worktree. The one surface I could not run, the
browser walk, is reported as **UNRUN** and not as a pass. Cite this report by filename.*

## What it is for

The ruling of 24 September puts every word the workbench shows into a glossary record, checked
by `build/check_glossary.py` (WP-14.1) and written in four batches (WP-14.2). This package
builds the part of the app that shows those words, and builds it so the app **cannot** write a
definition of its own:

- The one definition primitive takes an id and nothing else.
- A word with no record says so on screen.
- The glossary is fetched and never bundled, and a checker looks for it in the bundle.
- A new tooltip explanation or a new count typed into JSX fails a ratchet.

## I. What was built

**The read.** Four modules, all pure except the last:

- `api/fetchOnce.js` issues one request per page lifetime. It has four states (`loading`,
  `failed`, `ready` and a retry path back to `loading`), keeps exactly one request in flight
  however many readers there are, and returns a snapshot stable enough for
  `useSyncExternalStore`.
- `api/adapters.js` turns the §C.1 body into `glossary/lookup.js`'s index. It **throws** on a
  body with no `terms` list, and on a body whose `count` is not the length of its `terms`.
- `glossary/lookup.js` gains one method, `families()`. It returns `by_family`'s keys in the
  server's order, which is the schema's enum order, and never guesses a family from the records'
  own fields.
- `api/useGlossary.js` returns `{status, lookup, error}` and is the only React module of the four.

`client.js` gains `glossary()` and `glossaryTerm(id)`. The change is append-only, two lines and
a comment.

**The primitive.** `components/Term.jsx` destructures exactly `id`, `field`, `value` and
`children`. It has no definition prop and no fallback text.

- Every decision it makes is `glossary/termView.js`'s, as pure functions over the hook's answer,
  and each of four states reads differently:
  - `loading` claims nothing.
  - `failed` reads `glossary unavailable: <id>`.
  - `missing` reads `no entry: <id>`, which is `noEntry`, the PRD's one spelling.
  - `ready` is the record.
- The word is a real `button.tdl-term` carrying `data-term`, `aria-expanded` and
  `aria-controls`. It opens a **non-modal** `role=dialog` popover labelled by the word.
- The popover can be opened three ways and closed three ways:
  - Enter opens it and focus moves inside it.
  - A resting mouse opens it after `HOVER_OPEN_MS = 400` ms.
  - Esc closes it and returns focus to the word.
  - A change of place (`hashchange`) closes it.
  - Opening the command palette (⌘K / Ctrl+K, or focus entering a modal) closes it.
- The popover shows, in order: the definition, the analogy, the provenance (the record's `kind`,
  then its first source or the files an editorial record read), "not to be confused with" links,
  and "more", which points to `#/cite/term:<id>`.
- Every address comes from `router.js` (`citeHref`, `hrefFor`, `formatHash`). The citation
  grammar is not spelled a fourth time, and a source guard holds `termView.js` to that.
- `useTermDescription(id)` is exported for controls a `Term` may not sit inside.

`help/popoverStore.js` holds one slot, so only one popover is ever open. A late `close(key)`
cannot close a popover that replaced it.

**Links and heads.**

- `components/RecordLink.jsx` draws a citation as a practitioner reads one: the name from the
  search index (`names/useNames.js`), the id as an ink-2 note, and a real anchor with a real
  href. It draws text, never an anchor, for a cite the router cannot read.
- `components/PageHead.jsx` takes one prop, `termId`. Every word in it is the record's own:
  - the term in the eyebrow;
  - `surface.what` as the lede;
  - a "How to read this page" disclosure holding `surface.read[]` and `surface.try`.
- The disclosure's state is per-browser memory in `state/prefs.js`, never the URL. It is open
  the first time this browser shows the record and folded after that, and a reader's own toggle
  outranks both.
- `state/prefs.js` (key `'tdl-workbench-prefs'`) sanitises each key on its own. A corrupt entry,
  or no `localStorage` at all, gives the defaults and a working in-memory store.

**The surface.** `surfaces/Glossary.jsx` is registered in `App.jsx`'s `SURFACES`.

- `#/glossary` is the index: every record, grouped by family in the schema's order, narrowed by
  `?q=` and `?family=` through `useSurfaceFilters`.
- `#/glossary/<term>` is one record, shown whole.
- A bare `#/glossary` always shows the index, never a remembered term.
- It mounts its own `PageHead` and marks `#root` with `data-reflow` until the shell does both
  (WP-14.13). The walk asserts exactly one page head, so the day both are mounted it fails
  rather than drawing two.

**The ink and the ring (`theme/tokens.css`, this package alone).**

- `:focus-visible` draws a 2 px `--border-focus` ring on every element. Before this it drew one
  on anchors only.
- The three inputs that set an inline `outline: none`, which beats any stylesheet rule, no
  longer set it: `FilterInput`, `StylePicker` and the command palette.
- `#root[data-reflow]{min-width:0}` releases the 1380 px floor for a page that asks. The
  Glossary folds to one column below 1379 px.
- `.tdl-term` is shown with a dotted `--ink-2` underline.
- The WP-14.8 block adds **no colour literal**, and a test reads the block for hex, rgb and hsl.
- `Eyebrow`'s default ink went from `--ink-3` (3.15:1 on `--paper`) to `--ink-2` (4.85:1), and
  its count takes the label's own ink rather than `--ink-4` (2.26:1).
- `Chrome.jsx`'s unused `SurfaceHead` is deleted, as the PRD's §J.3 table assigns.

**The guards.** All are pure `src/*.test.mjs` files under `node --test`, with no React and
nothing from `node_modules`:

- `glossary.test.mjs` holds every **literal** glossary id in shipped source to a record in
  `glossary/*.json`, read with `node:fs`. The shapes it reads are:
  - `<Term id>` and `<Term field value>`
  - `<PageHead termId>`
  - `useTermDescription`
  - `.term` and `.termFor`
  - `describeTerm` and `termView`
  - `wordOf`, and `wordForCite` with a `term:` cite

  The scanner is driven on a fixture carrying every shape. The file also holds `FIELDS` to the
  records **both ways**: every field it names is bound with that field's own schema and pointer,
  and every bound field is one it names, at a value its enum has.
- `copy_ratchet.test.mjs` is a baseline held **by identity**, as a multiset of `[file, text]`
  rows, so one addition cannot net out one removal. It covers two things:
  - `title=` explanations of eight words or more: 15 baseline rows.
  - count literals written into JSX: 16 baseline rows.

  It is compared in both directions: nothing new may appear, and nothing may silently leave the
  baseline.
- `definitions.test.mjs`, `fetchOnce.test.mjs`, `popoverStore.test.mjs` and `prefs.test.mjs`
  drive the pure modules, and hold the components' own properties by source guard. The source
  guards cover:
  - no definition prop, and no phrase in Term but the PRD's two;
  - no inline `outline: none`;
  - no readable `--ink-4` in the new components or the block;
  - no source file importing `glossary/*.json`.

  A source guard is the weaker form, and the files say so. It is used only for what a file
  *says*, never for behaviour.

`build/check_frontend.py` gains a bundle probe. For each glossary record it takes the longest
run of plain letters in the definition, at least 30 characters, and searches every built chunk
for it:

- If a run is found, the check fails and names the records.
- If no record could be probed, the result is COULD NOT EVALUATE, never a pass.
- Six tests in `tests/test_check_frontend.py` drive all three states through `main()` itself and
  assert the corpus premise: at least 90% of records probed.

**The walk.** `workbench/app/e2e/walk.mjs` gains one block of 157 lines, a pure insertion before
`await browser.close()`, touching no line `engineClaim.test.mjs` reads. Everything it checks is
read from `GET /api/glossary`, not from a figure typed into the walk:

- the family order and the term count;
- exactly one page head, and that it is the Glossary's own record;
- the reflow mark;
- a 2 px ring on a focused field;
- a term page's own definition;
- the page head's `term:` Try link worded by its record;
- the popover driven by Enter, Esc, hover and a change of place;
- no sideways scroll at 1280 px, with a screenshot.

If the route does not answer with a terms list, the block records itself as unjudged by name.

## IV. Findings

1. **In Node 22, a capture listener added and removed with the bare `true` is never removed.**
   Measured on v22.22.2:
   - Added and removed with `true`, it still fires.
   - Added and removed with `{capture: true}`, it is removed.
   - Added with the object and removed with `true`, it still fires.

   `popoverStore`'s unbind test caught it on its first run. Both files use the object form now,
   which removes the listener in Node and in browsers alike. A Node test of browser code can be
   wrong in the direction that hides a leak.
2. **A `term:` cite has no entry in `/api/search/index`.** The index names only styles, slots,
   faults, packs, rooms, massings, groupings and partis. So `RecordLink` printed the raw
   `term:plan-record` in the Glossary's own page head. **Of the 21 records carrying a
   `surface.try` (12 surfaces, 9 sections), 4 point at a `term:` cite**: three at `plan-record`,
   one at `judgment-unjudged`, and all four are surfaces.
   - `glossary/termView.js::wordOf` / `wordForCite` is now the one spelling of "the word for a
     link to a glossary record": the record's `term`, or `noEntry`. The Glossary's See and Try
     lists and PageHead's Try all read it.
   - A source guard refuses a self-closing `RecordLink` in either file.
   - Left as it was: `brief:family-georgian`, one record's `try`, is also named by no index
     entry and still prints as itself. I established that by reading `names/names.js`,
     not by running it.
   - A worded `term:` link carries no id note, because `linkView` gives a note only to a
     resolved name. The href still carries the id.
3. **No glossary record names a family, and PRD §J.4 forbids an app-written kind heading.** The
   index therefore prints the schema's enum values as they are (`param-kind`, `pack-relation`,
   and so on). The term page carries eight field labels the app wrote. This is
   `oq/a-glossary-family-has-no-name-of-its-own`, raised here, and it tells the next reader not
   to add a family-name table to the Glossary.
4. **The count baseline froze three stale numbers, and a ratchet cannot tell stale from
   current.**
   - `FaultCorpus.jsx` (twice) and `ExportDetails.jsx` say **209 faults**, and `faults/` holds
     **210**.
   - `check_counts.py` reads no JSX. This was already known of the Kit's slot count, and it is
     true here too.
   - Two of the baseline's rows are not counts at all. "six reads" is a false positive of the
     regex, and "three inches" is a measurement. They are kept rather than excused by pattern,
     because a narrower regex is how a meter goes blind.
   - None of these files is this package's, so the numbers are recorded rather than corrected.
5. **Eight eyebrows ask for `--ink-4` by name (`tone="quiet"`, 2.26:1).** They are in
   `RevisionPanel` (4), `Phylogeny` (2), `BriefIntake` (1) and `CandidateSet` (1). The default
   change repaints the callers that take the default. By a single-line grep that cannot see a
   `tone` written on the next line, that is about 74 of 102 `<Eyebrow` sites. No caller names
   `tertiary`. The count half of the change is **inert today**: no caller passes `count`. And
   `--ink-2` is **4.32:1 on `--paper-deep`**, which is under 4.5 wherever an eyebrow sits on that
   ground. Which surfaces those are is not measured.
6. **Readable `--ink-4` is elsewhere too.** It appears 119 times over 33 `.jsx` files, for
   example the palette's "reading the corpus…". I did not sweep these: the guard is scoped to the
   new components and the block, which is what this package owns.
7. **`api.glossaryTerm()` has no caller yet.** The whole set comes in one GET, so a term page
   reads from the lookup already in hand. The client names both routes because the server
   contract gives both (§C.2), and a test holds that. The single-record route is there for a
   package that needs `see` citations named server-side.
8. **The adapter's count check is new behaviour at a boundary.** A body whose `count` disagrees
   with its `terms` is a truncated read, and it now goes to `failed` rather than to a Glossary
   that silently lists fewer words than the server holds.

## V. Deviations from the brief and the PRD

- **`palette/CommandPalette.jsx` got a one-token edit** (`outline: 'none'` removed). PRD §J.3
  gives that file to WP-14.12 and WP-14.13. The brief named the three inputs, and an inline
  `outline:none` beats the stylesheet ring, so there was no way to give the palette a ring from
  `tokens.css` alone. Expect a trivial conflict at 14.12/14.13.
- **`App.jsx` gains two lines, not one**: the import and the `SURFACES` entry. The PRD says "one
  line (`SURFACES.glossary`)".
- **`glossary/lookup.js` gained `families()`.** The Glossary needs the schema's family order,
  and deriving it from the records would invent one.
- **`glossary/termView.js` gained `wordOf` and `wordForCite`** (finding 2).
- **The Glossary mounts `PageHead` and sets `data-reflow` itself** until WP-14.13's shell does
  both, as §I.12 anticipates. The walk's one-head assertion fails the day both are mounted.
- **`client.js` adds the same two lines WP-14.3 is specified to add**, so a trivial
  append/append conflict at the merge is likely. Keep one copy.
