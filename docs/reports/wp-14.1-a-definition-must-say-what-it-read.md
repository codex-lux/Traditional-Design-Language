# WP-14.1 — A definition must say what it read

*24 September 2026. Phase 14, wave 1. The glossary's schema, its checker, its five seed records,
and the one change to `check_openings.check_basis` the checker needs. Built against the frozen
contract `docs/prd/phase-14-the-dossier-and-the-journey.md` §A, §B.0, §B.1 and §J, and against the
analysis it answers, `docs/reports/ux-first-principles-2026-09-24.md`. Every figure below is dated
24 Sep 2026 and was measured on this package's tree; none is a standing claim.*

---

## I. What was built

The ruling this package serves is that **every word the workbench shows a reader is defined by a
record in `glossary/`, and the app writes no definition of its own.** That moves the whole
question of whether a tooltip is true into one directory, which makes the checker of that
directory the only thing standing between a reader and an invented source. So the package is
mostly the checker.

- **`schema/glossary-term.schema.json`, version 0.1.0.** The §A.2 skeleton exactly, with the
  `description` strings the contract asked this package to add. *Exactly* is measured, not
  asserted: stripped of every `description` key, the committed schema is equal to the JSON block in
  §A.2 parsed out of the PRD, and it passes `Draft202012Validator.check_schema`.
- **`build/check_glossary.py`**, on `check_faults.py`'s pattern: the eleven rules of §A.5, in the
  contract's order. Exit 0 pass, 1 any error, 3 COULD NOT EVALUATE (jsonschema absent, the
  server's citation validator unimportable, or the schema uncompilable) and never 0 when it could
  not. Registered in `build/check_all.py` directly after `check_faults.py`; `TOTAL_CHECKS`
  **53 → 54**, `len(CHECKS)` 50 → 51. `build/check_costs.json` is not edited, so the new unit takes
  `DEFAULT_COST`.
- **`check_openings.check_basis(rep, rule, source=..., rec_re=None)`** now returns the number of
  quotations it verified in full, and `check_openings.GLOSSARY_REC_RE` is the one spelling of which
  files a glossary basis may name, verbatim from §A.5. With `rec_re=None` the function reads
  `_REC_RE` exactly as before. `_KEYPATH_RE` is not widened.
- **The five seeds of §B.1**: `about-tdl` (with three `readers` from `VISION.md` §IX and five
  `is_not` from §X, and deliberately no line for the people who live there), `judgment-passed`,
  `judgment-failed`, `judgment-unjudged` (aka *could not evaluate*) and `judgment-not-applicable`.
  All five are editorial; together their bases carry **27 quotations, every one verified** in
  `VISION.md`, `mcp_server/core.py`, `build/check_all.py` or `schema/fault.schema.json`.
- **`glossary/README.md`**, the §A.6 authoring rules, written for the four agents authoring the
  tranche-one records against the same contract at the same time as this package.
- **`tests/test_check_glossary.py`** (41 tests) and one new case in
  `tests/test_schema_validators.py`'s loop (the glossary schema against `about-tdl`, clean and with
  each required key removed, compiled against uncompiled).
- **`CLAUDE.md`**, two figures and nothing else: `**54 checks, 2,718 tests**`, and a dated
  `"51 of 54 checks passed"` beside the `"50 of 53"` illustration, stated as the identity it is.

### The command line

```
python3 build/check_glossary.py                        # the repository's glossary/
python3 build/check_glossary.py --glossary DIR [...]   # these directories, checked as ONE set
python3 build/check_glossary.py --quiet                # errors and the verdict only
```

`--glossary` may be repeated and replaces the default rather than adding to it: a batch authored
outside this directory is checked on top of the seeds by naming both (`--glossary glossary
--glossary <batch>`), and an id present in two of the named directories is a duplicate. The
corpus a basis quotes, the bibliography, the schemas and `briefs/` are always the repository's
own; there is no root override, because nothing in the checker's contract needs one and a checker
that can be pointed at a different corpus can be pointed at one that agrees with it.

## II. What was found

**1. The worktree this package was given did not carry the contract.** It was cut at `d565dea`,
one commit before `15a7e39` added the PRD. The instruction said the contract was "in your
worktree"; it was on the integration branch. `15a7e39` descends from `d565dea` with no divergence,
so the worktree was fast-forwarded onto it before anything was written, and this package's branch
therefore carries `676b5a6` and `15a7e39` beneath its own commit. That is a process note for the
lead, not a change to anything the contract says.

**2. The seven callers are byte-identical, and a byte-identical green run is a weak witness.**
Each of `check_openings.py`, `check_windows.py`, `check_furniture.py`, `check_threshold.py`,
`check_moves.py`, `check_critic_suspects.py` and `arrangement.py selftest` was run before the edit
and after it, and stdout, stderr and the exit code were diffed: **all seven identical**, all seven
exit 0. But all seven are green, and a green caller prints one OK line — nothing in it says what
`check_basis` did on a basis that fails. So the equivalence was also taken where it can fail: every
dict carrying an `id` and a `basis` in the six grammar files, plus `arrangement.py`'s
`ROUTE_MODEL` — **109 bases** — each run through the pristine function (`git show HEAD`'s copy)
and the new one, as authored and under three mutations (a quotation corrupted, every named path
removed, a path renamed to one that does not exist). **416 runs, 310 of which record an error or
an unjudged item, 0 differing.** The instrument was then proved able to see a difference: the same
run with a narrower pattern passed as `rec_re` reports **125 differing**. The zero is a
measurement.

**3. Rule 3's premise holds, and the one directory it leaves out is right to be left out.**
Measured over every JSON file in the tree: top-level `sources` lists of strings live under
`styles/` (164 records), `faults/` (209), `rooms/` (60), `proportions/` (55 of 57 packs),
`groupings/` (17) and `partis/` (21) — **1,655 distinct strings**. `precedents/` carries none,
**0 of 695**, as §0.1 said. The one place the contract does *not* admit that does carry a
`sources` key is `kits/`: **562 nested, slot-level lists, 520 distinct strings, 514 of which
appear in none of the six directories** — and they are not works at all but provenance notes
(*"Authored, not retrieved. There is no historical Norman precedent for a garage."*). Admitting
them would let a glossary record "cite" a sentence saying nothing was cited.
`test_a_kit_provenance_note_is_not_a_bibliography` holds the exclusion, computing its specimen
without the checker's own reader.

**4. The seven bind pointers resolve to exactly the enums §A.4 lists**, read from the schema files
as they stand, and the checker re-reads them on every run, so a schema that moves reddens the
glossary rather than leaving a word bound to nothing.

**5. The returned count is load-bearing, because `_QUOTE_RE` never sees a short quotation.** It
matches double-quoted runs of 25 characters or more; a basis whose only quotation is 20
characters is not *checked and passed*, it is *not read*, and without the count it would go
through `check_basis` with no error recorded. That is the fake pass wearing a citation. The count
is what lets rule 4 say "verified no quotation" instead. The same regex has a neighbouring trap
this package did **not** change, because changing it would move all seven callers: two short
quotations close together can make the text *between* them match as one long quotation, which is
then reported as not found. The README tells authors to keep every quotation long and why.

**6. Four of this package's own tests could not fail on the first mutation run.** Forty-seven code
mutations of the checker, of `check_basis` and of the registration, each applied in an isolated
copy of the tree, asserted to have landed exactly once, run against the test file, and restored
byte for byte: **43 red and 4 blind** on the first sweep. The four:

- a bind to a field outside the table — the schema's own enum refuses it too, so exit 1 never
  depended on the checker's rule having run;
- a bound record in the wrong family — the id rule derives the name from the row, not from the
  record's family, so nothing else sees it;
- a collision declared on *neither* side — the asymmetric-`confusable_with` fixture removes one
  side, and there the symmetry rule catches it, so the collision rule was never the one tested;
- a `confusable_with` naming a record that does not exist.

A test was added for each, each asserting the rule's own message rather than a nonzero exit.
**The re-run: 47 red of 47.** The first of the four is the one worth keeping: where a schema and a
checker both refuse a thing, a test that asserts only the exit code tests the schema.

**7. The test count in `CLAUDE.md` was already stale on this package's base.** It read 2,643; the
base collected **2,675** before anything here was added. It is **2,718** now, and that reconciles
exactly: 2,675 + 41 in `tests/test_check_glossary.py` + 2 new parametrised cases in
`tests/test_schema_validators.py`.

**8. This package's own test carried a dangling report citation, and `check_ids.py` caught it.**
The test that holds `GLOSSARY_REC_RE` to what it may not admit named an invented
`docs/reports/…` path as its specimen of a report. `build/check_ids.py` reads every tracked and
untracked `.py` for a `docs/reports/<name>.md` and fails the build on one that does not exist —
the rule the contract's own preface warns every package about — and it failed here, on the
specimen. The specimens are real files now, with the reason beside them. **And the first
reading of that run was wrong in the flattering direction**: the three checkers were run as
`… | tail -4; echo exit=$?`, so every `exit=0` printed was `tail`'s. `CLAUDE.md` records exactly
this — *a harness that reads `returncode` through a pipe reads `tail`'s* — and it was met again
by the session that had just read it. The figures in §V are each checker's own exit code, taken
without a pipe.

**9. `build/gen_readme_counts.py` writes on any argument, `--help` included.** Asked for its help
while checking whether a new schema file moves README's counts block (it does not: `schema_files`
is computed and never rendered), it regenerated README in place. The block was already current, so
nothing changed — `git status` was clean afterwards — but a generator with no `--check` and no
argument parsing will one day be run by somebody asking it a question. Found in passing and not
touched; it is outside this package's files.

## III. What was deliberately not done

- **No served payload.** `GET /api/glossary`, the set's version and digest, each record's derived
  `reads` line, the `term` citation kind and the one ungated path are WP-14.3's. The constant's
  comment names §C.1 as where `reads` will be derived from `GLOSSARY_REC_RE`, and says nothing
  about a server that reads it, because none does yet.
- **`_KEYPATH_RE` is not widened**, as the contract says. A glossary basis naming a key path under
  `partis/`, `schema/`, `VISION.md` or a `docs/` page is verified against the whole file and not
  against the key. The README says what the key-path reader does and does not reach.
- **`_QUOTE_RE`'s between-quotations behaviour is unchanged** (II.5), because every caller depends
  on it.
- **No root README line for the new checker.** README lists the checkers one per line; that file is
  not in this package's list, and the prose pass is WP-14.15's.
- **No other `CLAUDE.md` prose.** The two figures only.
- **No full `check_all` run.** A baseline is being taken elsewhere on the shared box, and two full
  suites at once is the hazard `check_all.py`'s own sharding note describes. What was run is in
  §V; the new unit was not timed, which is why the cost table is not touched.
- **No open question was raised.** Everything found is either inside this package's reach and done,
  or named above as somebody else's file.

## VI. Where this departs from the contract, stated so it can be attacked

None of the contract's ids, fields, families, file names or the schema changed. Four readings of
what it leaves open:

1. **A key stated twice in one record file is an error under rule 2.** Not in §A.5's list. `json.load`
   keeps the last occurrence silently, so such a file says one thing and means another, and four
   agents are writing these files by hand at once. `tests/test_duplicate_json_keys.py` would catch
   it at the next full suite; this catches it at authoring time.
2. **"Any digit" is read as a numeral of any script** — Unicode categories Nd, No and Nl — so a
   circled numeral or a fraction is refused as well as `0`–`9`. The analysis this phase answers
   found circled numerals as build history in reader copy, and `\d` alone would pass them.
3. **A fragment on a `term:` or `brief:` citation is refused.** §A.5 rule 7 says those kinds are
   checked against the glossary and `briefs/` and is silent on a fragment; neither kind has a
   fragment grammar, so a fragment there would name nothing.
4. **The command line is `--glossary DIR`, repeatable.** The contract names no interface; this one
   lets a batch be checked on top of the seeds from outside the directory, which §B.0 requires of
   every batch.
