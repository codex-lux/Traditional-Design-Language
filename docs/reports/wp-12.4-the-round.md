## Findings

### 1. The `xz` frame is left-handed, and it wound half the house inside out

`solids.js::sweptFaces` wound its caps by the outline's own order. That is correct on `yz` and
`xy` and wrong on `xz`, because `PLANES.xz` maps `(u, v, n)` to `(x, z, y)` and **x × z = −y**.
So an outline wound one way faced outward in a gable and inward in a wall: every opening reveal
and every gable came out with its normals reversed.

The consequence on the plate is a flat sun lighting half the house from inside — WP-5.11's
mirrored-arc class exactly, a model that is entirely self-consistent and ink that is wrong.

**The box normal test passed over it**, because the box's faces are hand-wound and never go
through `sweptFaces`. The tell was a mutation of the cap winding staying green. The fix computes
orientation from the solid's own centroid rather than reasoning about it once per plane, which is
correct whatever the frame's handedness and whatever order the record wrote the outline in.

### 2. A plate served without its metadata is a plate that has stopped disclosing

Serving the flat plates out of `scene.plates` — the whole point of WP-12.3's one call — was
implemented by storing `got["svg"]`. The SVG was right. Everything around it vanished: WP-3.2's
photograph-measurable disclosure, which face the record calls the entrance front, the relaxation
count, and WP-11.8's engine-and-input-digest line.

**The browser walk was the only thing that caught it**, on two checks that read the caption:
*exactly one face is named the entrance front* and *the caption names the face drawn, and where
the front is*. No Python test saw it — `test_scene_endpoint.py` was asserting that the picture
was a picture, and the defect was in everything the picture does not say for itself. That file
now asserts the metadata too.

A plate looking right while having stopped disclosing is precisely the failure surface ⑧ exists
not to have, and it took the slowest guard in the tree to find it.

**And the first version of that repair put its two new guards behind a wall.** The block read
`assert got["svg"].lstrip().startswith("<svg")` first and the two disclosure assertions after it.
Driven with `got["svg"]` written back into `corpus.py`, the suite went red — on a
`TypeError: string indices must be integers` from the picture line, so the guards written for
this defect **were never reached at all**, and the sentence a reader gets says nothing about what
a plate owes. The shape is asserted before the picture now, and both defect shapes were driven:
the bare string fails on *a plate is its drawing AND the things the drawing does not say for
itself*, and `{"svg": ...}` — the plausible half-fix, which sails past the picture line — fails on
*carries a drawing and no metadata*. A guard that a neighbouring assertion makes unreachable is
green for a reason that has nothing to do with the property it names, which is this repository's
own *a guard that runs only where the bug cannot occur* met inside a single `for` body.

### 3. The corpus sheet hash moved, and the package verified the property by hand instead of
running the guard that measures it

`data-frame` was checked by diffing all 44 plates with the attribute stripped. They were
identical, and this package published **"16 of 16 plates byte-identical"** on the strength of it.

`tests/test_exterior_faces.py::test_no_shipped_sheet_moves` hashes the **raw bytes** of all
sixteen shipped sheets. It went red — `373d0116be7cecb8` → `535077ae0bca1ea2` — and **three
commits had already shipped on it**, under an assertion whose own message names the very property
those commits were checking by hand. The full `check_all` was the only thing that said so, fifty
minutes in.

Re-derived over the same sixteen sheets on the same engine: with ` data-frame='...'` removed the
corpus hashes **`373d0116be7cecb8` to the character** — WP-11.14's own value. So the guarantee is
intact and the entire movement is 2,918 bytes of attribute across 16 of 16 sheets.

**A bare re-pin would have converted a defect into a claim.** This pin exists to say that
WP-11.14 is the identity on a one-rectangle corpus; overwriting its number tells the next reader
that identity was re-verified when all that happened is that a new value was written down. So the
stripped hash is asserted **first**, as `CORPUS_SHEET_SHA_NO_FRAME`, and the raw hash second with
a message saying that if the assertion above passed the movement is inside the attribute itself.
A third assertion holds the premise — all sixteen sheets must really carry a frame.

Three mutations, each biting a different one:

| injected defect | assertion that fires |
|---|---|
| a byte outside the attribute (`data-mutant="1"` on the root `<svg>`) | the stripped hash — *"moved by more than the data-frame attribute accounts for"* |
| a wrong `px_per_ft` **inside** the attribute | the raw hash — *"the movement is inside the data-frame attribute itself"* |
| the attribute not emitted at all | the premise — *"only 0 of 16 sheets carry a data-frame"* |

**And the first attempt at the middle one was red for the wrong reason**: it rewrote `frame_attr`'s
argument as a list of dicts, and `frames` is not one, so it died on a `ValueError` having
interrogated nothing. That is this repository's own *a mutation can land, go red, and still prove
the wrong proposition*, met while applying the rule.

### 4. No plan in this corpus states a lot, so a whole block of `render_plan` is unreachable

Swept: **0 of 16**. So the site block, the setbacks and the four `extra_*` terms are dead on every
shipped record, `oy` equals `top` on every plate drawn, and a mutation replacing `data-frame`'s
origin with the sheet's top margin stayed **green**. The fixture states a lot by hand and asserts
the premise, so the day a plan grows one the driven case stops being the only route rather than
quietly becoming redundant.

### 5. Two independently emitted numbers about one edge, agreeing to the printed decimal

`data-plate-top` and `data-frame.origin_px[1]` are written by different code paths and both claim
the plate's top. They agree — to **0.05 px**, because the first is printed at one decimal and the
second carries full precision. The frame is right to: a viewer registering a plate on a model
needs the number and a reader needs a legible one. Stated as a named tolerance rather than rounded
away, which is WP-12.2's residue rule in a new place.

### 6. A plan carries several plates, so a root-level frame would have been wrong by a plate's width

`data-frame` carries a LIST. Measured on the Tidewater plan the two level plates' origins are
**44.0 px and 1177.2 px**: a single frame at the root would have described the ground floor and
mis-registered the upper one by eleven hundred pixels. Found by reading the renderer before
writing the attribute, which is the only reason the attribute has the shape it has.

## What was deliberately not done

- **APPROACH.** The 8 Sep ruling puts a 5′-6″ perspective view in v1 and it stands; it lands with
  **WP-12.7**, beside the entrance and porch it exists to show. At this package the model is an
  undressed massing, and eye height is exactly where a missing cornice, dormer and door surround
  are least forgivable. `frame.js` therefore carries one projection kind, and `PLAN-OF-ACTION.md`'s
  view-bar line is corrected to say so rather than left promising a chip that is not there.
- **The other six overlays and every modifier** — WP-12.5. Only the `plate` overlay is here,
  because it is the one that holds the model and the drawings to each other.
- **Hidden-line removal, cast shadows, dimension strings on the model.** v1 draws faces, edges and
  the flat plate; a dimension the model states itself would be a second authority over a number
  the plates already carry.
- **`elevation.py::_face_bays` was not changed.** It computes bay centres across the span without
  consulting the face, so nothing says which model end `u = 0` is. The viewer assumes the face's
  left edge as the camera sees it and says so in the function; every face in this corpus is
  symmetric, so the assumption cannot be caught out here.
  `oq/an-elevation-does-not-state-which-end-of-the-face-it-starts-from`.
