# WP-12.6 — The envelope dressed, and two fields read off the wrong record

*9 September 2026. Brief: `docs/prd/phase-12-the-sheet-in-the-round.md` §7.3; plan block
`PLAN-OF-ACTION.md` WP-12.6.*

The model has sash bars, meeting rails, shutters and chimneys now. **Tidewater 101 → 492 solids,
the spec Colonial 75 → 368**, every number the record's own.

**The two findings worth reading first are both the same defect**: a field read off the wrong
record, drawing nothing, disclosing nothing, and invisible to the tests written beside it. One
was caught by a census. The other was caught by checking a claim I was about to publish about
something else.

---

## I. What was built

| solid | from | Tidewater | spec Colonial |
|---|---|---|---|
| `muntin` | `lights_across`, `lights_high_per_sash`, `muntin_width_in` | 350 | 200 |
| `sash` (the meeting rail) | the same | 39 | 31 |
| `shutter` | `shutters_carried`, `shutter_leaf_width_in` | — | 62 |
| `chimney` | `roof.chimneys.positions`, `chimney_stack_plan_in` | 2 axes | — |
| `sill` | `kit.window_sill.projection_in` | refused | refused |
| dormers | `elevation.dormers` | none stated | none stated |

`opening-frame` is **unchanged at 40 and 32**. This package changed how an opening is dressed and
not which openings exist, and that is the shape of the guarantee.

**The two shipped plans exercise opposite halves, which is what makes the pair an assertion
rather than a sample.** The Tidewater house carries no shutters — its own kit makes `none`
canonical, adjudicated in WP-5.13 against four independent records — and draws two chimney axes.
The spec Colonial carries 62 shutters and draws no chimney at all, because its roof judges no
ridge and there is nothing to carry a stack up past. A change that drew shutters everywhere, or
stacks everywhere, fails on one of the two.

**The sash arithmetic is `across − 1` verticals and `2 × high − 1` horizontals**, of which the
middle is the meeting rail. The two sashes of a double-hung align, so a bar is ONE member and not
two; the rail is a member of the sash rather than a glazing bar, and carries its own class so a
reader can tell them apart. `sash` is therefore exactly `opening-frame − 1` on both plans: the
entrance door has no sash.

**The sill is refused and that is the finding.** `window_sill.projection_in` resolves to a BAND
on `tidewater-georgian` — `[0, 1]` in, because a child `extends` replaced the ancestor's
derivation — and only 2 of 159 kits state the parameter at all. That is
`oq/a-child-band-replaces-an-ancestor-derivation` reaching its first consumer: WP-11.4 raised it
as a data observation with nothing reading it, and a drawing is the thing that cannot draw a
band. A sill at the band's midpoint is a measurement nobody authored.

**A stack whose plan size is a judgment is an AXIS and never a solid.** `tidewater-georgian`'s
`chimney_stack_plan_in` is 22 in carrying `judgment: true` — the mason still owes 18 or 27 — so
the scene draws a two-vertex construction line where the stack stands and puts the judgment on
the record beside it. `judgment` 0 → 2. Drawing a box at 22 in would have published a dimension
the corpus declines to settle, in the one place a reader cannot tell a decision from a
measurement.

## II. `shutters_carried` was read off the elevation and is set per storey window

The first draft read `elev.get("shutters_carried")`. That key does not exist: it is set per
storey window, at `elevation.py` 1843. So the read returned `None` on every house in the corpus
and **not one shutter was drawn anywhere.**

The picture looked right. The sash bars had appeared, the windows were dressed, the schema
validated, every id was unique, and nothing failed. A whole class of solid was simply absent, and
the only thing that could see it was a **census of solid classes before against after** — which
is why `tests/test_scene_dressed.py` counts classes rather than asserting that some solid exists.

Fixed: 62 shutters on the spec Colonial, 0 on the Tidewater house, and the pair is a test.

## III. `dormers` is plural, and my own three tests corroborated my own wrong key

`build_elevation` writes `"dormers": dorm` at `elevation.py` 2012, and `render_elevation.py`
reads `elev.get("dormers")` in both of its readers. **`scene._dormers` read `dormer`**, so it
took `{}` on every record in the corpus: no dormer drawn, no refusal recorded, no disclosure.

**The three tests I wrote for it could not catch this and would never have caught it.** All three
drive `_dormers` with a hand-built dict, and that dict was written from the same wrong key as the
code — so the fixture and the defect corroborated each other and all three passed. A driven test
proves the branch runs. It says nothing whatever about whether anything reaches the branch.

`test_the_key_this_function_reads_is_the_key_the_elevation_writes` takes the name off a real
elevation now and routes the real block into the function. Deliberately not a source grep for the
string: the property is that the two modules agree about where the record lives, and the only way
to assert that is to route one into the other.

**It was found by checking a claim I was about to publish about something else** — the plan block
says WP-12.6 must not read `placeable` or `not_drawn_reason` "because they do not exist", which
is false (they are written at `elevation.py` 1971-1980), and reading the writer to verify *that*
is what put the plural key in front of me. Neither field was found by reading the code that
consumed it.

### And the fix's first version filed a refusal about nothing

With the key corrected, the shipped corpus moved: `not_modelled` 1 → 2 and 3 → 4. Both shipped
plans state `dormers.stated: True` with **`count: 0`** — a measured zero, the record having
considered dormers and found the house has none — and the function, gated on `stated`, filed
*"the dormer solids could not be modelled"* against both.

**A refusal about something that does not exist is the fake-unjudged collapse wearing its other
face.** It reads as a gap in this layer where the record is in fact complete, and it is exactly
as dishonest as a fake pass. `elevation.py` 1954 is the authority and settles it: `placeable` and
`not_drawn_reason` are written only `if dorm.get("count")`, so a zero count can never reach the
branch that refuses, and gating anywhere but on the count invents a state the writer does not
have. Gated on the count, the census returns to 1 and 3 — the same numbers as before the key was
fixed, now for the right reason rather than by accident.

That case is asserted on the **real records** rather than driven, because both shipped plans are
in it, and the assertion states its own premise so the day a plan grows a dormer the suite says
so.

## IV. One opening had two names, and the guard written to catch that could not

`tests/test_opening_rects.py::test_the_scene_drops_the_same_bay` is WP-12.2's guard that the SVG,
the DXF and the scene all skip the same blind bay. It went red on this package, which had not
touched the blinding: it counted **every solid** where its own docstring named the **frames**, and
blinding a bay now costs 22 solids — two frames, two meeting rails and eighteen glazing bars.

A count that is only incidentally the property it is named for is a guard that fails on the next
unrelated change. That is the **loud** half of the selector fault this repository keeps meeting;
the quiet half goes blind instead. Re-cut against the frames.

**Then a mutation found the real defect underneath it.** The re-cut assertion also checked that a
bay's dressing leaves with the bay — a frame dropped while its glazing bars stayed in the wall
plane is exactly WP-12.2's original shape. Injecting that defect left the guard **green**, because
the two ids could not be compared:

```
frame     _openings rebuilt it:      S-0-ground-window     {face}-{bay}-{storey}-{kind}
dressing  keyed off the rect's own:  S-0-ground-bar-v0     {r["id"]}-bar-v0
```

`opening_rects` has named every rectangle since WP-12.2. WP-12.1 rebuilt that name out of four
fields; WP-12.6 dressed the opening off the record's own. **One opening, two names**, and no
assertion relating a frame to its dressing could hold. It cost nothing a reader could see — the
picture was right, the ids were unique, the schema was satisfied.

The frame takes `r["id"]` now. **Restoring the hand-built name left every suite in this repository
green**, which is why `test_an_opening_has_one_name_and_the_scene_does_not_rebuild_it` exists
rather than a comment. Nothing committed holds a scene solid id, so the rename moves no artefact.

### And it retired a selector in the test beside it

`test_scene_dressed.py` read a solid's storey as `"-ground-" in id` — a **separator**, not a
field. It worked only while the frame id was `{face}-{bay}-{storey}-{kind}`; the moment the frame
took the rect's own name a frame id ended at `ground` and the selector silently matched nothing.
It reads the id's third field now, with an assertion that the count is neither zero nor all,
so a selector matching everything cannot pass either.

## VI. What was deliberately not done

- **The dormer solids are not drawn.** All four of the record's states are stated and the geometry
  is not built: the cheeks, face and own roof stand on the roof *surface*, which this layer models
  as two planes rather than as a box to sit a dormer on. Refused by name, and no shipped plan
  reaches the branch — both state a count of zero.
- **The cornice, water table and belt are not swept.** §7.3 asks for them from
  `profiles.pack_geometry`; they are the entablature's own problem and belong beside the columns
  in WP-12.7, where the same sweep serves both.
- **A shutter is drawn as a plain leaf.** The record states `shutter_panel_count` and the panels
  are not modelled; the solid's own note carries the count, so the drawing discloses what it did
  not draw rather than implying the leaf is blank.
- **The eave-projection question R3 records is not raised**, because nothing in this package
  needed the eave. It belongs with the cornice.
