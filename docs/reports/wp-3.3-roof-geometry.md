# WP-3.3 — Roof geometry

Full technical detail lives in `docs/structure.md`'s new "Roof geometry (WP-3.3)" section, which this report points at rather than duplicates. This is the "what was found" record the hand-off brief asks for.

## What was built

A new `build/roof.py` (`roof_form_for`, `main_roof`, `_hip_lines`, `_cross_gable`, `_style_gambrel_geometry`, `_gambrel`, `wing_step_down`, `chimney_positions`, `cape_eave_check`, `gambrel_break_check`, `dormer_rhythm_check`, `roof_outline`, `elevation_profile`, all orchestrated by `build_roof()`) and a new `build/render_roof.py` (a plan-view roof SVG: eave rectangle, ridge, hip lines, gambrel-break lines, cross-gable ridge, chimney markers, a pass/fail legend). 47 new tests in `tests/test_roof.py`. Both reference plans wired into `build/check_all.py`.

Every height number this file adds builds on top of `structure.py`'s own `grade_to_eave_ft` (and, for gable and hip forms, `grade_to_ridge_ft` too — a symmetric hip and gable roof over the same footprint and pitch share the same ridge *height*, only the plan-view outline differs), rather than re-deriving it independently, so the two files cannot silently disagree about the same building's height. Gambrel is the one form whose ridge height genuinely differs from `structure.py`'s single-pitch simplification; it is recomputed independently and the divergence is stated explicitly in the record's own note rather than swapped in silently.

## What was found

**No bugs reached the test suite this time** — three were caught and fixed during direct manual smoke-testing (invoking the module's functions directly, CLI runs against both shipped plans plus synthetic hip/gambrel/cross-gable/dependency-wing/Cape-style scenarios, and cairosvg PNG renders of the SVG output) before `tests/test_roof.py` was even written, following the discipline WP-3.1 established: actually running the module surfaces mistakes reading the code does not.

1. **`wing_step_down()` initially read the wrong field off `groupings/dependency-and-hyphen.json`.** That file carries two prose fields per internal rule: `statement` (reader-facing prose, "60 to 80 percent") and `test` (a plain-sentence expression, `"dependency_ridge_ft / main_ridge_ft between 0.6 and 0.8"`). The regex that extracts the two band numbers only matches the `test` field's wording; called against `statement` it silently returned `None`, which then raised `TypeError` the moment the ratio band was indexed. Fixed by reading `test` instead. Re-verified directly: the function now correctly returns `ratio_band: [0.6, 0.8]`, `hyphen_length_ft: 16.0`.
2. **`chimney_positions()` collapsed three distinct "can't place a chimney" causes into one misleading message.** The original condition (`if not gable_end or not ridge or ridge.get("grade_to_ridge_ft") is None`) printed "no gable-end indicated" for `spec-builder-colonial.json` even though its massing's `hearth` field genuinely does call for gable-end chimneys (`four-over-four`: `gable-end-paired`) — the real cause was that `colonial-revival` has no migrated roof-pitch constraint, so the ridge height is unjudged and there is nothing to measure a chimney's total height against. Fixed by splitting into three separate branches with accurate, distinct notes. The corrected message (confirmed by direct CLI re-run against `spec-builder-colonial.json`, reproduced below) now names the actual cause.
3. **Dead debug code in `_cross_gable()`** — an unused `half_span` variable computed via a vestigial `... if False else ...` ternary, plainly a debugging leftover, and an unused `cross_span_ft` variable, neither referenced elsewhere in the function. Deleted; the cross-gable path re-verified working after cleanup.

**Verified against both shipped plans, with the actual CLI output:**

`plans/tidewater-georgian-careful.json` (`declared.roof_form: "side-gable"`, style `tidewater-georgian`) — form side-gable, pitch 8.0:12 read from `tidewater-georgian.c02`; grade to eave 25.44 ft, grade to ridge 39.66 ft (both reused unchanged from `structure.py`'s section record); ridge runs the x axis from 0.0 to 62.58 ft (the outside-to-outside footprint's own width); two chimneys placed at the gable-end walls (x = 0.0 and x = 62.58, y = 21.33 — the footprint's mid-depth), each at total height 47.66 ft grade-to-cap, checked against `tidewater-georgian.c01`'s `chimney_height_above_ridge_ft >= 6` constraint and reported **OK** at both.

`plans/spec-builder-colonial.json` (`declared.roof_form: "side-gable"`, style `colonial-revival`) — form side-gable, grade to eave 20.98 ft; ridge **unjudged**, because `colonial-revival` carries no migrated `roof_pitch_rise_per_12` constraint (this is a real, pre-existing gap in the migrated-constraint corpus, not a bug in this file — `structure.py`'s own section record already reports the same unjudged ridge). Chimneys: placement source correctly resolves via the massing-hearth fallback (`four-over-four` → `gable-end-paired`, since `colonial-revival`'s own kit chimney slot is `status: empty`), correctly identifies that gable-end chimneys are called for, and then correctly declines to place them because there is no judged ridge height to measure total height against — an honest "unjudged, not placed" rather than a fabricated height.

**Cross-gable, hip, and gambrel forms verified against synthetic scenarios**, since neither shipped plan declares one: a hip variant of the Tidewater plan produces the expected four diagonal hip lines terminating at the same ridge endpoints the side-gable form already established; a gambrel variant, run under both `dutch-colonial-american`'s own migrated `roof_slope_lower_deg` constraint and (separately) a style carrying no such constraint, correctly prefers the style's own figure when present and falls back to the family-wide default (66°/24°/0.625, sourced from two independently-authored style statements agreeing on the same numbers — see the module's own docstring) when absent, with the two-slope ridge height explicitly reconciled against `structure.py`'s single-pitch estimate in the record's note rather than silently substituted.

**A genuinely schematic finding, disclosed rather than hidden.** `wing_step_down()`'s ridge-step-down ratio check against `dependency-and-hyphen.json`'s own 0.6–0.8 band is real and exercised, but neither shipped plan declares that grouping, and this corpus's `geometry.py` has never placed a real second (wing) volume anywhere — there is no actual wing footprint to measure a real depth or eave height from. The function is explicit about this: it computes a schematic wing depth (one bay module) purely to exercise the ratio rule itself, and marks the result `"schematic": True` with a note naming exactly why, matching the disclosure discipline WP-3.1's `framing_basis` finding and WP-2.2's dining-room finding both established. `tests/test_roof.py` pins this directly (`test_neither_shipped_plan_actually_carries_the_grouping`).

## What was deliberately not done

- Cross-gable valley geometry is not modelled — only the two ridges are computed (main and cross), because `geometry.py` solves a single rectangular footprint and there is no second real volume to cut an actual valley line against. `_cross_gable()`'s own docstring and returned note both say so.
- Hip roofs whose footprint is deeper than it is wide along the ridge axis are flagged rather than re-derived — a hip roof needs its own longer dimension to produce a real ridge line at all; a footprint that fails this collapses the ridge to a point with an explicit note rather than producing a negative-length ridge silently.
- Chimney placement is gable-end only. Interior or off-ridge chimney solutions (needed for hip and gable-on-hip forms where a gable-end wall calling for a chimney genuinely doesn't have one) are flagged as not modelled rather than placed at the wrong wall.
- Dormers are checked only as a pure function of two position lists (dormer centres vs. bay centres) — no schema field on the plan record currently authors where a dormer sits, and neither shipped plan has an attic storey a dormer would light, so `dormer_rhythm_check()` reports honestly not-applicable on both rather than exercising invented data.
- Only a single ridge is modelled per roof volume (main and, where relevant, one cross-gable wing) — no multi-ridge or complex-plan roof geometry (an L- or T-plan with more than one true intersecting volume) is attempted, consistent with `geometry.py`'s own single-footprint scope.
- The elevation-profile silhouettes this file exposes for WP-3.2 are plan-axis-aligned line lists only — no dormers, chimneys, or other roof-plane penetrations are cut into the profile geometry itself; those remain separate record fields (`chimneys`, `checks.dormer_rhythm`) for the elevation generator to draw on top rather than being merged into one silhouette.
