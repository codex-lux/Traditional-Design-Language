# WP-14.23: a record is a place, and the slot list that counted a refusal as a specification

*25 September 2026. Branch `worktree-agent-a7c46478de859e925`, taken from `c8ed0c1`. The contract
is `docs/prd/phase-14-tranche-2.md` §B (routes, citations, legacy addresses, the site map), §C.6
(what a record page reads), §A.2 (the `try` example on a kind's surface record), §F (who owns which
file) and §G (what no package may do). Every figure below was measured in this worktree, the
base figures on a `git archive` of `c8ed0c1`. Cite this report by filename.*

**Verdict: five kinds of record have a page of their own, and a palette result now lands on the
page that shows it.** A slot is `#/elements/<slot>` in a new Elements index. A room type, a
massing, a grouping and a parti are `#/room/<id>`, `#/massing/<id>`, `#/grouping/<id>` and
`#/parti/<id>`. Until now those four citations landed on a surface that was about something else
(the bench, the family tree, the candidate set) with a "searched" card over it, and that card,
`components/Spotlight.jsx`, is deleted. Each page shows its record's relation from the other side,
and each of those inverse lists is computed from the forward relation and held to it by a test.

**The finding is about the slot page's own data.** Tranche 1's interim slot page printed
`core.get_slot`'s `specified_by_styles` under the heading "specified by". That list reads each
style's own kit file and counts any record with a status, so it lists styles that FORBID the slot.
It also misses every style that inherits the slot. **All 97 of 97 slots disagree with the resolved
reading.** The page reads the resolved kits now. `tdl_get_slot` is left byte-stable and carries the
defect, which is
`oq/the-slot-tool-lists-a-style-that-forbids-a-slot-as-specifying-it`.

## I. What was built

**The addresses (router.js, citations.js).** Five rows join `SURFACE_PATHS`:

| surface | key | address |
|---|---|---|
| `elements` | `slot` | `#/elements[/<slot>]` |
| `room` | `roomType` | `#/room[/<id>]` |
| `massing` | `massing` | `#/massing[/<id>]` |
| `grouping` | `grouping` | `#/grouping[/<id>]` |
| `parti` | `parti` | `#/parti[/<id>]` |

`routeCite` sends `slot:`, `room:`, `massing:`, `grouping:` and `parti:` to these pages, and
`citeFor` is its inverse on each. **No regex changed**: the citation grammar is spelled three
times and `test_grammar_agreement.py` holds the three together, so a fourth spelling was not
available and none was needed.

The addresses tranche 1 wrote for these records are kept in `LEGACY_PLACES`. It has one row per
retired (surface, key) pair:

- `#/style/-/kit/<slot>` and `#/kit/-/<slot>`
- `#/workbench?roomType=`
- `#/workbench?grouping=`
- `#/phylogeny?massing=`
- `#/candidates?parti=`

Each is read as the record page and rewritten with `replaceState`. A row applies only when the old
selection holds nothing else, so `#/candidates/2?parti=x` stays the second candidate and
`#/workbench?roomType=parlor&room=parlour` stays the bench (both are in `router-unit.mjs`'s list of
addresses that are not legacy).
`canonicalPlace` is the one reader. `parseHash`, `formatHash` and `navModel.normalizePlace` all
call it, so a place built by hand with a retired key reads as the record page too.
`#/brief?parti=` is not legacy: WP-14.19 made it the brief naming a parti.

**The site map (navModel.js, crumbs.js).**

- Elements is a Library item after the fault corpus.
- The four record surfaces stand `UNDER` it. They have no rail item of their own, and the rail
  marks Elements while one is shown.
- The trail is Library › Elements › the record.
- A bare record surface is its kind's index, and its crumb is the kind's own surface record.
- The page head's eyebrow is the kind (`surface-room` and so on), from `headTermFor`.

**The server.**

- `GET /api/slots` serves every slot row exactly as `core.get_slot` serves its `slot`, plus
  `specified_by`, the count of styles whose resolved kit specifies it.
- `GET /api/slots/{id}` adds `bindings`: the specifying and the forbidding styles, each read from
  the resolved kit.
- `GET /api/groupings/{id}` adds `carried_by`, the partis whose own `groupings` name it.

Every enrichment is on the workbench's copy in `corpus.py`. `core.get_slot` and
`core.get_grouping` are untouched, so the MCP payloads are byte-stable, and a test asserts the
tool's keys. The massing, room and parti routes already carried their inverse (`used_by`,
`appears_in_groupings`, `nativity_by_style`) and are unchanged. `api/client.js` gains four
functions appended at the foot, and no existing function is edited.

**The pages.**

- `surfaces/Elements.jsx` is the index: the slots under their groups, each with its served count,
  and above them a link to each kind's index. `?q=` narrows it.
- A slot is `dossier/SlotPanel.jsx`. Tranche 1 built it as the interim page, and it moved here.
- `surfaces/RecordPage.jsx` draws a kind's index or one record.
- `record/{Room,Massing,Grouping,Parti}Body.jsx` draw one record each, over `record/parts.jsx`.
  The name comes first, the id is a Courier note beside it, and every heading is a glossary
  record's word through `Term`.
- **The parti's rooms are a TABLE**: type, level, outside walls, doors. The page draws no diagram,
  because a parti states topology and roles and no positions (§G).

**The words.** Seventeen new glossary records name what these pages show that nothing named:
furniture, footprint, clearance, the three adjacency ladders, a massing's plan shape, storeys and
bays, why a massing takes its shape, how it grows, a grouping's internal rules, what it attaches
to, what a parti gives up, and the parti table's level, outside walls and doors. Each quotes the
schema field it names. The five kind surface records gain a `try`, the one record §A.2 offers a
reader to open. `surface-compare` does not, as the brief says. `check_glossary`: **203 records and
643 quotations verified** (186 and 621 on the base).

**The retirement.**

- `Spotlight` is gone from `CandidateSet.jsx`, `PlanWorkbench.jsx` (two sites) and
  `Phylogeny.jsx`, and its file is deleted.
- `PlanTypes.jsx`'s massing, parti and grouping names are `RecordLink`s to their pages. This hunk
  is minimal, because the file is shared with WP-14.25.
- The Style Dossier no longer holds a slot place. `dossier/sections.js::placeOf` answers `dossier`
  or `index` and nothing else.

## II. What was found

**1. The slot tool counts a refusal as a specification, and misses every inheritance.**
`core.get_slot` walks `D["kits"]` (each node's own kit file) and appends a style whenever its
record's `status` is not `empty`. It never reads `binding`, and a forbidden binding carries a
status because the forbidding is authored. Measured over all 97 slots against
`corpus._resolved_bindings`, which reads `core._resolved_kit` for all 164 styles:

| | count |
|---|---|
| slots whose two lists differ | **97 of 97** |
| own-list entries whose own kit FORBIDS the slot | **228**, over 41 slots |
| own-list entries bound `open` | 8 |
| own-list entries an `extends` resolves to forbidden | 2 (`colonial-revival.cornice_return`, `georgian-revival.water_table`) |
| resolved specifiers missing from the own lists | **6,380** (2,145 listed, 8,287 resolved) |

Three specimens:

- `cornice`: 35 listed against 85 that specify it after the cascade. 10 of the 35 are forbidden
  in their own kit, and the resolved kits forbid the cornice on 24 styles.
- `construction_type`: 64 against 149.
- `roof_form`: 62 against 118.

Tranche 1's slot page printed that list under "specified by", so a reader choosing a cornice was
shown ten styles that refuse one among the styles that use one.

The page reads `bindings` now and shows the forbidding styles under their own heading.
`test_record_pages.py` holds both lists to an independent reader. It also asserts the PREMISE, that
the own-kit list still differs. Without it, a later fix to `get_slot` would leave the test
comparing two equal lists and proving nothing.

**Not fixed in `core`.** The tranche-2 PRD holds the MCP payloads byte-stable, and changing a
tool's answer under an agent that relies on it is a ruling. The open question also warns against
the obvious repair: filtering `binding == "forbidden"` alone removes the 228 and leaves the 6,380.

**2. A kind index read from the list routes would have been a partial list and said nothing.**
`GET /api/massings` defaults to `limit=25` over 40 massings, `/api/rooms` to 25 over 60 rooms and
`/api/groupings` to 20 over 17 groupings. An index page built on them would have shown 25 of 60
room types as though that were the catalogue. The kind indexes read the names index instead
(`useNames`, the search index the palette already holds), which carries every record of every
kind. The walk holds each index's row count to that index's own count for the kind.

**3. The walk's "searched" check asserted the card, not the property the card stood for.**
`walk.mjs` visited `#/cite/room:parlor` and asserted that the word *searched* was on the page.
That asserts the workaround existed. It says nothing about whether a reader who searches for a room
reaches the room. It is re-cut into the property: for one record of every kind with a page (the
first of its kind by id in the search index, never a literal), the palette is opened, the id is
entered, the result is dispatched as a reader dispatches it, and the check requires three things:

- the address is the page's own;
- the page carries that citation;
- the record's own head drew.

A second alternation, `|searched` on the family tree's hearth-click check, was the same card
surviving as an accepted answer, and is removed.

**4. A record page with an empty inverse would pass any comparison with nothing drawn.** The new
walk block takes each kind's `try` record, reads the inverse list the server states for it, and
requires the page's count to equal it. It also requires the server's count to be above zero,
because a zero is also what a page that drew nothing reports.

**5. The walk's first run convicted two record pages, and the fault was in the new check.** The re-cut
palette check failed on `parti:bungalow-open-linear` and `room:attic`, and passed on the other
three kinds. The palette's own `search()`, run over the served index, ranks all five first, so the
records were findable. `CommandPalette.jsx` focuses its input a tick after the dialog paints
(`setTimeout(..., 0)`). Keys typed the moment the dialog was visible could arrive before the focus
did and lose their first characters, depending on what the previous iteration left behind. The
check now `fill`s the input, which is what a reader's typing ends as, and waits for the option
rather than sleeping 500 ms. The second run is green on all five. A reader types more slowly than a
robot, so this is recorded as the instrument's race and not the app's.

Each mutation was applied by a script that asserted it LANDED, ran the guards reading exit codes
directly (never through a pipe), and restored the file byte-for-byte, asserting that too. The
harness is in the session's scratchpad.

| mutation | red |

| `routeCite('room:x')` sent back to the bench (`surface: 'workbench'`) | `src/record.test.mjs` (2 of 10), `e2e/router-unit.mjs`, `e2e/search-unit.mjs` |

| `corpus.grouping`'s `carried_by` drops its last parti | `test_record_pages.py::test_a_groupings_partis_are_the_partis_that_carry_it_in_both_directions` |
| a `Spotlight` import restored in `Phylogeny.jsx`, the file still deleted | `src/record.test.mjs` (the name scan) |
| `components/Spotlight.jsx` restored, no call site | `src/record.test.mjs` (the file check) |

The Spotlight mutation was run twice on purpose. The test checks that the file is absent BEFORE it
scans for the name, so restoring the file alone would be caught by the first half and would never
prove the second. The call-site variant leaves the file deleted and is caught by the scan alone.

`check_glossary.py` catches the deleted record only by accident: `glossary/parti.json` names it as
a `confusable_with`. The guards that name the rule are the two app-suite tests. One is
*"every surface the router routes has a surface-<id> record of its own"*. The other is
*"each kind names glossary records that exist"*.

## V. What was deliberately not done

- **`core.get_slot` is unchanged**, and so is every MCP payload (II.1).
- **No diagram of a parti.** A parti states no positions, and a drawing from it would draw what it
  does not hold.
- **No count literal in JSX or tests.** Every count a page shows is the length of a list it was
  served. The Elements index's kind counts are the names index's own counts per kind. The tests
  read their expectations from the corpus files.
- **`PlanTypes.jsx`'s now-unused `data` import is left**, to keep the hunk in a file WP-14.25 also
  edits to the lines that change.
- **The list routes' default limits are unchanged.** They are other callers' contracts, and the
  pages do not read them (II.2).
- **A retired address that holds anything beside the record is not rewritten.** Only one that
  names the record and nothing more is read as the record page, because `#/candidates/2?parti=x`
  is still a candidate and a bench holding a room is still a bench.
