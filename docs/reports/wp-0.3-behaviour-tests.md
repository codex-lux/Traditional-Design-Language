# WP-0.3 — Behaviour tests and a single check entry point

*Executed 23 August 2026, overnight autonomous session, immediately following WP-0.2.*

## What was built

`tests/` — a pytest suite of 35 tests across six files, every one of them protecting a specific finding recorded in `docs/plans.md`, `docs/compose.md`, `docs/geometry.md`, `docs/inheritance.md`, `docs/proportion.md`, or `mcp_server/README.md`, named for the finding it protects rather than for the function it calls:

- `test_plan_validator.py` (16 tests) — the exact fatal/serious/minor counts and the three named fatals on both shipped plans; the two-hop-through-a-hall widening and its contrast case (a room present but genuinely unreachable, which must still fail); circulation being rank-transparent and its contrast case (a direct jump between two non-circulation rooms, which must still fire); the `via` intermediary on the kitchen→dining rule and its contrast case; the two-ended daylight halving and its contrast case (a single-sided room at the same depth, which must still fail); completeness findings kept separate from, and never outranking, genuine defects.
- `test_composer.py` (5 tests) — Centre Passage, Single Pile ranks first on the family-Georgian brief with zero fatal; Bungalow, Open and Linear ranks first on the bungalow brief; the composer always returns four genuinely different partis, never one, and every candidate states what it trades away (decisions #9 and #10).
- `test_kit_cascade.py` (3 tests) — the three-level chain (tidewater-georgian → georgian-colonial-american → english-georgian) resolves and every level actually contributes bindings, not just the first; `check_kits.py` still catches a variant `op: replace` naming an id no ancestor defines (round-trips a real kit file through a deliberately broken copy and restores it in a `finally`, so the corpus is provably unmodified whether the test passes or fails).
- `test_proportion_engine.py` (6 tests) — `selftest` and the three checkers stay green; and, because it's one of the sharpest findings on record, that Vignola's Corinthian and Composite pedestal really is 7/20 = 0.35 of the column and not the folklore 1/3 — computed from `proportion_engine.resolve()`'s live output, not hand-copied.
- `test_core_measurements.py` (3 tests) — a measurement the corpus has no test for comes back entirely `unjudged` (0 present, 0 clear), never silently `passed`; a passing and a failing measurement are correctly `clear` and `present` respectively, using the exact half-width-shutter numbers from the shipped Spec Builder Colonial fatal.
- `test_geometry.py` (5 tests) — the spanning rule (only a circulation room with exterior walls on opposite sides spans; a porch with the same wall condition must not) on all four wall-pair/axis combinations; a smoke test that `solve()` still places every indoor room in the careful Tidewater plan with coordinates and reports its relaxation count.

`build/check_all.py` runs the twelve existing data checkers in sequence, then `pytest tests/`, and prints a summary that names every failure rather than stopping at the first — a script fixing one broken checker should not have to re-run the suite five times to find the second one. `Makefile`'s `check` target wraps it (`make check`); `counts` wraps `gen_readme_counts.py`. No GitHub Actions workflow was added — see "what was deliberately not done" below.

## What was found

**Two more instances of the exact drift this whole phase exists to fix**, both caught by writing tests against live behaviour rather than against the docs' own numbers. `docs/plans.md`'s summary table said 54 serious findings on Spec Builder Colonial and 19 on the careful Tidewater plan; the actual, current numbers (verified by running `plan_check.py` directly, both with `--json` for machine-readable counts and by hand-counting the human-readable output) are 49 and 18. The table has been corrected and a note added pointing at the test that now pins it. A similar discrepancy exists between `docs/geometry.md`'s narrative ("11 upper wall line(s) do not continue to a wall below") and this session's default `geometry.solve()` call on the same plan, which reports 16 — but the doc's example uses an explicit `--parti centre-passage-double-pile --candidates 900` invocation this session did not reproduce exactly, so unlike the plan-validator table this was **not** corrected; it would be asserting a discrepancy without controlling for the variable that most plausibly explains it. Flagged rather than silently changed — see "open question" below.

**The `EQUIVALENT` room-type aliasing groups in `plan_check.py` (stair-hall/vestibule/entrance-hall are treated as interchangeable for adjacency purposes) is not documented anywhere**, and it broke the first draft of the two-hop-through-circulation test: a "circulation room standing between powder-room and entrance-hall" fixture using `stair-hall` as the intermediary passed even with the entrance-hall room deleted entirely, because `stair-hall` itself aliases to `entrance-hall`. The fixture was rebuilt using `centre-passage`, which is not in any alias group, to isolate the mechanism actually under test (the one-hop-through-circulation widening) from a second, undocumented mechanism (type aliasing) that happened to produce the same visible result. This is worth a short paragraph in `docs/plans.md` or `docs/model.md` — recorded as an open question below rather than added speculatively.

**`check_measurements`'s exact return shape** (`faults_present`, `faults_clear`, `could_not_judge`, `summary: {present, clear, unjudged}`) matches what `mcp_server/README.md`'s own "Testing without a client" example implies, and the shutter numbers from that example (12 in leaf / 32 in opening → clear; the shipped plan's 10.67 in / 32 in → present, `shutter-half-width-leaf`) reproduce exactly.

## What was deliberately not done

**No GitHub Actions workflow.** The consolidated repository (WP-0.1) has no remote configured — git is local-only in this session's working copy, and setting up CI against a remote that doesn't exist yet would be premature. `make check` / `python3 build/check_all.py` is the CI-equivalent entry point for whenever a remote and a workflow file are wanted; adding the workflow file itself is a five-minute follow-up once that decision is made.

**`docs/geometry.md`'s "11 upper wall lines" was not changed**, for the reason given above — the doc's own example command differs from the default `solve()` call this session's test uses, and changing prose to match a differently-parameterised run would itself be a small dishonesty of the kind this whole phase is trying to eliminate.

**No JS/Python cross-engine order agreement test.** `dist/orders.html` is checked (per the state-of-project review) to agree with the Python proportion engine to 0.02 inches, but porting that comparison into this pytest suite would mean either running a JS engine as a subprocess (Node is available in this environment, but the comparison harness itself doesn't appear to exist as a standalone, invokable script — it would need to be extracted from `render_orders.py` or `dist/orders.html` first) or re-implementing the comparison in Python against the rendered HTML's embedded values. Both are more than this package's scope; flagged as a good candidate for a small follow-up package rather than done partially here.

**Room/type-alias behaviour was not turned into its own documented feature.** The `EQUIVALENT` groups clearly encode a real architectural judgement (a stair hall often *is* the entrance sequence in smaller houses) but nothing states that judgement in prose anywhere a reader would find it before hitting the surprising test result this session hit. Recorded as an open question rather than added to a docs file with words this session would be putting in Lucas's mouth.

## Open question raised

It is real, load-bearing logic — it changed this session's test-fixture design once already — and it currently exists only as an unexplained list in the source. Added to `docs/open-questions.md`.
