# WP-11.1 — The sheet says what the placement gave up

*Phase 11, package 1 of 11, and the first of the three that needed no ruling. 4 September 2026.
Raised by `docs/reports/tidewater-layout-diagnosis-2026-09-04.md` — findings J1, J2, J3, J5, F1 and
G1 — where the plate Lucas read said* **PLACEMENT PROVED (CP-SAT) AGAINST THE RECORD'S DECLARED
FACTS** *over a placement that had set aside sixteen of the record's declared exterior walls, both
ends of the centre passage among them, with its compositional objective never evaluated.*

## What this package is

Five facts were already in the record the sheet was rendering, and nothing anywhere in the tree
read any of them:

| fact | where it already lived | on the shipped Tidewater plan (CP-SAT) |
|---|---|---|
| declared exterior walls set aside to reach a placement | `geometry_report.solver.downgraded_wall_pins` | **16 of 35** |
| the compositional objective never ran | `geometry_report.solver.objective: null` | true — "best of 1 hard-valid placements" |
| declared window units not drawn | `opening_report.windows_unplaced` and each window's `unplaced.reason` | **27 of 35** |
| upper wall lines landing on no wall below | a sentence inside `geometry_report.vertical` | **30** |
| what each ∗ room's record asked for | the room's own `width_ft`/`length_ft` | **24 rooms**, worst +81% |

They are on the plate now, and on the bench, computed once. `build/disclosures.py` is the one
spelling: `build/render_plan.py` draws its lines on the printed sheet, and
`core.placement_summary` carries the same list to the workbench as `placement.disclosures`, so the
Plan Workbench displays what Python computed rather than deriving a second version in JavaScript.
**Do not add a third.**

Two more lines came with them. The engine line no longer claims the whole record when part of it
was set aside — it reads *PLACEMENT PROVED (CP-SAT) AGAINST 19 OF THE RECORD'S 35 DECLARED EXTERIOR
WALLS*, in the warning colour rather than the reassuring one. And a **style disagreement** line
fires when the plan's title names a style that is not the one the sheet judged it as, or when the
parti the record names does not list that style: the plate Lucas read was titled *"Tidewater
Georgian, five bays, carefully planned"* and carried the style slot `palladian`, which is a
different node, a different cascade and a different fault set, and no field on the sheet compared
them.

Under the plates there is now a table, **WHAT THE RECORD ASKED FOR**, giving every ∗ room's drawn
figure beside its declared one. It is a table rather than a second line inside each room
deliberately: the label fitter reserves space for every line it draws, so a per-room record line
would have shrunk names until they dropped out, and **a room that loses its name to gain a
disclosure has traded one silence for another.**

## What was found

**1. THE FIRST DRAFT OF THIS PACKAGE INTRODUCED THE DEFECT IT WAS SENT TO REMOVE.** The undrawn-
window line ran 160 characters, and the canvas cut it mid-word: *"…3 THE WALL HAS NO CLEAR RUN LEFT
BESIDE ITS DOO"*. A disclosure the sheet does not show, produced by the package that exists to make
the sheet disclose — and found by rasterising the plate and looking at it, which is the only thing
that has ever caught one of these in this repository. The fix is two-part and the second half is
the durable one: the reasons are shortened where a short form exists, and `_wrap_banner` wraps any
line too long for the plate rather than letting it run off, because **a disclosure that does not
fit is still owed**. `tests/test_sheet_disclosures.py` holds every banner row inside the canvas
width, computed from the renderer's own `.lb` advance.

**2. The banner's height is the number of ROWS, not the number of LINES, and the layout arithmetic
had to be reordered to know it.** `top` — the sheet's top margin — reserves 14 px per banner line,
and a line that wraps costs two. But wrapping needs the plate's width, and the width was computed
after `top`. Nothing above `top` depends on it, so the width computation moved up. Left as it was,
the reserve would have been short by exactly the amount a long disclosure needs, and a long
disclosure would have been drawn through the top of the first plate — which is
`docs/reports/wp-9.6-the-check-that-could-not-see-the-drawing.md`'s finding, in the same file, one
package later.

**3. A NEW INSTRUMENT PUBLISHED A FALSE CLAIM ABOUT THE ONE ENGINE THAT CANNOT MAKE THE MISTAKE.**
`build/diagnose_sheet.py` (below) read `solver.objective is not None` for both engines and duly
reported *"the objective did not run"* for the hill-climb — which writes no `objective` field at
all, because its score IS its objective, summed over every candidate it looks at. It printed on
the instrument's very first run, in the line a reader would have quoted. `objective_not_run` is
gated on `engine == "cp-sat"` in both files now and
`TestTheObjectiveThatDidNotRun::test_the_hill_climb_never_takes_this_line` is the guard.

**4. The bench's caption was making a claim the bench did not support.** *"Where a set of them
could not all hold, the ones it had to give up are named above rather than dropped."* Nothing
above named them: the panel that exists for this shows `geometry_report.infeasible`, which is a
different and rarer state, and `downgraded_wall_pins` had no reader on any surface. It is true now
and says so; where a placement gave nothing up the sentence reads *"It gave nothing up."* This is
`docs/reports/wp-6.4-the-audit.md`'s class — a prose claim its own package falsified — found in a
caption written by that package's successor.

**5. AND ONE OF THIS PACKAGE'S OWN NEW GUARDS WAS BLIND, CAUGHT BY MUTATING THE CODE IT
GUARDED.** `test_the_canvas_grows_for_the_table` compared the sheet's height with the table against
its height without, and **passed with the growth term deleted** — because a plan with no diverged
rooms also loses a banner LINE, and 14 px of banner is enough to keep `tall > short` true. Two
causes, one comparison, and the one under test contributed nothing. It is replaced by the direct
property: no mark the sheet draws may sit below the canvas it declares, plus an assertion that the
lowest mark is near the foot so the guard cannot hold vacuously on a sheet with no table. That is
`docs/reports/wp-10.1-the-audit-of-the-dependency.md`'s lesson — a mutation that changes nothing is
evidence the fixture is blind — met inside the package that quotes it.

**6. AND THE BENCH'S OWN PAYLOAD CAUGHT A SEVENTH.** Run against `/api/plan/evaluate` the
undrawn-window line read *"14 OF 35 … 2 1 OF 2 UNIT(S) HAD NO CLEAR RUN LEFT ON THIS WALL"* —
two counts in a row, because `openings.py` parameterises that one reason with a count already
inside it and this file was counting by sentence. Reasons are grouped by KIND now. Found by
running the server path rather than by any test, which is the same lesson as (1): look at the
thing.

## The instrument, and the baselines every Phase 11 package is held to

`build/diagnose_sheet.py` generates the diagnosis's Part I from a record rather than from a
screenshot: every room's drawn rectangle beside its declared one, the placed and declared exterior
walls, the entrance front's openings per storey and how many sit over one below, the solver's
downgrades and objective status. `--baseline` prints one line of the six numbers Phase 11 measures
every package by. Measured 4 Sep 2026, before this package changed anything about placement (it
changes nothing about placement):

| plan | engine | key (fatal/serious/minor) | diverged | windows unplaced | walls set aside | transfers | score |
|---|---|---|---|---|---|---|---|
| tidewater-georgian-careful | heuristic | 3 / 62 / 85 | 21 | 13 of 35 | 0 | 9 | 712.6 |
| tidewater-georgian-careful | cp-sat | 0 / 73 / 80 | 16 | 27 of 35 | 16 | 30 | 835.0 |
| spec-builder-colonial | heuristic | 10 / 97 / 90 | 18 | 5 of 14 | 0 | 4 | 630.0 |
| spec-builder-colonial | cp-sat | 4 / 132 / 87 | 15 | 6 of 14 | 6 | 16 | 1285.1 |

**Read the two engines together or not at all.** CP-SAT halves the Tidewater plan's fatal findings
and doubles its undrawn windows, triples its transfer beams and scores 122 points worse; on the
spec Colonial it is worse on every column. A package reporting one engine's movement is reporting
half of what it did — which is why the phase's own measurement rule names both.

**The `diverged` count differs from the diagnosis's 23/24, and the difference is the instrument,
not a change.** The diagnosis read the screenshot's own banner (23) and then a fresh CP placement
(24); this table is a fresh placement on 4 Sep at the default candidate count. Nothing about
placement moved in this package: `tests/test_geometry.py`'s pinned relaxation counts are unchanged
and both shipped plans place byte-identically.

## What was deliberately not done

**Nothing about what the solver DOES.** This package only reports it. The sixteen set-aside walls
are the container's fault and are WP-11.6's; the objective that did not run is WP-11.8's ruling and
WP-11.6's real fix; the undrawn windows are WP-11.7's.

**The DXF and IFC exports do not carry the disclosures.** A downloaded drawing is the same house
and should say the same things, and `export_dxf`'s XDATA is capped near 16 KB per entity
(`docs/reports/wp-9.2-the-corrective-revisions.md`), so the disclosure list needs a decision about
what rides in a drawing and what does not. Named here rather than half-done.

**No line for a heuristic placement's own compromises.** The hill-climb gives things up too — it
charges itself and wins — and `geometry_report.under_band` already reports the sharpest of those on
the bench. A `walls_set_aside` equivalent for the search would need the search to record which
declared walls it failed to honour, which it does not.

**The style-disagreement line does not fire on a silence**, only on a positive disagreement: a
title naming another style, or a parti not listing this one. Most plan titles name no style, and a
line that fired on every sheet would be ignored by the second week.
