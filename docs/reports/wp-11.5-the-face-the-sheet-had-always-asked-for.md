# WP-11.5 — the face the sheet had always asked for

*5 September 2026. Graphic Standard No. 1 names one serif voice. Every plate this system has
ever produced asked for it in a `font-family` stack and carried no font.*

---

## What was asked for, and what was built

`PLAN-OF-ACTION.md`, WP-11.5, in full: *"A subset `@font-face` in the exported SVG. Until it
lands the sheet is set in whatever serif the reader's machine has, and the title block must say
so."*

Both halves are built. The sheet carries EB Garamond and the margin says which face it is set in.

| | |
|---|---|
| new | `build/gen_sheet_font.py`, `assets/generated/eb-garamond-sheet.woff.b64`, `eb-garamond-sheet.json`, `eb-garamond-OFL.txt`, `tests/test_sheet_font.py` |
| changed | `build/sheet_style.py` (`font_asset`, `face_status`, `font_face_rule`, `advance_widths`), `build/render_plan.py` (the `<style>`, `_adv`, the margin schedule), `requirements.txt` |
| the face | EB Garamond 1.003, printable ASCII + a named extras list, **127 glyphs, 15,016 bytes WOFF, 20,024 base64** |
| the cost | the Tidewater plate **43,141 → 63,555 bytes, +47%**; over all 32 sheets (16 plans × 2 registers) **813,739 → 1,469,385, +81%** |
| checks | unchanged at 49; tests **1,612 → 1,628** |

This is the first thing in the repository that needs `fontTools`, and it runs by hand: the
artefact is committed, so no checker, no test and no drawing imports it.
`tests/test_sheet_font.py::test_nothing_at_render_time_imports_fontTools` walks the five renderer
sources to keep it that way, because *"the corpus and every checker in build/ run on the standard
library alone"* is a property `requirements.txt` states about itself in its own first paragraph.

## I. The finding: the sheet's own mark is in neither face it names

`∗` is the mark a working sheet puts on every room drawn at a size the record does not declare.
It is defined in the sheet's own margin — *"23 ROOM(S) DRAWN AT A SIZE THE RECORD DOES NOT
DECLARE, MARKED ∗"* — and it is **U+2217 ASTERISK OPERATOR**, a mathematical operator, not the
typographic asterisk U+002A.

Measured, on the two faces the standard states and `sheet_style.py` spells:

| stack | first family | cmap entries | has `∗` |
|---|---|---|---|
| `FACE` — `.nm` room names, `.hd` the plate title | EB Garamond 1.003 | 2,091 | **no** |
| `MONO` — `.dm` dimension strings, `.lb` the margin | Courier Prime 3.018 | 383 | **no** |

**Every other character the shipped sheets draw is supplied by the first family of its own
class's stack.** This is the only gap and it is on the one symbol the sheet defines.

It renders today, and that is the problem rather than the reassurance: Chromium draws it by
falling past both declared stacks into a system font, so the plate carries a third face for one
glyph — Phase 11's own opening complaint, at one character instead of a whole sheet. On a machine
whose fallback chain lacks U+2217 it is a box.

**Not changed.** The symbol is the standard's, and a renderer quietly swapping a glyph the
standard chose is the same class of edit as a checker reconciling two records by picking the
number that makes it green. The generator RECORDS the gap (`missing_from_source` in the sidecar)
and `test_the_divergence_mark_is_in_neither_face_the_sheet_names` pins it as a SET so it cannot
grow in silence. `oq/the-divergence-mark-is-in-neither-face-the-sheet-names` carries the three
things a ruling has to settle — including whether to carry the mono face too, which would make
the rule *"every character a renderer emits must be supplied by the stack it is emitted in"*
enforceable for both stacks instead of one.

## II. `recalcTimestamp=False`, and why a generated artefact could not otherwise be verified

The generator's first two builds of one font from one source produced different files. fontTools
writes `head.modified` as the time of the save unless told not to, so four bytes differ and every
hash of the output differs with them.

**A generated artefact nobody can rebuild identically is an artefact nobody can verify**, and
`gen_sheet_font.py --check` — whose whole job is to say whether the committed asset is what the
script builds — would have been a command that always says FAIL. One keyword argument, and the
two builds now agree to the byte.

The same `--check` carried a second defect of the same family, found on its first run: given no
`--source` it fell through to `if not (a.source or a.fetch)`, printed the docstring and returned
**0**. A check that reports success by doing nothing. `--check` implies `--fetch` now.

## III. The fitter measures the face it draws in, for the first time

`render_plan._adv` was a five-branch estimate of glyph widths:

```
if ch in "iljI.,:;'|!": return 0.28
if ch in "ft()[]r ":    return 0.36
if ch in "mwMW":        return 0.86
if ch.isupper() or ch.isdigit(): return 0.66
return 0.53
```

One number, 0.66 em, for every capital — in a face whose `I` is **0.34** and whose `W` is
**0.916**, a three-to-one spread. `.` is 0.23 against the estimate's 0.28. It was a guess about a
face the sheet did not carry, which was reasonable while it did not carry one.

`workbench/app/src/sheet/label.js` has measured the real glyphs in a canvas since WP-5.2, so the
two renderers of one record have disagreed about how wide a room name is for four packages. The
generator now writes the subset's own `hmtx` advances into the sidecar and `_adv` reads them:
**34 room labels across 10 of the 16 plans change size.**

**The estimate is kept, not deleted.** A checkout without the asset still has to fit a label, and
`test_the_estimate_survives_for_a_tree_with_no_asset` is the test that says which one is running.

## IV. The choices, each with the measurement behind it

**WOFF, not WOFF2, not TTF.** Printable ASCII plus the extras is 26,280 bytes as a TTF (35,040
base64) and 15,016 as WOFF (20,024). WOFF2 would be smaller again and needs the Brotli extension,
which is not installed here; WOFF's compression is zlib, which is in the standard library, so the
artefact can be verified by anything that can open this repository.

**It reaches no desktop drawing program, and that is not a defect of the format.** Inkscape
resolves type through fontconfig and does not load an `@font-face` at all, in any format. An
embedded face reaches every browser and nothing else. A reader who needs the sheet set correctly
in Inkscape installs EB Garamond — and the margin now tells them which face to install.

**Printable ASCII, not the 44 characters today's sheets draw.** See §V; this is the choice the
package's own guard could not defend.

**Per sheet, not per drawing set.** A drawing set carries the same 20 KB on each of its plan
plates, because an exported SVG has to stand alone — that is the whole reason the package exists.

**The serif only.** Courier Prime is OFL and a subset is about 9 KB base64 on top of the serif's
20. The plan of action names the serif; carrying the mono is the third item of the open question
above, because it is what would make the coverage rule enforceable for both stacks.

**The other three renderers are untouched.** `render_section.py`, `render_elevation.py` and
`render_roof.py` draw in the DARK register and set Archivo and Bodoni Moda, which is a different
argument and not this package's.

## V. The guard that could not see the thing it was written for

`test_every_character_the_sheet_sets_in_the_serif_is_in_the_subset` is the obvious guard for a
subset, and it is blind in one direction. **Every character any of the sixteen plans sets in the
serif is an uppercase letter, a digit or ASCII punctuation** — 42 distinct over all of them, 32
over the two that ship — because room names and plate titles are upper-cased before they are
drawn. A regeneration cut to those 42 glyphs saves 8 KB a sheet
(11,984 base64 against 20,024 — measured, and exactly the kind of saving that gets taken), leaves
that test green, and breaks the first mixed-case name anybody writes.

The mutation was run: narrowing the sidecar's charset to capitals left the sheets-versus-subset
test **passing**. The guard that bites is over the PROMISE — *the subset must cover printable
ASCII* — rather than over today's traffic. Both are kept, because they fail on different things:
one catches a renderer that starts drawing a new character, the other catches a generator that
stops carrying one.

## VI. What the guards caught, and what was mutated

Sixteen tests, and every assertion mutation-checked:

| mutation | result |
|---|---|
| `_adv` stops reading the measured widths | 2 red |
| `face_status()` always returns EMBEDDED | red |
| the licence is dropped from the `@font-face` CSS | red |
| the `@font-face` rule is dropped from the sheet's `<style>` | red |
| the FACE line is dropped from the margin schedule | red |
| the sidecar claims the whole 2,272-glyph font | 2 red |
| the charset is narrowed to capitals | red on the promise test, **green on the traffic test** (§V) |
| the upstream copyright contains `*/` | red — it would close the CSS comment early and take the `@font-face` with it |

Beside them: the payload's sha256 against its own sidecar, the OFL's first line against the
sidecar's copyright (so the licence beside the font is the licence *of* the font), the payload
being a WOFF, one `@font-face` per sheet rather than one per `<text>`, and a bounded byte cost so
a future full-font embed fails rather than ships.

## VIII. What was deliberately not done

- **The mark was not changed** — §I, and it is the open question.
- **The mono face is not carried** — §IV, and it is the third item of that question.
- **The three dark-register renderers are untouched** — §IV.
- **The workbench app's own face is unchanged.** `workbench/app/index.html` has loaded EB
  Garamond from Google Fonts by `<link>` since WP-5.2, so the browser's plate is set correctly —
  *when the reader's browser can reach fonts.googleapis.com*. After this package the exported
  SVG is more reliable than the application that produced it, which is worth knowing and is not
  fixed here: the app needs italics and three weights, and the sheet's subset is one upright.
- **`gen_sheet_font.py` is not in `check_all.py`.** Its `--check` needs the network, and a build
  step that fails on a firewall is a build step that teaches people to ignore it. The offline
  half — is the committed payload what its own sidecar says — is a test, and runs every time.
