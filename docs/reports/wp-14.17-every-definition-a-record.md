# WP-14.17: every definition a record

*25 September 2026. Branch `worktree-agent-a9103c3b3320fc972`, taken from `f0dc52a`. Scope:
`docs/prd/phase-14-tranche-2.md` §A whole, §0.3 default 2 and §G. Every figure below was measured
in this worktree, and every "before" figure on a clean `git archive f0dc52a` extraction (see §IV
for why "clean" is said twice). Cite this report by filename.*

## What it is for

Tranche one put every word the workbench shows into a glossary record, and left three kinds of
word outside the rule: the Glossary page's own family headings (the enum value, printed as it
was), the eight labels on a term's page, and the parts of a fault card. The ruling of 25 September
(`oq/a-glossary-family-has-no-name-of-its-own`, and the PRD's standing rule that a label the app
needs is a record) takes all three in. The same package gives every page its starter questions,
gives the schema a `mark` for WP-14.29 to use, and heads the front door's two lower sections.

## I. What was built

**The checker** (`build/check_glossary.py`).

- `PREFIXED_FAMILIES` gains the three new families.
- Rule 12 holds the starter questions: a page without them fails, and so does a list of more

- Rule 13 holds a mark to `workbench/app/src/theme/tokens.css`. It accepts a property that is

## II. What was found

**1. The fault card labelled the wrong field "how it lives".** The card's own opening note says
two severity axes, *how it reads* and *how it lives*, are two axes and not one badge. *How it
lives* is the schema's `severity_in_use`, whose description reads *"A stack with nowhere to land
is invisible in a photograph and fatal in occupation."* The label sat over `frequency` (endemic
through rare), which asks how OFTEN a fault occurs, a different question.
- This was invisible while the labels were typed strings, because nothing related a label to the
  field under it.
- It became visible the moment each label had to name a record and each record a field.
- `frequency` now takes its own word (*how often*). *How it lives* is drawn over
  `severity_in_use` wherever a fault states one.
- Re-derived over the corpus: **33 of 210** faults state one (15 minor, 15 serious, 2 fatal,
  1 not-applicable). The other 177 now show no fourth axis. They do not get *how it lives* over a
  frequency. `faultCard.test.mjs` pins the pairing.

**2. `not-applicable` is a value of `severity_in_use` and names no severity.** `fault.severity`'s
records bind fatal, serious and minor, and the fourth value of the in-use enum has no bound word.
- `judgment-not-applicable` was available and was NOT borrowed. That record is a check's verdict
  (the question does not arise), and handing it to a fault's in-use rating would be one word
  meaning two things, which is the OQ 48 error in a label.
- The value is printed as the record states it, as the card already prints `category` and
  `cause.driver`. One fault reaches this, `tempered-glass-at-the-entry`.

**3. The two copies of the bindable-field table had never been compared row for row.** They were
each held to the schema's KEYS, which is half of what they claim. The row-for-row test landed in
the same commit as the eighth row. Removing the row from either copy alone goes red (§III).

**4. The search index grows by 52 and the prose that states its size had to follow.**
- `workbench/server/corpus.py` indexes every glossary record outside `surface`, `section` and
  `nav-group`, so 52 of the 58 new records are searchable. The six new surfaces are the ones left
  out.
- The index goes **762 → 814 entries** and **241,518 → 258,029 bytes** served (glossary entries
  96 → 148). The instrument was first proved to reproduce the published 762 and ~242 KB on the
  base tree.
- `docs/workbench.md` (two figures and the size) and `workbench/README.md` are corrected here.
- `CLAUDE.md`'s *"762 named things"* is the lead's to write, so `check_counts.py` reports exactly
  that one line stale on this branch (§V).
- Whether a family heading, a field label or a fault-card part SHOULD be findable in the palette
  is a real question, and this package does not answer it. The corpus's rule
  (`GLOSSARY_FAMILIES_NOT_INDEXED`) is places against words, and these are words. The function
  sits in a file tranche two splits between three lanes, so it was not touched here. Named for
  the lead.

**5. Three comments stated the table's old size.** `build/check_glossary.py`'s rule 5,
`workbench/server/corpus.py`'s glossary header, and `workbench/server/tests/test_glossary_routes.py`'s
docstring and one assertion message all said "seven". The assertions derive their figure and
passed either way; the prose did not. All were corrected in this commit, on WP-6.4's rule.

## IV. What went wrong on the way, and was caught

- **The first control was contaminated.** It was a `git archive f0dc52a` extracted with `tar`
  into a scratch directory, and an extraction from earlier in the session had already been
  unpacked into that same directory. `tar -x` overlays, so the "base" carried a
  `surfaces/StyleRecord.jsx` that `f0dc52a` does not have.
  - The base app suite then read 513 of 515, red on two tests about that file.
  - This was noticed only because the red was inexplicable on a tree that should have been
    pristine.
  - Every control was re-run on a fresh extraction and all of them reproduced: 121 records,
    480 quotations, 0 stale counts, 41 tests, 762 entries at 241,518 bytes, 515 of 515.
  - The contaminated directory was deleted. **An extraction into a directory that already exists
    is not a control.**
- **The fault card's text reader first flagged its own object literal.** `LICENCE_FRAME`'s keys
  read as JSX text (`, refused:`), and the filter now drops a run opening with a comma. The
  fixture premise was extended to include that shape, so the filter is driven rather than assumed.
- **The first draft of the term-page guard would have convicted `FilterInput`'s accessible
  label.** It matched `label=` anywhere. It is scoped to `<Field label=` now, which is the one
  element that carried the typed labels.

## V. What was deliberately not done

- **`CLAUDE.md` is not edited**, by the lane rule. Two lines there are now stale because of this
  package, and each is the lead's to write at merge:
  - the open-question list names `oq/a-glossary-family-has-no-name-of-its-own`, which is
    CLOSED here, so `test_wp46_packs.py`'s derived-list test is red naming that one id and no
    other;
  - *"762 named things"* is now 814 on this tree, and that is a third value once 14.18 and
    14.19's records land beside these.
- **No record carries a `mark`.** The rule and its fixtures are built. The records and the
  `--mark-*` tokens are WP-14.29's (PRD §A.2 and §D), because a mark's basis quotes the
  stylesheet comments that package writes. "0 marks held" is the true count, and a later package
  will move it.
- **No `try` on the six new surfaces.** Their routes are WP-14.23's and WP-14.26's. A `try`
  citation to a page that does not yet route would fail the citation check, or worse, pass
  against a validator that knows the kind and not the page.
- **The search exclusion is unchanged** (§II.4).
- **`not-applicable` in use takes no word** (§II.2). A record binding it would need a field that
  binds `severity_in_use`, which is a ninth row and a ruling.
