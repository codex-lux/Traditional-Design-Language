# WP-14.26: one kit authority, and two styles at one address

*25 September 2026. Branch `worktree-agent-a8effb24d5fef64ac`, taken from `5aa8041`. The contract
is `docs/prd/phase-14-tranche-2.md` §B.1 (the `compare` route), §B.2 (`citeFor` returns null for
it), §C.7 (one kit authority), §0.2 ruling 1 (the freezes are lifted per item and named), §F (who
owns which file) and §G (what no package may do). Every figure below was measured in this
worktree. The "before" figures come from a `git archive` of `5aa8041`, extracted into a uniquely
named scratch directory. Cite this report by filename.*

**Verdict: the corpus serves one answer about a style's kit.** `core.resolve_kit` used to be a
hand-merge. It ran its own walk and its own `extends` merge, and it had its own rule for where the
walk stops. `tdl_resolve_kit` and `GET /api/kit` served that hand-merge, while every checker, the
elevation, the composer and the dossier's own slot count read `build/resolve_kit.resolve_slots`.
The two disagreed on **38 of 15,908 (style, slot) pairs** on the binding, the canonical set or the
forbidden set. Across the fifty-two rows both bound, they also disagreed on the rule text.
`resolve_kit` now reads the build's resolution through `core._resolved_kit` and keeps its row
shape. The disagreement is **0 of 15,908**, held by a test over every pair.

**The provenance strings stayed meaningful, so the PRD's fallback was not taken.** The build
already records which ancestor settled a slot, as `_source_chain`, base first. `_kit_source` spells
that chain in the form the Kit surface has always parsed (`"a"`, or `"a + b (extends)"`), so the
source column reads what the resolver actually walked. It is no longer the hand-merge's guess.

**On top of it: two styles at one address.** `#/compare/<a>/<b>[/<section>]` draws four sections
down one page: identify, kit, proportions and plans. `GET /api/compare/{a}/{b}` serves them, and the
kit section's rows are, by test, exactly the difference of the two `/api/kit` payloads. The family
tree's shift-click used to print a JSON panel. It now goes to that address, and so does a new
"compare with…" picker in the dossier head.

**And the slot tool's list is the resolved list.** `tdl_get_slot`'s `specified_by_styles` read each
style's own kit file. It listed 228 styles that forbid a slot as specifying it, and it missed 6,380
that specify a slot by inheriting it (WP-14.23's measurement). It now reads the same resolved
bindings the slot page reads, through one function in `core`.
`oq/the-slot-tool-lists-a-style-that-forbids-a-slot-as-specifying-it` is closed.

## I. What was built

**One kit authority (`mcp_server/core.py`).**

- `resolve_kit` reads `_resolved_kit(style_id)`, which is `rk.resolve_slots` over
  `rk.chain_for` and `rk.scope_for`: OQ 58's scoped edges, inline node kits and all. The row
  loop, the `only_specified` filter, the group and slot selectors and the payload's keys are
  unchanged.
- `_kit_source(rec)` spells the provenance from `_source_chain`.
- `provenance` no longer counts a slot nothing in the cascade binds. Such a slot has no source,
  and the hand-merge had credited it to whichever kit file happened to carry an `open` record.
- The hand-merge is deleted, not kept beside the new path. A second resolver that nothing calls
  would be the next one to drift.

**The slot tool (`mcp_server/core.py`).**

- `_slot_binding` and `_resolved_bindings` moved here from `workbench/server/corpus.py`, where
  WP-14.23 wrote them for the slot page.
- `get_slot` reads `_resolved_bindings()[slot]["specified"]`, and its `note` says it reads the
  kit after the cascade.
- `corpus._resolved_bindings` is now a one-line delegate, so the tool and the page read one
  function.

**The route (`workbench/server/corpus.py`, `app.py`).**

- `corpus.compare_kits(a, b)`, served at `GET /api/compare/{a}/{b}`, returns
  `{a, b, identify, kit, proportions, plans}`:
  - `identify` is `core.compare_styles(a, b)`.
  - `kit` holds one row per ontology slot where the two resolved kits differ on `binding`,
    `canonical`, `forbidden` or `source`. Each row names its fields in `differs_on`. Variant
    lists are compared as sets. The payload also carries `slots_compared`, `differ_in_answer`
    and `differ_in_source_only`.
  - `proportions` is `style_packs` for each style.
  - `plans` is `dossier_plan_types(x)["partis"]` for each style: `core.list_partis`'s nativity,
    exactly as the dossier's Plan types section reads it.
- An unknown style is a **404 naming it** (`detail.missing`).
- The route is registered before `/api/styles/{style_id}`.
- Measured on `craftsman` against `tidewater-georgian`: **91 kit rows, 73 differing in the answer
  and 18 in the source alone**. The response is about 61.5 KB.

**The address (`router.js`, `citations.js`, `nav/`).**

- `SURFACE_PATHS.compare = { path: 'compare', keys: ['style', 'compare', 'section'] }`.
- `'compare'` is appended to the end of `SELECTION_KEYS`.
- `citeFor` returns null for it, because the grammar has no two-style kind. No regex changed.
- `navModel`'s `UNDER` puts compare under the Styles item, and the Styles item is current there.
- `crumbs.js` reads Styles › `<a>` › compare with `<b>`. The last crumb is worded by the
  `compare-with` record and cites `style:<b>`.
- `App.jsx` `SURFACES` gains `compare: Compare`.
- `glossary/surface-compare.json` gains `try: style:tidewater-georgian`.

**The page.**

- `surfaces/Compare.jsx` draws the page. `compare/view.js` holds its decisions as pure functions:
  the sections, the section to scroll to, the section's address, the answer/source split, and
  who authored a disambiguation.
- **Its four sections are dossier sections.** `view.js` asserts at load that each is in
  `DOSSIER_SECTIONS`, so each is worded by the same `section-*` record the dossier uses.
- The kit section draws only the differing slots. The rows are split into those where the two
  give a different answer and those where they give the same answer from different sources (the
  latter under the new `kit-same-answer` record's word).
- Proportions reuses the dossier's own pack lists: `PackLists` is exported from
  `dossier/ProportionsSection.jsx`, which draws through it too.
- Plans reuses `NATIVITY_TERMS`.

**The two ways in.**

- The dossier head carries a "compare with…" `StylePicker`. It is worded by the new `compare-with`
  record and goes to `#/compare/<this>/<other>`.
- The Phylogeny's shift-click calls `nav.go('compare', …)`. Its local `compare` and `cmpData`
  state, its fetch effect, its highlight and its `JSON.stringify` panel are removed. The hunks are
  confined to the compare feature, because WP-14.27 edits the file's other hunks in parallel.

**Three glossary records, 204 → 207.** Each is editorial, with a basis quoted verbatim and checked
by `check_glossary.py`:

- `compare-with` (family product) quotes `schema/style-node.schema.json`.
- `shared-ancestry` (model) quotes `docs/inheritance.md` and `core.compare_styles`'s own
  `shared = set(_cascade(a)) & set(_cascade(b))`.
- `kit-same-answer` (model), the term "same answer, another source", quotes
  `build/resolve_kit.py`'s *"The SOURCE column is the point."*

## II. What was found

**The 38 pairs split into three causes, and one of them is a data defect that the hand-merge made
visible.** All 38 are in `tests/fixtures/kit_authority_moved_pairs.json`, with what the hand-merge
answered and what the resolver answers:

| cause | pairs | what the hand-merge did |
|---|---|---|
| `open-stops` | 33 | stopped at an `open` record carrying a status and served it, naming the node that wrote `open` as the source; `resolve_slots` treats `open` as transparent (OQ 87) and walks on |
| `scope` | 4 | reached an ancestor through an OQ 58 scoped edge that does not carry the slot, because it ignored `_cascade_scope` |
| `replace-on-a-duplicate-id` | 1 | see below |

The 33 open-stops fall on four slots: `pediment` 18, `landscape_idiom` 9, `composition_parti` 4
and `setback_rule` 2. 32 of the 33 go from `open` to `specified`. The 33rd,
`mediterranean-vernacular.composition_parti`, stays `open` and loses a forbidden list that the
hand-merge had been serving from its own `open` record. The scope cases are
`monterey-colonial.hearth_position`, `monterey-colonial.window_surround_wood` (now a dangling
`extends`, which the build reads as specified), and `octagon-house.primary_cladding` and
`.roof_form`. Each is served from the ancestor the scoped edge actually reaches.

**The duplicate variant id.** `kits/georgian-colonial-american.kit.json` lists
`none-masonry-reveal` TWICE in `window_surround_wood`: once permitted and once as a conditional
canonical. `new-england-georgian` `extends` that slot with an `op: replace` on the id, to forbid it
(*"There is no masonry reveal on a clapboard or rusticated-board wall."*). The hand-merge replaced
the FIRST copy and `rk.apply_variant_ops` replaces the LAST.

**Neither reading is right.** The hand-merge served the variant as canonical AND forbidden at
once. The resolver now serves it as **permitted and forbidden at once**, because the permitted copy
survives the replace. That is the same contradiction, one status down. The movement is real (it is
why the pair is in the fixture), but it is not a repair. The defect is the duplicate, and no reader
can resolve an `op` addressed to an id the base holds twice.

**The duplicate itself is not removed.** Which of the two records the corpus means is an authoring
question, and today the answer is decided by the order the file lists them in. `check_kits.py` does
not refuse a duplicate variant id within one slot. That is recorded here and nowhere else yet; it
is a candidate for the lead to file.

**Fifty-two more rows moved only their `rule` text, and every one is the resolver being right.**

- 30 are `rule_append` joined with `" "` by `merge_extends` where the hand-merge joined with
  `". "`. The words are the same.
- 16 are an `extends` delta that restates the slot's `rule`. The hand-merge merged parameters,
  variants and five named fields and never `rule`, so it served the ANCESTOR's sentence under the
  child's provenance.
- 6 are the scope cases above.

**The "before" column can only come from the control, because on this tree the comparison is
empty by construction.** The planning figure of 38 came from comparing `resolve_kit` against
`_resolved_kit` on one tree. After the rebase `resolve_kit` IS `_resolved_kit`, so that same
comparison run here would report 0 whether the rebase was right or wrong: an instrument that
cannot fail. So the moved-pairs file was built differently. Every
`resolve_kit(style, slot=slot, only_specified=False)` was dumped on the `git archive` of `5aa8041`
and on this tree, and the two dumps were diffed. The 38 it found are the planning figure,
re-derived rather than quoted. The fixture's `hand_merge` column is a record of what was served.
No test re-derives that column, because the code that produced it is deleted. What the tests hold
instead is that the served answer is now the build's (`resolve_slots`, read independently by
`tests/test_one_kit_authority.py`), and that no moved pair still answers what the record says the
hand-merge answered.

**The slot tool, measured from the other side.** Over the 97 slots, `specified_by_styles` now lists
**0** styles whose resolved kit does not specify the slot, and misses **0** that it does.
`tests/test_one_kit_authority.py` asserts both, and it asserts the two premises that give those
zeros meaning: that styles whose OWN file binds a slot `forbidden` exist, and that styles exist
which specify a slot their own file leaves unbound or `empty`. Without the premises, a corpus with
neither would pass vacuously.

**`get_slot` is now about two seconds on its first call** (it resolves every kit), and then cheap,
because `_resolved_kit` caches each kit. It was a single walk over the kit files. The slot page
has paid the same since WP-14.23.

## III. The frozen surfaces this package lifted, by name

Ruling 1 lifts tranche 1's freezes per item. This item needed exactly three surfaces:

1. **`tdl_resolve_kit`** (the MCP tool).
2. **`GET /api/kit/{style_id}`**, which serves the same function. Every style was dumped in both
   `only_specified` modes, and in slot mode for every slot, on the control and on the final tree,
   and the two dumps were diffed field by field.
   - **Default mode (`only_specified=True`).** It gains 32 rows, the open-stops that now resolve
     `specified`, so `slots_returned` moves on 24 styles. Row fields move as follows:
     - `rule` on 52 rows;
     - `source` on 7;
     - `canonical`, `forbidden` and the parameter count on 4 each;
     - `binding` on 1 (the dangling `extends` above).

     `provenance` moves on 89 styles, because a slot nothing binds is no longer credited to a
     writer.
   - **`only_specified=False`.** It returns a row for EVERY ontology slot, so 6,324 rows are
     added and `slots_returned` is 97 on every style (it moved on 101). The moves split by whether
     a row is open on both sides:
     - `binding` moves on 33 rows and `canonical` on 25, all of them bound rows.
     - `forbidden` moves on 26: 25 bound rows and one open-on-both row, the
       `mediterranean-vernacular` case.
     - `rule` moves on 87: 84 bound rows and 3 open-on-both rows.
     - `source` moves on 229: 39 bound rows and 190 open-on-both rows. For those 190 it goes to
       null.
     - `judgment` moves on 134. Of these, **129 are open-on-both rows going from `true` to
       `false`**, taken up in the next paragraph. The other 5 are bound rows.
   - **Slot mode.** The same moves appear, plus `parameters` reading `null` rather than `{}` on
     112 open rows, because the resolved record of a slot nothing binds carries no parameter
     block. `KitSurface.jsx` and `SlotRow.jsx` already guard a null.

   **The 129 are a cost, and it is OQ 87's own mechanism arriving in this payload.** The
   hand-merge served 222 rows from `open` records carrying a status, crediting the node that wrote
   `open`. 129 of those records carry `judgment: true`, for example
   `georgian-colonial-american.porch_ceiling`: the author left the slot open, and marked leaving
   it open as a decision. `resolve_slots` treats `open` as transparent, so for a slot nothing
   settles, the resolved record is not that `open` record, and the served row's `judgment` is
   `false`. The flag is still in every kit file. What moved is that `/api/kit` no longer delivers
   a flag the resolver does not read. **Not restored.** Serving it would mean reading the nearest
   `open` record ON TOP of the resolution, which is a second kit reader, and a second kit reader
   is what this package removes. Whether an authored `open` should stop the walk is OQ 87's
   question, and that question stays open.
3. **`tdl_get_slot`**: `specified_by_styles` and `note` moved on all 97 slots. The payload's keys
   did not move, and a test holds them.

**No other MCP payload moved, and that was proved rather than assumed.** 32 representative calls
cover all 25 of the other tools. Each is hashed as canonical JSON, and `tdl_revise_plan` has its
wall-clock `seconds` stripped. They were run on the `git archive` of `5aa8041` and on this tree.
Two control runs agree with each other, and this tree agrees with both: **0 of 32 differ.** (The
first two control runs disagreed on `tdl_revise_plan` alone, on its clock. The instrument was
corrected and re-run, and the new value was not believed until two control runs agreed with each
other.)

**The pins.**

- `tests/test_one_kit_authority.py` (7 tests). Every row of every style equals the build's
  resolution on the binding, canonical, forbidden and rule, with the source chain parsed back.
  Every open slot has no source. The fixture is a record of movement. No moved pair answers what
  the hand-merge answered, and the moved pairs are served as the build resolves them. `get_slot`
  lists exactly the resolved specifiers and no forbidding style. `get_slot`'s keys did not move.
- `workbench/server/tests/test_record_pages.py`. Its premise used to be "the MCP tool still
  disagrees", which this package made false. It is re-cut to "the tool's list IS the resolved
  list, its keys did not move, and the page, the tool and `bindings.specified` are one list",
  with the inherited-specifier premise asserted.
- `workbench/server/tests/test_compare_route.py` (4 tests). The kit rows equal an independent
  difference of the two `/api/kit?only_specified=false` payloads, over every moved style against
  `craftsman` and the walk's own pair, with a non-vacuity check that some row falls on a moved
  slot. `identify`, `proportions` and `plans` equal the routes they are read from. An unknown
  style is a 404 naming it. A style beside itself gives no rows.

**The mutation that decides the compare guard had to be written, because the tree no longer holds
a second resolver.** After the rebase, restoring the hand-merge inside `resolve_kit` (M1) moves
`/api/kit` and `/api/compare` together. `test_compare_route.py` rightly stays green under M1,
because what it asserts is that compare IS the difference of two `/api/kit` payloads, whatever
those say. The mutation that tests that assertion is the one where compare and `/api/kit` read
different resolvers, so M3 pastes the deleted hand-merge back in as a second reader.

**M6's guard is a source guard, and the walk is the behavioural one.** `compare.test.mjs` reads
`Phylogeny.jsx` for the `nav.go('compare', …)` call and for the absence of the panel's state. The
walk actually shift-clicks a row and reads the resulting address. That walk check was not
mutation-run: one run of the walk costs about a quarter of an hour, and it was run once, green,
on the final tree.

## V. What was deliberately not done

- **The duplicate `none-masonry-reveal` in `georgian-colonial-american.window_surround_wood` is
  not edited.** Which record the corpus means is an authoring question, and the resolver answering
  by list order is recorded above rather than settled by deleting one.

  statuses. That is the same shape of reader this package removed from `get_slot`, but it is a
  different payload (`tdl_get_slot` does not serve it). Changing it would lift a surface this item
  does not need.
- **MapView's `compare` parameter is left in place.** `Phylogeny.jsx` no longer passes it, so it is
  dead in `MapView.jsx`, but that file is outside this package's hunks while WP-14.27 edits the
  Phylogeny.

  says to append to `client.js` and not to edit existing functions.
- **The compare page carries no `citeFor`.** The grammar has no two-style citation. A reader
  citing a comparison cites the two styles.
