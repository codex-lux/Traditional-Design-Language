# WP-14.19: a brief may name a parti

*25 September 2026. Phase 14, tranche 2, wave 1. The contract is
`docs/prd/phase-14-tranche-2.md` §C.5, §A.2 (four glossary records), §0.3 default 4 and §G. Cite
this report by filename: Phase 14's numbers are this line's, and a number does not disambiguate a
package in this repository.*

## What it is for

The Style Dossier lists a style's plan types, and a reader who has just read one could not ask
for it. `schema/brief.schema.json` admitted no `parti`, and the composer chose every diagram
itself. Lucas ruled on 25 Sep 2026 (`oq/a-brief-cannot-name-a-parti`, answer 1):

- a brief may name a parti, and the composer guarantees it a place among the contrasting
  candidates;
- a parti not native to the style is borrowed, and says so;
- the tranche-1 freeze on the `tdl_brief_schema`, `tdl_compose` and `tdl_list_partis` MCP payloads
  is lifted for this item alone, and every other frozen surface stays byte-stable.

This package is the server half. The control that starts a brief from a plan type belongs to the
packages that own Brief Intake and the Plan types section.

**The guarantee is a place, not a rank.** The named parti is scored by the same arithmetic as every
other diagram and sorted by the same key. If the composer's own ranking returns it, it stands
where that ranking put it. If not, it is appended after the set as one more candidate and
displaces nothing. The composer's own set is therefore the set it would have returned with no name
in the brief, in the same order and with the same verdicts. That is what keeps *"a plan carrying a
fatal never displaces a clean one"* true with a name in the brief, and a test holds it.

## I. What was built

- **`schema/brief.schema.json` 0.1.0 → 0.2.0.** An optional `parti` with the id pattern
  `^[a-z0-9]+(-[a-z0-9]+)*$` and a description stating the guarantee, the borrowing and the
  refusal. Both shipped briefs validate under it unchanged; neither names a parti.
- **`compose.nativity(parti, style)`** returns `native`, `lineage` or `borrowed`. It is the one
  spelling of that relation, and its docstring carries the three definitions the glossary quotes.
  `native` means the style is in the parti's `styles`. `lineage` means the parti's `styles` meets
  `plan_check.style_chain(style)`, which is the style, its containers and its `inherits_kit`
  ancestors. `borrowed` means neither. An id nobody holds raises `KeyError`, because a relation to a
  diagram that does not exist is not "borrowed". `pick_partis` and `core.list_partis` both read
  it. Before this package they answered the question two ways: the composer borrowed a diagram and
  said so, while the list filtered on `p["styles"]` and showed nothing for a style with no native
  parti.
- **`compose.check_brief_refs(brief)`** returns `None`, or one sentence refusing the brief. It
  refuses an unknown parti, naming it and listing the catalogue. It also refuses a parti the
  brief's own `massing` contradicts, naming both and the massings the parti is built on. That
  refusal reads `compose._massing_admits`, the predicate `pick_partis`' massing filter now reads
  too, so the filter and the refusal cannot disagree about what a contradiction is.
  `BRIEF_REF_ERROR` and `BRIEF_REF_HINT` are spelled once, in `compose.py`, and read by both
  callers. It is called in four places:
  - `core.compose`, after the schema check, returning `{error, detail, hint}`;
  - `workbench/server/jobs.py::_validate_brief`, before a job exists, so `jobs.submit` and the
    route refuse alike and no job is left behind;
  - `compose.main`, which exits naming the refusal;
  - `compose()` itself, which raises `ValueError` for a direct caller. A named parti the massing
    filter drops would otherwise vanish in silence (§0.3 default 4).
- **The guarantee.**
  - `pick_partis` keeps the named row past the cut at its own fit. Being named adds no points. The
    old tie-cut is lifted into `_cut()` unchanged, so the keep runs after it.
  - `compose.considered(brief, candidates)` is the one list `compose()` works through, exposed so
    the job stream can count it.
  - After `_sort_key` and the revision loop, a named parti not among `out[:candidates]` is appended
    as candidate N+1.
- **The result** gains
  `named_parti: {parti, nativity, returned, appended, rank}`, or `{…, returned: false, why}`, and
  `null` when the brief names none. Every candidate gains `named_by_brief` and `nativity`. The named
  row's `why_this_diagram` opens with *"named by the brief, which guarantees it a place among the
  candidates"*. A borrowed named row reads *"NOT native to this style — the brief named this
  diagram, so the composer is borrowing it"*, in the same clause shape
  `candidateOrder.js::whyText` already strips. `how_to_read_this` gains one line saying which of
  three things happened: returned by the ranking, appended, or not among the candidates and why.
  It adds *"It is borrowed"* where the parti is borrowed.
- **Readers.**
  - `core.list_partis(style, massing, include_borrowed=False)` lists native and lineage partis,
    each carrying `nativity`. Borrowed partis are listed only on request. Without a style no row
    carries `nativity`, because there is no relation to state.
  - `core.get_parti(id)` wraps `core.load_parti` and returns
    `{parti, nativity_by_style: {native: [...], lineage: [...]}}`. It refuses an id whose file names
    a different record, so `x/centre-passage-double-pile` is not a second address for the parti
    (`load_parti` basenames its argument).
  - `GET /api/partis/{parti_id}` sits after `/api/partis`, and an unknown id is a 404 naming it.
    `/api/partis` takes `include_borrowed`.
  - `corpus.dossier_plan_types` passes `nativity` through on every parti row.
  - The `tdl_list_partis`, `tdl_brief_schema` and `tdl_compose` docstrings say all of this.
    `tdl_list_partis` lost its hand-typed catalogue count, which the docstring itself had recorded
    as wrong once.
- **The job stream.** Every `stage` event carries `total`, the length of `compose.considered`.
  A diagram the lot drops is now reported through `on_candidate` as
  `{parti, parti_name, why, dropped_lot: true, named_by_brief}`. The job turns it into a `stage`
  event, `{stage: "dropped", parti, note, named_by_brief, considered, total}`, which carries no `n`,
  so nothing counts it among the scored. Candidate events gain `named_by_brief`, `considered` and
  `total`. Every diagram considered is heard from exactly once before the revision loop, and
  `considered` counts 1 to N.
- **Four glossary records**, family `house`, `kind: editorial`, each basis quoting
  `build/compose.py` in 25 characters or more: `parti-native`, `parti-lineage`,
  `parti-borrowed` and `named-by-the-brief`. The glossary schema and checker are untouched.
  `check_glossary.py` reads 125 records and 490 quotations, and its basis check was driven red on a
  scratch copy with one changed letter before it was believed.
- **The question is closed**: `oq/a-brief-cannot-name-a-parti`, on answer 1, with a dated
  amendment. A new question is filed beside it (§IV).

## II. The MCP payloads whose freeze was lifted, and everything else that moved

Lucas lifted the freeze on three payloads for this item alone. Each change is named here.

- **`tdl_brief_schema`.** The schema is at version 0.2.0 and carries the `parti` property. The
  `hint` gains one sentence about `parti`. The example briefs are unchanged.
- **`tdl_compose`.**
  - A brief naming an unknown parti, or one its massing contradicts, is refused as
    `{error: BRIEF_REF_ERROR, detail, hint}` before anything is bounded or composed.
  - The result gains `named_parti`, which is `null` when the brief names none. Every candidate
    gains `named_by_brief` and `nativity`.
  - `candidates` may hold one more entry than was asked for, and only when a brief names a parti
    the ranking did not return.
  - `how_to_read_this` gains one line when a parti is named.
- **`tdl_list_partis`.** It takes `include_borrowed`. Given a style, every row carries `nativity`
  and lineage partis are listed beside native ones. The `note` gains two sentences.

**Surfaces outside the three MCP payloads that moved, all inside this item's own routes.**
- **`/api/partis`** follows `tdl_list_partis`.
- **`GET /api/partis/{id}`** is new.
- **The dossier's plan-type rows** carry `nativity` and list lineage partis (§III).
- **The compose job stream** gains `total`, a `dropped` stage and three candidate-event fields.
- **`compose()`'s `on_candidate` callback** now also fires for a diagram the lot drops. That is a
  change in the callback's contract. `tests/test_workbench_touches.py::test_compose_on_candidate_callback`
  filtered on `dropped_lot` rather than being loosened, and it now also asserts that no summary
  carries the plan, before the filter.

**Byte-stable where no parti is named.** A brief with no `parti` takes every old path. `pick_partis`
returns the same rows, plus two keys per row. `compose()` returns the same candidates in the same
order. `check_partis.py`'s output is byte-identical to a `git archive` of `f0dc52a`, red on
`side-hall-townhouse` as before. The revision loop's body was lifted into `_revise_one` and
`_skip_revision` unchanged, so the appended candidate could be revised by the same code.

**`COMPOSE_MAX_CANDIDATES` is respected by construction.** `out` holds at most one row per parti,
so the append never duplicates a diagram, and `returned` can never exceed the catalogue's size.
That is below the 24 cap: at 24 candidates, `out[:24]` already holds every composed diagram, so
nothing is appended. **Nothing reads `len(candidates) == requested` as a rule.** Swept:
- `tests/test_solver.py:477` and `tests/test_composer.py:94` assert four on the shipped briefs,
  which name no parti;
- `journey.js:134` prints `result.candidates.length`, which is the truthful count either way.

## IV. What was found

**`oq/a-brief-can-name-a-massing-no-parti-is-built-on`.** Building the refusal found the
neighbour it does not cover. Five of the catalogue's 40 massings are in no parti's `massing` or
`alternate_massings`: `mansard-block`, `prairie-cruciform`, `pyramidal-cottage`, `telescope-house`
and `temple-front-with-wings`. 34 style nodes name one of them in their affinities, 6 as
canonical. A brief naming one of these massings passes the schema, `check_brief_refs` and
`_validate_brief`, and composes `candidates: []` with no sentence saying why. So does an unknown
massing string, which the schema does not enumerate. **Not fixed**, because refusing a massing
changes what `tdl_compose` accepts beyond the one field this package's freeze was lifted for, and
the three available answers are a ruling. The question names all three.

**The parti-confinement guard convicted the new route, and it was narrowed, not weakened.**
`workbench/server/tests/test_parti_confinement.py` hunts for an id-to-path join outside
`core.load_parti`. Its `/partis/\{` spelling matched the route decorator
`@app.get("/api/partis/{parti_id}")` and every docstring naming the route, so the suite went red
on a URL template. Its first design point is kept: an f-string join such as `{ROOT}/partis/{x}`
must still match. The pattern is now a module-level `PARTI_JOIN` with the lookbehind
`(?<!/api)`, which excludes exactly `/api/partis/{`. The repository has no `api/` directory beside
`partis/`, so no filesystem join can hide behind it. A new
`test_the_join_pattern_tells_a_route_from_a_path` holds both halves: four join spellings must
match, and the route and a docstring must not. This file is outside the item's listed scope, and
it is named here for that reason.

## V. Guards, and the mutations that proved them

The composer's half is in `tests/test_composer.py`, in four new classes. The fixture brief is
`family-georgian` narrowed to its own canonical massing, `four-over-four`, which admits three
partis, so a compose at one candidate takes seconds. Every premise is asserted rather than
assumed: which diagram falls below the cut is a property of the tree. The server's half is
`workbench/server/tests/test_named_parti.py`. No new test asserts a count of partis or styles. The
one corpus-size floor a first draft carried (`len(styles) > 100`) was replaced by the premise that
both readers see the same style set.

**The fixture turned out to be the use case.** At one candidate the narrowed brief returns
`five-part-palladian`. The diagram below the cut is `centre-passage-double-pile`, native to the
style and on its canonical massing, at fit 7.0. It is the diagram
`oq/the-composer-returns-a-set-that-satisfies-neither-must-have-room` records the composer as
computing and no longer returning. Named, it comes back as candidate 2, and the composer's own
candidate 1 is untouched.

for byte; the working-tree diff hashed the same before and after each pass. All sixteen went red,

- **The harness's first pass stopped at M8.** Its landed-assertion required the old text to be

- **M3 went red for a wrong reason on its first run.** It reported *"the cut itself moved"*,

- **M5's premise was read off the stream under test.** Its first form asserted that a `dropped`

**Two existing tests were re-cut, not loosened.**

## VII. Not done

- **The brief-side control.** The *"start a brief from this parti"* bridge, `#/brief?parti=<id>`
  (PRD §C.5 and the URL table), belongs to the packages that own Brief Intake and the Plan types
  section.
- **The app readers in §III.** They must read `nativity`, and they are other packages' files.
- **`oq/a-brief-can-name-a-massing-no-parti-is-built-on`**, for the reason given in §IV.
- **The appended candidate's revision.** It is revised after the set, on whatever the set's
  revise budget left. Where the budget is spent, it is marked `revision_skipped` with a sentence
  saying it was appended after the candidates the composer chose. Revising it first would have
  taken budget from the composer's own set, and the ruling is that a name displaces nothing.
