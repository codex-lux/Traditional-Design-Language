# WP-14.22: the assistant sees the page

*25 September 2026. Lane branch `worktree-agent-a3b9e4d5611650ab8`, taken from the lead tip
`c8ed0c1` (wave 1 merged: 14.20, 14.17, 14.18, 14.19, 14.21). Scope: the tranche-2 plan's row
14.22 and `docs/prd/phase-14-tranche-2.md` §C.8. The assistant is told the page's citation and
fetches the record itself, the pane offers the page's own starter questions, and the prompt's
stale facts are corrected in the same commit. Every figure below was measured in this worktree.
Cite this report by filename.*

**Status: built and verified on the lane branch, not pushed.** It closes
`oq/the-assistant-is-blind-to-the-page` on answers 1 and 3 in the citation form, as ruled on 25
September. It raises `oq/no-tool-answers-which-styles-use-a-pack`.

**The ruling lifted three tranche-1 freezes for this item alone, and all three moved.** The item
changes `workbench/server/rail.py`'s prompt, the context `/api/rail/messages` accepts, and the MCP
tool DESCRIPTIONS. §III lists every change to those surfaces and how each pin was re-cut. Every
other frozen surface is byte-stable. That covers the MCP tool payloads (`mcp_server/core.py` is
not in the diff), `core.overview()` (the prompt still appends it unchanged), `/api/health`, and
`App.jsx`, which this package does not touch.

## I. What was built

**1. The page's citation reaches the model, and only a citation the validator accepts.**
`workbench/app/src/rail/railContext.js` is new and pure. It builds the context the pane sends:
- `cite`: the page's own `citeFor(surface, selection, params)` from `citations.js`, which is the
  inverse of `routeCite`. The key is absent where the page names no record.
- The four keys it sent before (`surface`, `plan`, the three-key cut of `last_eval`,
  `candidate_count`), built exactly as before. A test holds them to the old construction.

`RailHost.jsx` reads the place from the nav store (`useSyncExternalStore(nav.subscribe, nav.get)`)
rather than taking it as a prop, so `App.jsx`, which belongs to another lane, is unchanged.

`rail._context_block` writes one line for the cite, and only when `citations.validate(ref, ctx)`
accepts it:
> *The page the user is looking at shows the record {ref}. When a question is about what is on the
> page, fetch that record with the tools before answering, and do not assume its contents.*

A cite the validator refuses is omitted and never echoed. The refused cases tested are:
- `pack:nope`;
- a kind that does not exist;
- a real ref followed by a newline and instructions;
- a real ref followed by `]]<refusal>`;
- a dossier section that does not exist;
- the empty string, a number and a dict.

The model fetches the record itself with the 27 tools it already has, as ruled. Nothing of the
record is inlined.

**2. The candidate set reaches the prompt in whole rows.** `context.candidate_summaries` is one
compact row per candidate. Each row carries the `candidate` index a `candidate:<index>` citation
names, and `parti`, `name`, `nativity`, `score`, the `fatal`/`serious`/`minor` counts,
`disqualified` and `refused` (its kind and facts, read through `sheet/refusal.js::readRefusal`).
Each key is written only where the candidate states it.
- The client stops at a 3,000-character budget. The server applies its own 4,000
  (`rail.CANDIDATE_BUDGET_CHARS`).
- Both take WHOLE rows and never cut one. The server serialises with the same compact separators
  the client's `JSON.stringify` uses, so the two budgets count the same characters.
- Where the set holds more candidates than reach the prompt, the block's last line says how many
  were cut at the budget.
- A test reads the client's constant out of the JS and holds it within the server's.

**3. The prompt is built on each turn, from records and counts.** `rail.SYSTEM` is replaced by
`rail.system_prompt(tool_count)`.
- **Self-description.** It is `glossary/assistant.json`'s `term` and `definition`, quoted. Nothing
  of its `aka` is read, and the `aka` keeps "the rail" as history.
- **Readers.** They are the three `who`/`line` pairs of `glossary/about-tdl.json`. The prompt used
  to name one of them, *"a plan-development lead at a production builder"*, as *the* user. It now
  lists all three and tells the model not to assume which one it is talking to.
- **Fault figure.** It is counted off `faults/`: **210** causes, one with `driver: ignorance`.
  The old prompt typed **209**.
- **Tool count.** It is `len(tools.tool_definitions())`, the list the turn hands the model.
  `stream_turn` passes that length, so the prompt and the tool list cannot disagree.
- **Citation kinds.** They come from `citations.KINDS` (next item).
- **Missing records.** Where a glossary record is missing, the prompt says `no entry: <id>` in its
  place rather than inventing a description.

**4. `citations.KINDS` is one vocabulary, and the validator reads it too.** It is a sixteen-name
tuple, not a regex, so it is not a fourth spelling of the grammar that `REF_RE`, `CITE_RE` and
`parseCite` hold. `validate()` now refuses any kind not in it, where it used to fall through an
if-chain to a final unknown-kind return. A test reads `routeCite`'s `case` labels out of
`citations.js` and holds `KINDS` to them. The prompt names every kind the validator accepts and no
other.

**5. Starter questions.** `workbench/app/src/rail/starters.js` is new and pure. It returns the
`ask` list of the page's `surface-<id>` glossary record, verbatim, and returns nothing:
- while the glossary loads;
- where the glossary failed;
- where the page has no record, or the record has no questions.

`AiRail.jsx` draws the questions as buttons (`data-rail-starter`). A click fills the input and
focuses it, and **sends nothing**, because a starter is an offer and the reader decides. The
questions are not sent to the model: it is told the page, not the prompts the page suggests.

**6. The stale prose that the freeze preserved is corrected.**
- **`limits.py`:** the five refusals the limiter shows a reader say "the assistant" where they
  said "the rail". The substrings existing tests read are preserved.
- **`rail.py`:** the key-missing error now reads *"the AI assistant is off"*.
- **`tools.py`:** the docstring typed *"The 26 rail tools"* against a registry of 27. It says
  where the count is computed now and types none.
- **`mcp_server/server.py` DESCRIPTIONS only:**
  - `tdl_find_faults`: *"Search 209 named errors"* is now *"Search the corpus's named errors"*.
  - `tdl_check_plan`: *"the 209-fault corpus"* is now *"the whole fault corpus"*.
  - `tdl_get_massing`: *"40 types"* is dropped.
  - The module docstring: *"The same 27 tools"* is now *"The same tools"*.

**7. The walk checks the starters on a page.** `e2e/walk.mjs` gains one block and three checks:
- On `#/proportions` the starters equal `/api/glossary/surface-proportions`'s `ask`, verbatim.
- Clicking one fills the input, focused, with **zero** requests to `/api/rail/messages`.
- On `#/faults` the starters change to that page's own questions.

The block saves a screenshot as `assistant-starters.png`.

## II. What was found

**1. The server read a key no client sent, and the way it read it would have cut an object in
half.** The old `_context_block` appended `json.dumps(candidate_summaries)[:4000]`. No file in
`workbench/app/src` produced that key, so the branch had never run. If it had, it would have cut
the JSON mid-row and handed the model a truncated object with no word that anything was missing.
The OQ found the absence. The truncation came to light when the key was wired and the block was
read to see what it would do with it. It takes whole rows now and says how many it left out.

**2. The prompt named thirteen citation kinds, and the validator accepts sixteen.** The old list
was *style, slot, kit, fault, room, grouping, massing, parti, pack, candidate, finding, plan,
constraint*. It had no `term`, which tranche 1 added for the glossary, and no `brief` or `asset`.
So the model was told it could not cite a glossary record, which is exactly the kind a
`#/glossary/...` page would now send. The kinds lived in two places: the prompt's prose, and
`validate()`'s if-chain, whose accepted set is visible only by reading every branch. Both read
`citations.KINDS` now.

**3. The surface line echoed the caller's string raw.** This was not named by the ruling and was
fixed on the ruling's own grounds. `_context_block` wrote *"The user is looking at the {surface}
surface"* with whatever `surface` the POST carried. That is the injection shape the cite line
exists to refuse, one line above it. The surface line is now written only for a lowercase id of
at most forty characters (`_SURFACE_RE`), and otherwise omitted. A pattern too tight would fail
in the other direction: it would drop the line on a real page, and that reads exactly like a page
the model was never told about. A second guard therefore reads every id in the router's own
`SURFACE_PATHS` and requires each to be named. It is mutation-checked (M15).

**4. A registry pin typed the count the prompt must now compute.**
`test_rail_loop.py::test_tool_registry_is_the_mcp_servers` asserted `len(defs) == 27`. That
literal would have kept the old defect alive in a test. It is re-cut against the source of truth:
the `@mcp.tool()` functions in `mcp_server/server.py`, read through the AST. It asserts equal
COUNTS and equal NAME SETS, so a renamed tool fails it as well as a missing one.

**5. `tools.py` typed 26 against 27 and nothing noticed.** It was a docstring, so no test or
checker reads it. `check_counts.py` reads Markdown and never opens `build/` or `workbench/`. That
is `docs/reports/wp-8.14-the-number-nobody-policed.md`'s *name the surface the checker does not
read*, met in the file that builds the model's tool list. The fix types no number.

**6. The prompt costs 1,152 more characters a turn, and the corpus's own words are the cost.**
The old `SYSTEM` was **2,932** characters and the new `system_prompt(27)` is **4,084**. The
`core.overview()` suffix is unchanged at **9,322**.
- The old opening paragraph was **459** characters. It carried the self-description, one reader
  and the fault clause.
- The new head is **717** characters: the assistant record's definition and about-tdl's
  definition of the product.
- The new reader block is **701** characters: three `who`/`line` pairs.
- The other 192 characters are in the rules. The style and fault sentences moved there from the
  opening paragraph, a sentence stating the tool count joined them, and the kind list gained
  three names.

All of it is the glossary's own words, which the ruling asked for, and no clause was cut to save
tokens.

**A sentence of the old prompt left with the reader line, and it said something.** Diffing the two
prompts sentence by sentence finds that only five old sentences are absent from the new one:
- the self-description;
- the reader line;
- the reader's fluency;
- the typed fault clause;
- the thirteen-kind list.

Four of them were replaced deliberately. The fluency sentence was *"fluent in plans, framing, cost
and code; not in classical proportion"*. It described one reader and went with that reader. The
model is not now told any reader's fluency beyond what about-tdl's three lines say. *Be specific,
dimensioned, and dry. Show your arithmetic.* survives verbatim.

**7. On a pack page, the first question has no tool that answers it.** The context now names
`pack:trim-classical`. The question a reader is likeliest to ask there is *"which styles use
this?"*, and none of the 27 tools answers it. `tdl_get_proportions`'s keys list no style. Called
here, it returned:
- `assemblies`, `authority`, `conflicts`, `derived_rules`, `diameters_per_module`;
- `hint`, `invariants`, `judgment_rules`;
- `module_bound_to`, `module_from`, `module_in`;
- `name`, `pack`, `part_in`, `parts`, `resolved_from`, `totals`.

The workbench route does answer it, through `corpus.pack_users`, and serves that to the page and
not to the assistant. For `trim-classical` the answer has four parts, re-derived here: 36 styles
name it, 6 opt in, 6 decline, and the pack's `applies_to` names 42. The ruling kept to the tools
the model already has, and each fix moves a frozen MCP payload or adds a tool. So it is a question
and not a patch: `oq/no-tool-answers-which-styles-use-a-pack`.

## VI. What was deliberately not done

- **No tool for the reverse relation.** That is the new question in §II.7. The ruling kept to the
  model's existing tools.
- **No record content is inlined into the context.** Answer 1's heavier form, sending the
  selection's record, was not ruled. The citation form costs one line and the model fetches the
  record.
- **`App.jsx` is untouched.** It belongs to WP-14.23's lane. `RailHost` reads the nav store
  itself, which is where the place lives.
- **`assistant.json`'s `aka` is not given to the model.** It records "the rail" as the pane's
  former name, and handing it over would reintroduce what this package removes.
- **Two typed figures in `mcp_server/server.py` are left, and they are not descriptions.**
  - The comment *"Five of the 27 tools"* is a code comment, is true today, and is served to
    nobody.
  - `tdl_overview`'s *"About 1,300 tokens"* is a size estimate, not a count. Whether it is still
    right was not measured here.
- **The starters are not written by the app.** Every question is a glossary record's `ask`. A
  page whose record carries none shows nothing, and authoring more questions is the glossary's
  business, not this package's.
