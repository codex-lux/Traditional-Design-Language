# WP-10.1 — the audit of the dependency, and the revert it produced

*3 September 2026. The adversarial audit of this session's own work — the project review's
correction (Package A), the proportion floor (Package B), and the second massing element and the
service strip (Package C). In the phase tradition: WP-6.4, 7.5, 8.6, 9.4, 9.5.*

**Verdict in one line: the block MACHINERY ships and the DEPENDENCY does not.** Three read-only
auditors were dispatched over the diff; between them and the fixes they forced, this package ends
with C2 and C3 reverted, C1 retained and disclosed, eleven guards added and every one of them
mutation-checked with the mutation's match count verified before the colour was believed.

---

## I. What shipped and what was withdrawn

| | state |
|---|---|
| **Package A** — the review's correction, the Phase 9 status lines, `roof.py`'s three drift claims | SHIPPED |
| **Package B** — 35 proportion floors to 1.0, `UNBANDED_PROPORTION` | SHIPPED |

C1 is dormant because nothing in the composer now writes a `block` on any room. It is retained

byte-identically through it, footprint and every room geometry — and because the schema that
admits it is pushed. It is disclosed because six layers below it are not element-aware; see §IV.

## II. The blocking defects, and how each was found

Eight, all introduced by this session, none reachable by any test that existed.

1. **The sheet drew the dependency on the upper floor's plate.** `panel_w = W*scale` with `W` the
   main block, so a garage at model x = 84 landed at SVG x = 630 in a ground panel ending at 532.
   Nothing clipped: the marks were inside the canvas, in the wrong panel. Found by RENDERING the
   record — the package had validated it against the schema and never drawn it.
2. **And the first guard for (1) was vacuous.** It recomputed the panel geometry from the plan and
   checked the plan against it — asserting its own arithmetic — so reverting the fix left it green.
   It reads the emitted SVG now.
3. **CP-SAT placed the dependency inside the house and said nothing.** Every room is
   `x = NewIntVar(0, Wi)` with `x + w <= Wi`; handed a dependency it did not fail, it put the
   garage at x = 50 of a 0–70 block while `footprint.blocks` described an element at 84–114.
   **It also invalidated a number this session published**: `e04d577`'s "CP-SAT proves the stripped
   house at 0 fatals" was measured while CP was cramming everything into one rectangle, where every
   room is trivially reachable. Re-measured honestly: the six-room block with NO dependency really
   is solved at 0 fatal and 0 unreachable, so the strip's own claim stands; with a dependency CP
   cannot place it at all.
4. **The hyphen was inert on 7 of the 8 partis that attach a garage.** `HOUSE_END[0]` and
   `GARAGE_ANCHOR` are both `"mudroom"`, so `house_end is anchor`: two door records to one room,
   and the garage doored *directly across the massing gap* — contradicting the comment eight lines
   above it.
5. **`stock_the_dependency` doored the brief's programme into the garage**, exiled a breakfast room
   from a parti that has a kitchen (manufacturing a fatal against its hard `must_adjoin`), and its
   `SERVICE` set included `dining`, so a brief naming a dining room could put one in the garage.
6. **The dependency bypassed the lot cap.** A house reporting `lot_capped: true` measured 34 ft
   wider than its whole lot at the built extent.
7. **Dependency windows were drawn on the main house's wall**, fourteen feet from the room, in the
   DXF as well as both SVGs.
8. **A non-string `block` was an unauthenticated HTTP 500.** `by.setdefault(r["block"], [])` on a
   list or dict is `TypeError: unhashable type`, and `POST /api/drawings` takes a plan record
   verbatim, outside the schema.

**The central claim of C3 was also false**: `hyphen_length_ft` is *still* could-not-evaluate on
every plan. Writing the hyphen as a room was necessary and not sufficient —
`plan_check.derive_constraint_vars` was never taught to read its width. The commit message said
otherwise.

## III. The decision to revert rather than patch

Five further blocking defects — openings, structure, `vertical_score`, the lot cap and the critic —
all reduce to one thing: **six layers read the main block as the whole building**, and each is
wrong on a dependency room in its own direction. Patching them is a package. Shipping a dependency
that six layers mis-measure is the thing this project exists to stop. So C2 and C3 came out, in the
tradition of refusing with the measurement rather than shipping a half-built feature.

## IV. What was fixed instead

- **`engine="cp"` refuses** a multi-element plan and names the cause; `auto` falls back with the
  reason in `geometry_report.solver`, where the plate already reads it.
- **`geometry_report.multi_element`** is written on any placement with more than one element: the
  count, the six layer names, and **COULD NOT EVALUATE** in the corpus's own words. It also names
  any room ABOVE the ground level carrying a `block` tag, which the placer does not read and the
  schema admits. Raised as
  `oq/a-massing-element-is-placed-and-nothing-below-the-placer-knows-it`.
- **The drawn extent is separate from the main block** (the sheet is sized to it), and **the
  building outline is one rect per element** rather than one across the gap — a residual the first
  fix left, which drew a 70 ft house beside a 20 ft dependency as one 104 ft rectangle with the
  hyphen inside it, and ran off the canvas entirely on a west dependency.
- **`is_block_tag()` is one predicate with two readers.** The `blocks_for` guard and the CP
  refusal asked the same question 800 lines apart and answered it differently.
- **`_record_prep()` applies `is_placed()`**, which the two inline call sites did not: an unplaced
  terrace counted toward its element's area, so `footprint.blocks` described a rectangle no room
  occupies (measured: 20 × 22 sliced, 50 × 20.8 recorded).
- **The second west element's hyphen** was placed at a hardcoded `0.0 - gap` where the east branch
  three lines below correctly read `east_edge`, so it landed on top of the first one.
- **Dead code removed** from `blocks_for`: a first sizing from `fp["target_depth"]`, overwritten
  three lines later, and the only reason that key was read at all.
- **`_plan_schema_version()` says why it failed** instead of returning a bare `"unknown"` — a third
  state wearing the clothes of a value.

## V. The un-failable rules, and the second occurrence

`wing_step_down` chose its ratio inside the band it then tested against, so the verdict was true by
construction — a pass on a figure nobody measured. It reports `ok: None` with a reason now.

**The audit then found the same shape one function away and it had been dismissed on a docstring.**
`gambrel_break_check`: `_style_gambrel_geometry` initialises `break_frac = None` and has **no branch
that ever assigns it**, so it is `GAMBREL_BREAK_FRACTION_DEFAULT = 0.625` on all 164 styles, tested
against the fault's own `[0.55, 0.65]`. `break_ok` was `True` unconditionally, forever. The
docstring's hedge that had been cited to wave it away is about `diff_ok`, which is a real
comparison of two stated pitches. **It was dismissed on a reading and died on a run.**

**And fixing it broke two plates, which is the finding worth carrying.** `roof.py`'s own CLI and
`render_roof.py` both did `'OK' if x else 'FAIL'`, so an unjudged verdict printed as a
**conviction** — on the one surface a reader actually looks at, and one line from where the first
fix had been made. `render_roof.py` had ANDed the gambrel's two halves into one word, so the moment
the break went unjudged the plate convicted a gambrel whose one real check had passed. One word
cannot carry three states for two rules; there are two now.

**And sweeping for the pattern found a THIRD, in a different file.**
`proportion_engine.py`'s `show --invariants` printed `'ok ' if i['holds'] else 'FAIL'`, and
`check_invariants` sets `holds: None` with an `error` when an expression cannot be evaluated at
all -- so a pack was convicted of breaking its own invariant on the strength of a crash. **The
selftest twenty lines below has always read it correctly** (`if i["holds"] is not True`, printing
`i.get("error")`), so the file knew and the print did not. That is how these survive: the tri-state
is handled where the number is COMPUTED and collapsed where it is DISPLAYED.

## VI. The guards, and the four that could not fail

Eleven mutations were run; every fix goes red on its own. Four guards had to be rewritten first,
and two of those four were written BY this audit, inside the class that exists to catch exactly
that:

- `b["x"] == 0` **cannot fail against a float** — `0.0 == 0` is True — while its own comment
  claimed to be pinning the integer origin. It asserts `type(v) is int` now, excluding `bool`.
- The bounds guard asserted a consequence that **does not exist**: `slice_rect` confines a room to
  its element, so no score can relocate it. The real effect is on the SCORE and therefore on which
  candidate wins — measured at 28 points on the winning placement — and the call site is then read
  directly, which is the weaker form and is used because the stronger one is not available.
- The single-pile sizing guard's fixture **did not discriminate**: at 542 sf, `round(542/22/10)`
  and `round(542/36/10)` are both 2, so the rule under test made no difference to the answer. The
  areas are chosen to straddle the rounding boundary now (400 sf: 20 × 20 against a 10 × 40
  splinter).
- The hyphen-gap guard pinned the constant to itself. It reads the band out of
  `groupings/dependency-and-hyphen.json`, which is where the rule lives.

**A mutation that changes nothing is not evidence that nothing is wrong — it is evidence that the
fixture is blind.** That sentence cost three rewrites here.

## VII. What was deliberately not done

- **The six layers are not taught about elements.** That is the open question, with the four things
  that must be ruled first. Disclosure is not a fix and is not offered as one.
- **`hyphen_length_ft` remains could-not-evaluate.** It needed the room AND a reader; C3's removal
  takes the room away again. The claim that it had been delivered is retracted here.
- **The chimney `style_check` is still un-failable** for the one style that can run it —
  pre-existing, recorded, not this package's.
- **21 HARD fault rules are inert via prose `exceptions`**, and 47 of 51 exception lists are fully
  inert: `plan_check.excepted` intersects them with the style-id chain and a prose sentence matches
  nothing. Pre-existing, at scale, and the OQ 59 class. Recorded, not fixed here.
- **`schema/plan.schema.json` was reformatted wholesale** by an earlier commit in this session —
  991 lines of diff for 86 lines of real change. Verified semantically additive (0 leaf paths
  removed) but `git blame` on the schema is destroyed. Not reversed, because reversing it is a
  second reformat.

## VIII. Verification

`build/check_all.py` green. `check_counts.py` 0 stale, `check_citations.py` 0 dangling,
`check_ids.py` clean, `gen_open_questions.py` run. Both shipped reference plans place
byte-identically — footprint, every room geometry, relaxation counts 7 and 4 — which is the
regression guard the whole change is held to. Performance measured, not assumed: `blocks_for` is
outside the candidate loop, `_plan_schema_version()` is 0.41 ms once per `revise()`, and an
800-room solve went 78.79 → 62.75 s.

`tests/test_geometry.py::TestTheAuditGapsInTheBlockWork` and
`tests/test_roof.py::TestThePlateDoesNotConvictAnUnjudgedRule` are the guards.
