# WP-14.29: one meaning per mark

*25 September 2026. Phase 14, tranche 2, wave 3. Ruled by Lucas the same day: "one meaning per
hatch, one product key." The contract is `docs/prd/phase-14-tranche-2.md` §D, and the question it
closes is `oq/one-duty-per-hatch`. Cite this report by filename; a Phase 14 number does not
disambiguate a package in this repository.*

## What it is for

A key says what a mark MEANS, so a key can only be written for a mark that means one thing. Until
this package the workbench's could-not-evaluate hatch meant five things on screen and the 45°
hatch meant six (`oq/one-duty-per-hatch` counts them file by file). Five of the eleven were three
of the four states this corpus insists must never collapse: could not evaluate, a decision left to
the reader, and not applicable. The square that drew all three was `aria-hidden`, and the words
that told them apart sat in a map inside `JudgmentMark` that no screen reader ever met. And the
tradition hue `--t3` was `#AF6B50`, byte for byte the brick of the UI's fatal, so every Iberian
style was drawn in the colour of failure.

## I. What was built

**The duty tokens.** `workbench/app/src/theme/tokens.css` declares twelve `--mark-*` custom
properties in one block, under a comment per mark. Those comments are the only written statement
of what each mark means, and the five new records quote them as their basis. Each value is the
PAINT of the mark's form. `--judge-unjudged-fill` is retired, because a second name for one hatch
is a second place a second meaning can be given to it. `--t3` is `var(--salmon)`.

**The forms.** `workbench/app/src/marks.js` is pure and writes no word. It states each mark's
FORM, because a custom property can hold a paint and cannot hold a shape. It also names the six
states `JudgmentMark` draws, each with its token and its record.
`components/MarkGlyph.jsx` draws one token in its form, `aria-hidden`. The exception is the one
form with no glyph, loading, whose word IS the mark.

No row was added. Four rows took a consumer the PRD did not list, and each consumer means exactly
what its row means. Nothing was widened:

- the dossier's judgment constraints, a derived rule flagged `judgment` and the assistant's
  question turn are the three other *yours to decide* uses `oq/one-duty-per-hatch` itself listed;
- the masthead's refusal word is a refusal;
- the atlas's country ring already drew the low-confidence form, and it is named here for the
  first time.

**The records.** Five new `mark` records: `mark-loading`, `mark-low-confidence`, `mark-not-built`,
`mark-wanted` and `mark-set-aside`. Each is editorial, and each quotes its own tokens.css comment
verbatim. The six judgment records and `variant-status-forbidden` carry `mark`. The severity
records carry none, because §D gives no severity a mark row.

One record was added that the PRD did not name. `key-to-the-marks` is family `product`, and it
words the key's heading and the `?` card's link, which would otherwise have been a word the app
wrote. All together: 210 records, 668 quotations verified, and 12 marks held to the stylesheet by
rule 13.

**`JudgmentMark`** draws six states, each in its own form. Each state's word is its record's word
and reaches assistive tech on both branches:

- where the mark carries a label, the word is a visible `Term`;
- where the row already names its state (`showWord={false}`), the word is visually hidden text;
- on the bare glyph, the word is visually hidden text.

A state the component does not know is drawn unjudged, which is the one direction a wrong state
may fall.

**The key.** `components/MarkKey.jsx` sits on the Glossary, on the unfiltered index and on the
Marks family. The `?` card links to it at `#/glossary?family=mark`, and the link is worded by
`key-to-the-marks`. Its rows are `marks.markKeyGroups(lookup)`: every record carrying a `mark`,
grouped under its family's record. It holds no list of marks.

**Two readers that choose a mark.**

- `judgment.styleFindingMark(finding)` reads the finding's own `kind`. The Plan Workbench had
  matched `/cannot evaluate|check by hand/` and drawn both in the unjudged hatch.
  `constraint-unjudged` is a test that could not run. `constraint-unformalised` is a hard rule with
  no test, which `build/check_constraints.py` admits only as `scope: judgment`.
- `proportions/page.js`'s `ruleMark(r)` draws a `judgment` rule as yours-to-judge. Its verdict,
  `ruleState`, still counts it as no verdict.

**The pointer that was not a state.** Brief Intake's *conflict set · on the bench, not here* wore
the 45° hatch. It is a link to the bench now, and wears none.

## II. What was found

1. **The rule-13 checker holds one direction and the key needs both.** `build/check_glossary.py`
   refuses a record naming a property the stylesheet does not declare. It does not see a duty the
   stylesheet declares that no record names, and that is the case where the key would draw a mark
   with no word. `src/marks.test.mjs` holds that direction. Deleting `mark-wanted.json` leaves the
   checker green and turns that test red.
2. **Four judgment seeds broke four checker tests, and the fix was the control, not the
   assertions.** `tests/test_check_glossary.py`'s control copies four judgment records as seeds.
   Rule 13's tests drive a synthetic stylesheet declaring only what each test names. Once the seeds
   carried their real marks, `mutate()` refused to set a mark they already had ("would prove
   nothing"). In the other tests a seed would have been judged against a stylesheet that never
   declared it. The control clears the seeds' marks and says why, and the real marks are held by the
   checker's run over the corpus.
3. **The basis pattern had to admit the stylesheet.** PRD §A.2 names `tokens.css` comments as the
   `mark-*` records' basis. `check_openings.GLOSSARY_REC_RE` admitted no file under `workbench/`,
   so every such basis failed with *"names no record"*. It admits that one path now, spelled
   exactly, and nothing else of the app. Its test says both halves: `marks.js` and a CSS neighbour
   are refused. The schema's `basis` description names the file too.
4. **`--t4` is `--violet`, which is the ink `--refusal` names.** Every North American style is drawn
   in the colour of a refusal: the ruling's `--t3` finding, one tradition over. And the refused mark
   is brick by the PRD's table while every refusal card is violet. Neither is changed, because each
   is a ruling about the standard. Raised as
   `oq/a-refusal-is-drawn-in-two-inks-and-one-is-a-traditions-hue`.
5. **A medium-confidence node is no longer marked.** The family tree drew `medium` as an open ink-4
   square and `low` as a hatched one. The open square is yours-to-judge's form now, and the hatched
   one is could-not-evaluate's. `medium` is the style schema's own `default`, the unmarked case, so
   the one `low` node (`scandinavian-log-vernacular`) takes the low-confidence mark and its record's
   word, and the twenty-eight `medium` nodes take nothing.
6. **The Glossary index's term count would have counted the key.** The key's rows first carried
   `data-glossary-term`, which is the index's own selector. The walk's check that the index lists
   every word the server serves would have counted twelve rows twice. The rows carry
   `data-mark-term` instead.
7. **The Plan Workbench's panel disagreed with its own count before this package, and the marks
   now show where.** On `good-03-parlor-drawing-room-house` the panel's heading reads *could not
   evaluate · 3 of this style's constraints* over FIVE constraint rows. `plan_check`'s
   `constraint_summary.unjudged` counts only the `constraint-unjudged` rows, so the 3 was always
   right, and the two `constraint-unformalised` rows sat under it in the same hatch. Drawn now,
   three rows wear the hatched square and two the open one, so the count and the marks agree row
   by row. The heading's words still say *could not evaluate* over the two that are yours to
   judge (§III).

## III. What was deliberately not done

- **`OrderPlate`.** Its dashed confidence stroke paints the low-confidence form through
  `--judge-unjudged` by name, and it marks `medium` as well as `low`. The tranche forbids any change
  to `OrderPlate` (§G).
- **Transcription.** It sets a room with no type, and its gaps, in `--judge-unjudged`. That is an
  ink and not a hatch, and so outside a ruling about hatches, but it is a judgment's ink borrowed
  for something that is not a judgment.
- **`FaultCard`'s unjudged licence** keeps its dashed left rule. The field moved onto
  `--mark-unjudged`. A dashed RULE is a line style, not the dashed OUTLINE that is the low-confidence
  mark.
- **`--gilt-deep`'s other duties and the pass/fail luminance.** The question counted eight colour
  duties on `--gilt-deep`, and the PRD's table gives it a ninth, the yours-to-judge outline. Pass and
  fail still differ by 1.08 : 1 in luminance. The answer to that is the word beside every verdict
  square. No ink moved but `--t3`.
- **The Plan Workbench panel's heading** still reads *could not evaluate* above its yours-to-judge
  rows (§II.7). The heading is copy the app writes today. Splitting the panel into two headed
  groups needs two headings, and a heading is a record. That belongs with the panel, not with a
  package about marks.
- **The forbidden pill's legibility.** At 1440 a forbidden variant's name is hard to read under
  the close hatch and the strike. `--mark-forbidden` is `var(--hatch-forbidden)`, the paint it
  always had. The same names are legible in the notes beneath the pills.
- **The walk's pen check** was examined and not re-cut. It already reads computed style, and its
  one exemption is a `<pattern>` inside an SVG sheet, which is a drawing material in model units,
  not a CSS duty token. No walk check selected on a hatch.

## IV. Guards, and the mutations that drive them

`workbench/app/src/marks.test.mjs` is fifteen tests. Every population is derived from the
stylesheet, the records or the code, and none is typed. Each is asserted non-empty first.
`judgment.test.mjs`'s JudgmentMark test is re-cut: the component keeps no `words` map, so the test
holds `JUDGMENT_MARK` to `marks.js`'s table and asserts that the component reads that table.

Fifteen mutations. Each was asserted to have LANDED by reading the file back, then restored and
proved restored by hash. All fifteen went red from a green baseline:

| Mutation | Red on |
|---|---|
| Brief Intake's pointer back on `var(--hatch-45)` | no shipped file draws a hatch by name |
| the candidate set's dropped diagrams back on `var(--hatch-45)` | the same |
| `glossary/mark-wanted.json` deleted | each duty named by exactly one record |
| `--t3:#AF6B50` | `--t3` names a palette ink and is not brick |
| set-aside reads the 45° hatch (two duties on one hatch) | one duty per state hatch |
| not-built reads the 45° hatch (a state hatch left with none) | the same |
| a selector in tokens.css paints `var(--hatch-135)` | only a `--mark-*` reads a hatch |
| the bare `JudgmentMark` loses its hidden word | the word reaches assistive tech on both branches |
| yours-to-judge given the hatched square's form | the non-verdicts are never drawn as one another |
| a hard rule with no test read as could-not-evaluate | `styleFindingMark` |
| a `judgment` rule drawn with its verdict's mark | `ruleMark` |
| a duty token with no form in `marks.js` | the forms match the declared tokens, and the key |
| the stylesheet struck from `GLOSSARY_REC_RE` | `check_glossary.py`, and the admitted-files test |
| a `mark-*` record's quotation edited out of the stylesheet | `check_glossary.py` |
| a record naming an undeclared duty | `check_glossary.py` rule 13 |

The walk gains two blocks.

- **The key.** Every marked record is a row, once. Each row's specimen is drawn by that record's
  own duty token and paints something, beside the record's word. The `?` card links the key,
  worded by its record, and following the link lands on the key.
- **A judgment mark's word.** Read through the accessibility tree (`ariaSnapshot`) on Craftsman's
  judgment constraints, never through the DOM, because hidden from sight and hidden from assistive
  tech are different properties.
