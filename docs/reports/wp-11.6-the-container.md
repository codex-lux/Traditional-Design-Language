## Layer 1 — `openings`

**First, and not by preference.** The ruling: an element-aware `openings` makes the dependency's
windows real, which turns `structure`'s missing envelope walls into a **drawn collision** rather
than a silent absence. Fixing them the other way round leaves the shield in place — WP-7.4's
fixture packer, where turning the corner produced five overlapping pairs immediately because the
fixtures had previously been wrong together.

`openings.envelopes()` maps each room to its own element's rectangle and `_boundary_walls` tests
against that instead of the main block. Refused dependency openings **9 → 5**.

**The five that remain are honest.** The kitchen's north edge is 23.72 against its element's 29.12:
it does not reach that face and the refusal is correct. That is the difference between a house
telling you something and an instrument telling you about itself.

**THE OLD READING DID NOT LOSE THE DEPENDENCY'S WALLS — IT ASSERTED ONE FORTY-ONE FEET AWAY.**
`x <= tol` is satisfied by any x at or west of 0.6, so a room at x = −41 tested as sitting on the
main block's **west face**. Against the main block the fixture's kitchen returns `{"W": (9.05,
23.72)}`, not `{}`. That is the mechanism behind the entry's *"a window drawn fourteen feet from
the room"*, and it is worse than reporting nothing: a false positive rather than a silence. This
report's first draft asserted the old call returned nothing, and the test that pinned it failed —
which is the only reason the sharper statement is here.

**The join is the room's own `block` tag, not a room list on the block.** `blocks_record` writes
id, role, x, y, width, depth and area and **no membership**, so a first version read `b["rooms"]`,
found nothing on every plan, and left all nine refusals in place while reporting success. The tag

**The one-rectangle regression holds by construction.** `envelopes()` returns an empty map below

once per element over that element's own rooms, at that element's own origin, and tags each wall
and span with the element it belongs to. A one-element plan takes the same path with one element,
so the sixteen one-rectangle records are byte-identical by construction rather than by a branch.

| | before | after |

| the dependency's own envelope walls | **0 of 2** | **2 of 2** |

**A span is not filtered out of the gap — it cannot be computed there**, because each element's

its width.

**The ruling is item 2: the cap is on the BUILT EXTENT, hyphen included** — *"the hyphen is roofed

Measured on the fixture at an 80 ft lot: main block **63 → 45 ft**, built extent **104 → 86 ft**,

**THE BASELINE ITSELF WAS WRONG — THE THIRD PROBE OF SIX TO BE WRONG, AND THE SECOND TO READ A
KEY THAT IS NOT THERE.** The table above published `lot_capped: null`, and carries the correction

**AND THE SECOND BYPASS IS ON EVERY PLAN IN THIS CORPUS.** Chasing the first one, the probe was run

## Item 4: CP-SAT places per element, and twelve downgrades become four

`geometry._solve_uncached` refused a plan with a dependency and `auto` fell back to the hill-climb
naming the reason, so on exactly the plans whose composition most needs proving, the search carried
the findings. The refusal was honest — handed a dependency the engine did not fail, it placed the
wing's rooms **inside** the main block while `footprint.blocks` went on describing an element
somewhere else — but it was a refusal, and Phase 11 opens on a sheet that says
*"PLACEMENT PROVED (CP-SAT)"* over a placement that set aside sixteen declared exterior walls.

`geometry_cp._boxes` gives each room its own element box, read from `geometry.blocks_for` — this
repository's one spelling of where an element sits, so the two engines cannot come to disagree.
**With one element every room maps to `(0, 0, Wi, Hi)`, which is the pair the model spelled inline
at every site**, so each expression is arithmetically the one it replaced. That is layer 2's
discipline (`structure.build_section` runs the same path with one element) followed for the same
reason: a branch is a second code path nobody exercises.

**The regression guard is the MODEL, not a placement.** A CP solve of the Tidewater record takes
ninety seconds on this machine, which is not a test; but the model CP-SAT is handed is deterministic
and free to build. Serialised and hashed, `_build`'s proto is **byte-identical on all sixteen
records, hard and objective, before and after** — and if the model is identical the placement is
identical whatever the solver does with its budget.

**THAT SENTENCE WAS PUBLISHED ONCE BEFORE IT WAS TRUE, ON AN INSTRUMENT THAT COULD NOT FAIL.** The
first harness called `m.Proto().SerializeToString()`, which this build of ortools does not have —
`CpModelProto` here is the C++-backed helper. It threw `AttributeError` on BOTH sides, so `diff`
compared two identical tracebacks, reported no difference, and the run printed
`CP MODEL BYTE-IDENTICAL ON ALL 16`. It was believed three times, and it went into this report and
into `CLAUDE.md` as the package's headline guard. Re-derived with `str(m.Proto())` — and an
assertion that a model serialises to more than 5 KB, so an empty read cannot pass again — **the
objective model had moved on seven of the sixteen.**

The cause was mine and it is worth stating plainly: `_EXT` widened four variable domains so a
wing's negative coordinates fit, and the first version widened them **unconditionally**, on the
argument that a looser domain cannot change an answer. **A domain is an input to presolve, not a
comment.** `_wide` returns its arguments unchanged below two elements, and
`test_no_shipped_plan_gets_a_WIDENED_domain` computes the widened bound the way `_build` computes
it rather than quoting it, with the multi-element control beside it so it cannot pass by never
widening at all. *An instrument that cannot fail is worse than a test that cannot fail, because its
output is a number* — this repository's own sentence, met while relying on it.

### The measurement

The Tidewater reference record, `engine="cp"`, 90 s, seed 7, on this machine. **`block-only` is the
same record with the three service rooms tagged into a west dependency and NOTHING else changed** —
the same declared `exterior_walls`, so it isolates item 4 from the fixture's own re-declaration:

| record | engine | downgraded wall pins |
|---|---|---|
| one rectangle | cp-sat | **12** |
| block-only | cp-sat | **4** |
| the package's fixture (tagged **and** walls re-declared N/S/W) | cp-sat | 5 |

**Twelve to four, with not one declared fact changed.** That is the diagnosis's own sentence
measured: *"the declared record is infeasible in one rectangle because its `exterior_walls` are the
exposures of a five-part house."* A service room declaring N/S/W is declaring the exposures of a
WING; pinned to the main block those walls cannot co-hold with the rooms around them, so CP proves
them impossible and sets them aside. In their own element they are ordinary facts.

Beside it, at the same budget: `plan_check`'s key on the one-rectangle CP placement is
`[0, 81, 83]` at score 930.4 and on the tagged one `[0, 44, 86]` at 517.8 — but **that pair mixes
two changes** (the tagging AND the re-declared walls) and is quoted as a reading, not as item 4's
effect. The downgrade column is the isolated one.

### The hyphen's abutment needed no new constraint, and that is the finding

The plan text called the abutment "the seventh defect", to be added as a constraint. It was already
there. `_build`'s door rule is `a["x"] + a["w"] == b["x"]` with the two overlap bounds — a **hard
abutment**, vacuous while every room shared one rectangle and real the moment the elements are.
`AddNoOverlap2D` stays over the whole level for the same reason: two elements are disjoint so every
cross-element pair is trivially satisfied, but the link's rooms and the rooms either side of it
stand in the ordinary non-overlap relation, so the rule can ask them to share a face and get a true
answer.

What it needed was **the other half**. A door between elements that do NOT touch is not the model's
fact, and left alone it would prove a buildable house impossible: the elements are laid by
`blocks_for` with a gap, and no placement of rooms inside two separated rectangles can put a leaf
across it. The heuristic charges such a door and draws it `unplaced` with a reason; the prover says
the same thing in `refinements` rather than returning INFEASIBLE.

**On the hyphen fixture the whole claim is one measurement**: the hyphen element abuts BOTH the
dependency and the main block, the dependency abuts the main block not at all, and so
*"Kitchen (Dependency) and Hyphen share a door"* stays a hard requirement while the three doors that
would have to cross open ground are stated as outside the model. The link carries what a link is
for, and it does it through the rule that was already written. Both halves are asserted, because
either alone is worthless: `_abuts` returning True for everything would prove a buildable house
impossible, and returning False for everything would make every cross-element door vacuous and the
hyphen carry nothing. **Measured on the no-hyphen fixture: three such doors stated and twenty-seven
door requirements kept** — the count matters, because a clause
that refused every door would make the model trivially satisfiable and every measurement above
vacuous, and there is a control test for exactly that. (An earlier draft wrote "5 of 5", carried
across from the parti section's own fixture, which is a different house.) `_abuts` is the test, and a shared CORNER is not an abutment — no leaf fits in a point,
which is the reading `openings.faces_across_a_gap` already takes one layer up.

### Three things found on the way, and two of them were not about CP at all

**1. `derive_footprint` sized the main block from the whole building's programme, wing included.**
`a0 = sum(r["_area"] for r in prep[0])` counted a dependency's rooms into the main block while
`flank_sizes` sized that dependency from the same rooms and laid it BESIDE the block — the area
counted twice. Measured on this fixture: **2,405 sf of main block for 1,863 sf of main-block rooms,
29% over.** The hill-climb absorbed it silently as empty floor. CP-SAT, which has a coverage floor,
reported the house INFEASIBLE at every bay count *"even with every declared requirement dropped"*.
**A search that tolerates an over-size and a prover that refuses it are the same defect read
twice**, and only one of the two readers says so.

Fixing it moved the main block from 63 × 38.17 to 45 × 41.4 and **every measurement WP-11.6 had
published on this fixture with it** — the layer-1 refusals 9 → 5 became 9 → 5 → **0**, the layer-5
landlocked control fell from two rooms to one (`chamber2` reaches its east wall in an honestly-sized
block), the kitchen's lit walls went `["S","W"]` → `["N","S","W"]`, and the three-element built
extent 118 → 100 ft with `flanking_ft` unmoved at 55. Each is updated in the suite with the reason
in its own docstring. **The identity survived and the literals moved**, which is the difference
between a guard and a measurement: `built_extent - main == flank` still holds exactly.

**2. The multi-element disclosure was attached in `write_record` only** — the heuristic's record
writer — and the CP path builds its report separately. So the one engine every multi-element plan
was *sent away from* was the only engine that disclosed anything about them. The first proved
dependency placement came back with `multi_element: null` on a record carrying two blocks. It is on
both writers now, which is the argument this file already makes four lines above about OQ 54 and
OQ 55: a guarantee that holds on one engine is not a guarantee.

**3. `_score` never passed `bounds` to `exterior_score`** while `solve_heuristic` has passed its
`gbounds` since layer 4 — so a wing room's declared walls were charged against the WING on one
engine and against the main block on the other. `_score`'s own first sentence is *"the heuristic's
OWN scoring of this placement, term for term"*. The other scorers take no bounds in either engine
and are left alone deliberately; the entrance and zoning terms keep the main block's frame for the
same reason, with only their variable DOMAINS widened, because a wing's coordinates are negative and
`NewIntVar(0, span)` on a distance-to-the-front is not a worse model, it is an infeasible one.

### The site that was missed, and how it was found

Every site in `_build` that read the footprint as the whole building had to become the room's own
element, and all but one were found by reading. The one that was not is
`m.NewIntervalVar(x, w, m.NewIntVar(0, Wi, ""))` — **the interval's END variable**,
which carries no constraint of its own, so nothing in the source reads as a bound on where a room
may be. A west wing's rooms end at x = −14 and that domain cannot hold a negative number, so the
model came back INFEASIBLE **with every assumption cleared and no conflict to name**. Found by
bisecting the model — turning the coverage floor off and watching it stay infeasible — not by
re-reading it. *An unreachable bound looks exactly like no bound.*

### Mutation: seventeen run, and the misses came in two waves

The first sweep of fifteen caught eleven. All four misses are guarded now — and re-running the
containment mutation against its **new** guard exposed a fifth, the DEPTH bound, which is
unreachable from the corpus (a dependency is centred on the main block's axis and never deeper than
it) and so is driven by replacing `blocks_for`, exactly as layer 6's garage-element branch had to
be. Seventeen of seventeen on the re-run.

The four first-wave misses share one shape. The first pass asserted that the tagged model is SATISFIABLE and
that the solution it returns sits inside the wing — and **satisfiability is a weak instrument**: a
LOOSER model is still satisfiable, and a returned solution can happen to be contained. So every
mutation that merely *widened* a bound passed.

| mutation | why it was missed | the guard now |
|---|---|---|
| containment back to `x + w <= Wi` | the main block's bound is far looser than the wing's and every legal placement satisfies it | force a wing room one foot past its own east face: must be INFEASIBLE, with the one-foot-inside control beside it |
| wall pins back to the main block | the pins are assumption literals and the test cleared assumptions | assume the kitchen's own wall literal alone; under the main block's reading not one of the four faces is reachable, so the status itself is the guard |
| the bay grid measured from the main block's origin | it is in the objective block, and **every test built `objective=False`** — the whole soft half of the model was unexercised on a multi-element plan | build with the objective and solve |
| `fill` back to the building's ratio | inline in `_build` and unreadable from outside | lifted out as `_element_fills` and measured, with the one-element control asserting it is the number the old line computed |

The second and third are worth carrying past this package: **an assumption literal is invisible to a
test that clears assumptions**, and **a suite that only ever builds the hard model has not tested
the objective at all**.

### What item 4 does NOT do

The disclosure keeps its block and its list stays empty. It used to give two surviving reasons and
now gives one and a half: the roof is still derived for the main block alone with no stated ridge
relation per element (ruling 1's second half, unbuilt), and **the abutment between two ADJACENT
elements is still nobody's rule** — refusing a door across a gap and stating why is honest, and is
not the same as knowing when two elements ought to touch. The note may no longer say the prover
refuses a multi-element plan; saying so would be a false statement about the engine in the
flattering direction, which is the fake-unjudged shape this corpus treats as exactly as dishonest as
a fake pass.
