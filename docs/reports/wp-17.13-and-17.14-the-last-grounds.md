## WP-17.13, the third surface: Proportions

**The material modules come first.** `packGroups` (`proportions/page.js`) moves the module-system
group ahead of every other kind. The board orders it that way: a brick course or a sash light is
what a building is measured in before an order is applied. Every other kind keeps the server's
order, and the sort is stable. A new test sends the kinds in the wrong order and reads them back in
the right one.

**The order plate's inks are the drawing duties.** The plate is a drawing on vellum, so its root is
`data-ground="vellum"`, and its lines and figures read `--draw-*`:
- `--draw-grid` for the axis;
- `--draw-seen` for a member;
- `--draw-dim` and `--draw-note` for the dimensions.

**Two faint text rows are gone.** The two dimension figures were set in `--ink-4`, which reads
2.26 : 1 on paper. They are `--draw-note` now, which is `--ink-2`. `inks.test.mjs`'s baseline lost
both rows, so it shrank by two.

**The page around the plate reads the text and border duties.** It went from 43 primitive rows to 0.

## WP-17.14: the Glossary and Transcription

**The Glossary sets each word as a vellum card on the instrument**: an index entry is a card, and a
word's own page is a card. The page already showed the term, its quoted basis, how it is drawn,
where it appears and its neighbours, so nothing there was rebuilt.

**Transcription draws its tracing on vellum.** The tracing `svg` carries `data-ground="vellum"`, so
its grid and the rooms the user draws keep their paper inks. The form at the right stands on the

**The draft's gaps are named as what the critic will not see yet**, a new record,

**The discard and clear controls were the only `--iron` fallback in the app.** They read `--refusal`
now, the duty a refusal takes everywhere else.

## What was found

**The ground ratchet was blind to Transcription, and for the reason this repository has already
written down once.**
- `grounds.test.mjs` stripped comments with `/\*[\s\S]*?\*\//`, which reads Transcription's
  `accept="image/*"` as the start of a comment.
- So everything after it was blanked, and three primitives the ratchet never saw passed it. They
  were two `--ink-2` texts and a `--rule` border.
- WP-14.33's audit recorded exactly this trap for the copy scanners and built
  `sourceReader.mjs`, the one lexer they share. The ground guard was written after that audit and
  used the regex anyway.
- It reads `stripComments` from the shared lexer now.
- **The mutation that proves it: on the lexer and the pre-fix Transcription source, the guard
  reports `surfaces/Transcription.jsx: 3`.** On the regex it reported nothing.

**Twenty-four other test files carry the same regex.** On a stylesheet it is right: CSS has no
string that contains `/*`. Some of them read JavaScript, though, and `no_raw_fetch.test.mjs` is one
that walks every source file. A raw `fetch` written in Transcription after its file input would be
invisible to it. Sweeping the JavaScript readers onto the shared lexer is the audit's (WP-17.15) and
not this package's, because each of those guards has to be mutation-checked as it moves.
