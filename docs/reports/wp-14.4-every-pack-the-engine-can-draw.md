# WP-14.4 — every pack the engine can draw

**Status: built, on a branch cut from `d565dea` (§VI says why that base and not the contract
commit).** Every figure below was measured on that base plus this package's working tree, in this
package's worktree, on 24 Sep 2026, unless it says otherwise. Re-derive before quoting: the figures
that describe the corpus move whenever a pack, a node or a fault record moves.

The package is the server half of Phase 14's proportions and dossier surfaces, built to the frozen
contract's §H (payload shapes), §D.2 (section counts) and §0.1: the members payload for every pack
the engine can draw rather than the 25 with a column stack, a pack's own statement that its module
IS the room's ceiling and a checker that refuses the statement where the pack's rules do not bear it
out, who uses a pack, a style's packs by provenance, the dossier's head and section counts, the
lineage edge's slot scope, and the example briefs. No surface draws any of it yet; that is the
client packages' work.

## I. What was built

1. **`build/profiles.py::pack_geometry(..., datum="order")`** gains `datum="wall"`. Under the wall
   datum the column radius, the diminished radius and the die are all 0, no group's axis reading is
   consulted, no assembly takes the shaft's taper branch, every face walks from the wall plane, and
   the output gains `"datum": "wall"`. **Under the default nothing changes and no key is added**,
   and that is held two ways (§III): the base commit's own `pack_geometry` against this one over
   every pack at three modules, and `render_profile.py`'s 73 plates against their committed hashes.
   An unknown datum is refused rather than read as the default.
2. **`module.equals`** — `schema/proportion-pack.schema.json` admits `equals: ceiling_height` on a
   pack's `module`; `proportions/systems/trim-classical.json` declares it, restating what its own
   `module.name` already says in prose ("The finished ceiling height of the room"). It is
   **lie-checked, not trusted**: `build/check_systems.py` check 19, one function
   (`module_equals_errors`), refuses a declaration unless (a) the value is a variable the engine
   binds, (b) some derived rule reads it, (c) no rule reads it together with `module` or `part`,
   which would count one input twice, and (d) `module.default_size_in` is a number.
   `tests/test_module_equals.py` runs the function over every pack in `proportions/`, not only the
   `systems/` directory the checker opens, so a declaration elsewhere cannot escape it; and it
   drives the checker's own CLI over a temporary copy of `trim-prairie` — clean alone first, then
   refused once the declaration is added — so the red is the declaration's and not the lone pack's.
3. **`corpus.proportions_with_members`** (`GET /api/proportions/{id}?members=true`) serves every
   drawable pack. `drawing` says which path: `"stack"` is the existing path with every existing
   key's value unchanged; `"assemblies"` dimensions each assembly on its own (`include=[aid]`, so
   its y runs from 0) and builds its geometry on the wall datum; `null` is a pack with nothing to
   draw. A pack whose module is bound to the ceiling is dimensioned AT the ceiling, defaulting to
   its own `default_size_in` and not to the route's 108, so the plate and the rules table describe
   one wall and move together. New keys `drawing`, `at`, `module_name`, `module_bound_to`, `kind`,
   `used_by`. The route's two defaults are `None` so the members path can tell "not given" from
   "given as 108"; its other path passes 108 and 36 exactly as before.
4. **`corpus.pack_users`** (`used_by`), **`corpus.style_packs`** (`GET /api/styles/{id}/packs`)
   and **`corpus.style_dossier`** (`GET /api/styles/{id}/dossier`). The first two are read off
   `build/resolve_kit.py`'s own `resolve_packs`, `withheld_for` and `refusals_for` — no second
   cascade, because a second walk would be a third spelling of OQ 51's rule the first time either
   moved. The dossier's section counts are each the figure the section's own endpoint gives, and a
   zero-count section is omitted rather than listed empty.
5. **`/api/phylogeny`** edges carry the lineage record's `slots` (null where it states none), and
   **`GET /api/briefs/examples/{name}`** mirrors `example_plan` exactly: basename, `.json`
   appended, 404 naming the brief, 422 for a file that is not JSON. Every new route sits behind the
   auth gate, and a test asserts it rather than assuming the prefix covers it.
6. **`workbench/app/src/api/client.js`** gains `stylePacks`, `styleDossier` and `exampleBrief`,
   appended; nothing else in the client changed.

## II. What was found

**1. The order datum would have drawn all 27 stackless packs standing off their own wall.** Asked
for their assemblies under the default datum, every one of the 27 packs this package newly draws
puts its nearest face clear of the wall, because `dimension()` computes a column diameter for EVERY
pack as module over diameters-per-module and `pack_geometry` reads it as a radius.
`trim-classical`'s 9'-6" ceiling module becomes a column **228 in** across and every wall section
is drawn **114 in** off its own wall — the ceiling height turned sideways. It never reached a
drawing only because the members payload served these packs no assemblies at all (`stack_for`
knows only order assembly names), so the pack-level geometry it did serve described an empty stack.
The wall datum is the fix; the default is untouched.

**2. The wall datum puts three faces behind the wall plane, and the cause is the half round, not
the datum.** `profiles.py` constructs a torus with its height as its diameter, so a round whose
recorded face is less than half its height springs behind the plane it stands on, and the member
walked from it starts there: `facade-portada`'s estípite baluster (a torus 43.2 in high on a
12.0 in face) and the acanthus capital walked from it, and `jetty-overhang`'s drop pendant (a torus
with no recorded projection at all). The contract's sentence that every face runs from the wall
plane is true of where every face path STARTS and ENDS; it is not true of every point on these
three. The test states the exemption as the construction and asserts that it is exercised, so it
cannot quietly become an exemption for anything else. Whether a baluster or a pendant should be
drawn as a round at all is a question about `profiles.py`'s vocabulary and not this package's.

**3. `height_in` and `height_in_stated` are equal on all 50 assemblies, and it is not for the
reason the contract gives for serving both.** Side-by-side members (`sums_check: false`,
`moorish-arch`'s arch and alfiz) are given the stated height by `dimension()` itself, and a stacked
record whose members do not sum is refused by `check_systems.py` check 11 and by `check_orders.py`.
So on the corpus the field could read either figure and nothing would tell — which the mutation
harness proved by going green (§IV). Both are still served, because a record COULD state a height
its members do not fill and the plate must draw what is there; the case is DRIVEN on an in-memory
copy of a real pack.

**4. No stackless pack is an overlay** (0 of 50 assemblies has an owner other than its own pack),
so `owner` could be the pack's own id and nothing would tell. Driven with an in-memory overlay of a
real stackless pack that states none of its assemblies: every row names the base.

**5. The MCP payload is unchanged and still serves no assemblies for `trim-classical`.**
`mcp_server/core.py` is not touched; the workbench now draws six assemblies (71 members) of a pack
the MCP tool serves none of. That disagreement between two surfaces over one pack is
`oq/mcp-proportions-serve-no-assemblies-for-non-order-packs`, and the test pinning today's MCP
answer names that question in its own failure message, so the day it moves the question it belongs
to is named rather than the answer changing under this package.

**6. `used_by` and the packs route re-derive every figure the contract measured.**
`trim-classical` is bound by 36 nodes, delivered to 6 (all six opted in, all `interior` — the
opt-in gate at work), named by 42 in its own `applies_to`, applies-to-only 7, bound-not-named 7.
Tidewater binds 4 and opts into 4 (`gibbs-ionic`, `trim-classical`, `opening-proportion`,
`facade-classical`, all from `georgian-colonial-american`), receives 26 more by cascade and has 1
withheld. Its dossier lists identify, lineage 5, kit 94, proportions 35, plans 11, rules 5, faults
206 and evidence 57, and its faults partition as 8 verdicts here + 23 lineage + 175 universal =
206, the contract's own figures. Over all 164 nodes the omission rule alone produces the
rank-awareness the contract asks for — traditions list 3 sections, families 4 or 5, styles 8 or 9,
variants 8 — with no rank table anywhere.

**7. `dist/orders.html` embeds `trim-classical`'s module block and will gain `equals` the next time
`render_orders.py` runs.** Not regenerated here: it is outside this package's files and no check
compares it with its sources.

**8. Five of the package's own guards were blind on the first mutation sweep, and one of the five
is code that cannot be told apart rather than a guard that failed.** §IV.

**9. A sibling agent's harness overwrote this package's harness in the session scratchpad.** The
scratchpad is shared by every Phase 14 agent in the session, and another package wrote its own
`mutate.py` to the same path between two of this package's runs. Nothing that mattered was lost —
the overwrite landed after the second batch had printed its verdicts — but a harness named
generically in a shared directory is the concurrency hazard WP-13.9's audit recorded for a shared
checkout, one directory over. The harness was re-created in a subdirectory of its own, asserts
which worktree it runs in, and the whole sweep was re-run from there before any verdict below was
written down.

**10. One server test fails in every checkout whose directory is not named
`Traditional-Design-Language`, and it is not this package's.** `test_parti_confinement.py`'s
`up-and-back` escape target is `../../Traditional-Design-Language/schema/brief.schema`, resolved
from `partis/`, so it names a real file only where the repository's own directory has that name. In
an agent worktree it resolves to `.claude/worktrees/Traditional-Design-Language/…`, which does not
exist, and the guard-on-the-guard correctly reports that the case cannot distinguish confinement
from a miss. The test file is untouched here and reads nothing but that path, so it fails
identically in every agent worktree on any commit; from the main checkout, whose directory has the
name, the same arithmetic lands on `schema/brief.schema.json`, which exists. A guard whose
premise is the name of the directory it was checked out into is not reported further here, because
the fix is not in this package's files.

## V. What was deliberately not done

- **MCP parity.** `mcp_server/core.py` is untouched and its payloads are byte-identical; whether
  `tdl_get_proportions` should serve a stackless pack's assemblies is the open question named in
  finding 5.
- **No other pack declares `module.equals`.** Which packs' modules are building inputs is
  `oq/which-packs-module-is-a-building-input`; a declaration is added only where a pack's own
  record says so, and `trim-classical` is the one that does.
- **`DOSSIER_SECTIONS` is not added to `citations.py`.** That spelling belongs to another package.
  Until it lands, `corpus.dossier_sections()` reads the real one if it exists and otherwise carries
  the nine ids as a named fallback, and the agreement test holds the fallback to whichever real
  spelling exists — reporting COULD NOT EVALUATE, never a pass, while neither does.
- **`dist/orders.html` is not regenerated** (finding 7), and **finding 10's test is not touched**.
- **The full `check_all.py` was not run**, per the package's brief; the pieces it names were.
- **No new open question is filed.** Both questions this package meets already have entries.

  `oq/mcp-proportions-serve-no-assemblies-for-non-order-packs` in plain text, as the brief asks,
