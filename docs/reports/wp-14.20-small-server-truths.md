## I. What was built

**1. `/api/health` states the session, and the signed-out boot asks nothing gated.**
`workbench/server/app.py`'s health route gains ONE key, `session`: `auth.authorised(request)`,
the gate's own answer to whether this request may pass, and not a second reading of the cookie.
It is a bool about the request it answers, so it reveals only the caller's own state; the route
stays ungated and `auth.OPEN_PATHS` is unchanged. On a server with no gate every request passes,
so it reads `true`, and `auth.required` beside it says why.
`App.jsx`'s `boot()` reads it: where health says a password is set and `session` is `false`, the
Gate shows and **no gated route is called** — until now the boot learned the lock by probing
`/api/overview` and taking the 401, one gated request on every signed-out visit. The probe is kept
only for a server that does not state `session`, where a real request is still the only way to
find out.

**2. An evaluation names its plan** (`oq/an-evaluation-whose-check-errored-names-no-plan`,
closed on its answer 1). `workbench/server/evaluate.py` writes `out["plan"]` when it builds the
response, BEFORE the early return a check that errored takes, so the route names the house on
exactly the path `plan_check` cannot. `workbench/app/src/journey/journey.js` gains
`evalPlanOf(lastEval)` — the route's id first, the check's own second — and both sites that match
an evaluation to a plan read it: `journeyState` and `App.jsx`'s stale-evaluation clear.
`core.check_plan`'s payload, which the MCP tool serves, is untouched.

**3. The two raw fetches go through the client.** `KitSurface.jsx`'s slot read (which also put the
style and slot ids from the URL into its path unencoded) and `Proportions.jsx`'s pack list call
`api.kitSlot` and `api.proportionPacks`, two functions APPENDED to `api/client.js` with no
existing one edited. Both now pass through `noteUnauthorized`, so an expired session raises the
Gate on those surfaces, where it used to leave an empty slot panel and an error line with nothing
to sign in from; the slot path is `seg()`-encoded; and the Kit's read joins the client's GET cache.
The Proportions error line stays, now in the client's words (`GET /api/proportions → 401` where it
said `HTTP 401`).
`src/no_raw_fetch.test.mjs` walks every app source and allows a network call (`fetch(`,
`new EventSource(`, `XMLHttpRequest`) only in `api/client.js`, a named allow-list of one.

**4. The sixteenth carries into the foot.** `build/proportion_engine.py::_fmt_in` and its port
`workbench/app/src/fmt.js::feetInches16` printed 23.99 in as `1'-12"`: a sixteenth that rounded up
carried into the inch and stopped. Both now carry a twelve-inch remainder into the foot (23.99 →
`2'-0"`), in one commit, tested ON THE INCH rather than on the sixteenth.

**5. `components/DimensionString.jsx` is deleted.** Nothing imported it (verified by name across
the whole tree, `dist/` excluded), and it carried a second feet-and-inches formatter.

`docs/workbench.md`'s route table names both new keys, `session` on health and `plan` on the
evaluation, so the layer doc describes what the two routes now send.

## II. What was found

**1. PRD §C.4 said a test held `/api/health`'s KEYS, and no test read them.** The PRD row reads
*"`GET /api/health` — its keys and its `counts == core.overview()["counts"]` | held by
`test_glossary_routes.py`"*; that file asserted the counts and that no `glossary` key exists, and
nothing about the key set. The freeze was a claim with half an assertion behind it. The re-cut
therefore had nothing to widen and pins the keys for the first time:
`test_health_keys_are_tranche_ones_plus_exactly_the_keys_lifted_by_name` holds the body's key set
to the ten tranche-1 keys plus `HEALTH_KEYS_LIFTED = {"session": "WP-14.20"}` and nothing else.

**2. The byte-stability of health, measured against a control rather than asserted.** The route
was run in three auth states (open, signed out, signed in) on a clean `git archive` of `c1c88f5` and
on this tree, `sha`/`sha_source` excluded because they name the commit: **in all three the body
minus `session` is identical to the base**, and the body grows by 15 or 16 bytes as the route
serialises it (1,145 → 1,160 open, 1,054 → 1,070 signed out, 1,111 → 1,126 signed in) — exactly
`,"session":true` or `,"session":false`. (The first figures taken here were not these; §II.7 says
why they are withdrawn.)

**3. `session` is the gate's answer, and the test that says so reads the gate.** The obvious
spelling — `verify(cookie)` — would tell a bearer-token caller it is signed out while the gate
lets it through, and on a Cloudflare-Access deployment would show the Gate to a browser the proxy
has already signed in. The server test holds every state against what the gate then DOES with the
same client (`session` is true exactly where `/api/overview` does not answer 401): open, signed
out, signed in, a forged cookie, a right and a wrong bearer token.

**4. An errored, unrefused evaluation now reads `evaluated` with nothing counted.** It read
`not yet evaluated`, which was false (the evaluation happened; its check counted nothing). It now
reads plan `evaluated` with all three counts `not counted` — never zero — and the drawings `ready`,
because nothing refused them. Whether the bar should name the error itself is a word the journey
does not have; it is not added here.

**5. The sixteenth carry moved nothing the corpus prints.** Measured before and after over 339
outputs: `proportion_engine.py list`, `show` and `show --rules` for all 57 packs, `compare` over the
order packs, `resolve_kit.py <style> --verbose` for all 164 styles, `render_profile.py`'s report,
a digest of `core.get_proportions` for all 57 packs (what `tdl_get_proportions` serves — `_fmt_in`
is not reachable from `mcp_server/` at all), and `dist/orders.html` after `build/build.py`.
**0 of 339 moved**, across 9,288 inch figures printed. No MCP payload string moved, so no frozen
surface this package does not own was touched. The seven vector-table rows that moved are the
seven whose remainder reaches twelve, and they are the only pinned values that moved.

**6. A carry tested on the sixteenth would have been half a fix.** `divmod(-1e-20, 12)` is
`(-1.0, 12.0)` — `12 - 1e-20` is 12.0 in a double — so the inch reaches twelve with NO sixteenth at
all. The fix tests `whole == 12` after the sixteenth's own carry, and the parity test asserts the
table carries a row reaching twelve that way, so a port carrying only on the sixteenth cannot pass
by the table's luck.

**7. The first two controls were taken against an extract nobody owned, and one of them did not
reproduce.** The session's scratchpad is shared by every agent the session runs, and the folder
this package first extracted `c1c88f5` into had a generic name. By the time it was checked it held
files `c1c88f5` does not: a tranche-2 PRD and a WP-14.16 report that are later than it, and
`surfaces/StyleRecord.jsx`, which it deleted — so some other writer had extracted into the same
path, and when is unknown. The measure of it: the app suite on that folder reads **513 of 515**,
the two reds being exactly the stale `StyleRecord.jsx`, where a fresh extract under a unique name
reads **515 of 515**. Both controls were re-taken on the fresh extract. **The carry's reproduced
to the figure** — 339 outputs, 0 moved, 9,288 inch figures. **The health byte figures did not**:
the uncommitted first draft of §II.2 carried growth of 17 or 18 bytes over bodies of 1,244, 1,152 and 1,214,
which were measured with the default JSON separators rather than the compact ones the route sends,
on a tree whose content is not known. The identity it asserted — body minus `session` identical in
every state — held on both, and is the claim; the byte figures are replaced, not averaged. **A
control is only as good as the certainty that the tree it ran on is the tree it names**, and a
shared folder with a generic name gives none: name the extract after the package and the commit.
