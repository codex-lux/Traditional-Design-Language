# WP-14.11: what an edge carries, and what a fault card answers

*25 September 2026. Branch `wp-14.11`, taken from `0ad8b49`. Scope: PRD
`docs/prd/phase-14-the-dossier-and-the-journey.md` §I.13 and the WP-14.11 section of
`PLAN-OF-ACTION.md`, with finding 11 of `docs/reports/ux-first-principles-2026-09-24.md`. Every
figure below was measured in this worktree, and the base-commit figures on a `git archive` of
`0ad8b49`. Cite this report by filename.*

## What it is for

Two things on screen were false.

1. **What an edge carries.** `EdgeGlyph.jsx` and `Phylogeny.jsx` each carried a table of edge
   TYPES, `CARRIES = { descends_from, regional_of }`, and captioned, grouped and weighted every
   edge by it. The fact is per EDGE, not per type: a `hybridizes_with` edge carries the kit where
   the two kits really blend and carries nothing where they do not. So every kit-carrying co-parent
   was captioned *carries nothing*, listed under *claims only* and drawn light. And the glyph
   printed *browsing only — carries no inheritance* under a filing (`member_of`) edge, which has
   been false since WP-4.2 spliced a style's family into its kit cascade.
2. **What a fault card answers.** Every fault record carries `correct_practice` (the right way)
   and `detection` (how to spot it), and the card rendered neither. And where a style was in view
   the card printed that style's licence under an "exception for" heading whatever the server had
   said about it, so a licence the style is REFUSED and one nobody could judge both read as earned.

## I. What was built

**The carry, read off the served flag.** `lineage/carry.js` is pure and imports nothing. It maps an
edge to one of four glossary ids: `member-of` for filing; `carries-the-kit` where `inherits_kit` is
the boolean `true` and the edge names no slots; `carries-named-slots` where it names a non-empty
list; `carries-nothing` otherwise. It reads the flag STRICTLY (a string `'true'`, a `1` or an object
is not a verdict, as `judgment.js` already rules), and `strokeOf` gives the line its weight from the
same answer and never from the type. `glyphEdge` renames a served `/api/phylogeny` edge (`from`,
`to`) into the glyph's keys; `filingEdgeOf` makes the filing edge from a taxon's `member_of`;
`groupByCarry` groups by the carry word.

**`EdgeGlyph.jsx`** takes `{ edge, width, style }`, PRD §I.13's props. The carry word is a literal
`<Term id=…>` per branch, the verb is `<Term field="lineage.type" value={type} />`, the target and
each named slot are `RecordLink`s (name first, id beside it). There is no caption string in the
file; `lineage.test.mjs` reads the file's live source to keep it that way. Both tables are gone.

**The Phylogeny** filters the drawn tree with `carriesKit`, draws each path at the weight its flag
states (and publishes `data-edge-from`/`-to`/`-type` so the walk can read it), and its panel's
lineage is one `Lineage` section: the filing edge first, then one group per carry word, each edge an
`EdgeGlyph`. `phylo/MapView.jsx` weights its arcs the same way and lost the `carries` prop.
`TRADITION_HUES` and `traditionOf` are IMPORTED from `styles/taxa.js` now; `styleTree.test.mjs`'s
copy-equality guard is re-cut to "`Phylogeny.jsx` imports it and holds no copy". The panel's
eyebrows moved from `tone="quiet"` to the default, and the time-axis eyebrows wrap.

**The Style Record's call** (`StyleRecord.jsx:217`, the one line this package owns in that file) is
`<EdgeGlyph edge={e} width={44} />`. `e` is the record's own lineage item, and `/api/styles/{id}`
serves those items with the normalised flag (measured: `regional_of` and `descends_from` items read
`inherits_kit: true`), so both surfaces give one word per edge; a test holds the raw record and the
served edge to the same carry word on all 476 edges.

**The fault card.** `faults/licence.js` is pure. `FAULT_CARD_ORDER` puts `correct_practice` and
`detection` first, then the licence, then symptom, cause, rule, fixes and the machine test last.
`licenceOf(fault, styleInView)` reads the SERVER's verdict, `for_this_style.exception.granted`
(`core.grant_exception`, WP-8.4), and never collapses it: only the served words `granted` and
`refused` are those verdicts; a missing card, a card about another style (a fetch still in hand from
the previous style), or any other value is `unjudged`. `FaultCard.jsx` renders the sections in that
order, prints the verdict through the literal glossary ids `exception-granted`,
`exception-refused` and `judgment-unjudged`, the server's reason (`granted_because`) beneath it, and
frames the licence by verdict — gilt where earned, the plain rule where refused, the unjudged hatch
where nobody could say. The file names are unchanged, because tests read them by path.

**The Fault Corpus draws only the answer to the latest question.** See §II.4.

**The glossary.** `glossary/section-members.json` said filing "passes nothing down" and "carries no
inheritance". Its definition, surface line and basis now say filing is for finding things and not
descent, and that a family's own kit does reach the styles filed under it, quoting the schema,
`docs/inheritance.md` and `build/build.py`. `check_glossary.py` verifies all 480 quotations.

**Tests.** `src/lineage.test.mjs` (10) and `src/faultCard.test.mjs` (5), top-level, `node:fs` only,
every expectation derived from `styles/*.json`, `faults/*.json`, `glossary/*.json` and the server's
own source. The 42 is DERIVED, never pinned: the test computes the edges the old type table and the
served flag disagree on and asserts they are exactly the kit-carrying co-parents.

**The walk.** Three blocks: the Phylogeny lineage (after the phylogeny shot), the fault card's
answers-first order (in the Fault Corpus block), and the licence verdict (appended). Each reads the
page and holds it to the API; the lineage block's reading of the flag is deliberately a second one,
written in the walk and not imported, so it cannot agree with a defect in `carry.js`. The taxa and
the faults it reads are found in the payload, never named.

## II. What was found

**1. The finding, re-derived.** `/api/phylogeny` serves 476 edges. The type table and the served
flag agree on 434 and disagree on exactly 42, every one a `hybridizes_with` edge that carries the
kit: 40 the whole kit and 2 only the slots they name (`monterey-colonial → new-england-colonial`,
`octagon-house → italianate-american`). The inverse error — a table saying "carries" over a flag
saying "no" — is empty, because every `descends_from` and `regional_of` edge carries by the server's
rule. 15 `hybridizes_with` edges carry nothing, which is why no table keyed on the type can be right.

**2. The filing caption was false, and so are two sentences the glossary quotes.** `README.md:24`
("It exists for browsing and nothing else.") and `docs/model.md:16` ("It does not carry
inheritance.") predate WP-4.2's family splice. They are NOT corrected here, because three glossary
records quote them verbatim — `member-of` and `section-members` noting that the sentences predate
the splice, and `surface-style` quoting the README's as a basis with no such note — so correcting
the prose dangles three quotations `check_glossary.py` verifies, and `surface-style` is not this
package's record. The prose and the three quotations must move in one commit; that is WP-14.15's
"prose no checker reads", with the quotations as the part a checker does read.

**3. Sixty-eight licences read as earned that are not.** Asked of `core.get_fault(id, style)` over
every licence written for a real style: **838 licences, 770 granted, 18 refused, 50 unjudged.** The
card printed all 838 the same way. (8 more licences name a `construction:`/`region:` pseudo-id
rather than a style and are not reachable from the style picker.)

**4. The Fault Corpus drew a fault the address does not name, and has since before this package.**
The walk's refused-licence check went red on its first run with NO licence on the card, and the card
was not the fault asked for. A move to a new fault and a new style changes both in one navigation;
`FaultCorpus.jsx`'s fetch effect runs once for the style (with the OLD fault still in `id`) and again
for the fault, so two requests are in flight and whichever resolves LAST is drawn. Measured with a
probe that logs every `/api/faults/` request and reads the card's heading:

- on this tree, unforced, the stale answer won 2 runs of 5 — the walk's own and the first probe's;
- on a `git archive` of `0ad8b49`, unforced, 0 of 3 — but the stale request
  (`newel-too-thin?style=beaux-arts-american`) was sent on every run;
- forced, by delaying the stale response 600 ms, **both trees** drew *The Newel That Cannot Be
  Leaned On* under an address naming `surround-that-lies-about-the-wall`, and kept it.

So the race predates the package and the package's check is what could see it, because a card
of another fault under this address carries another fault's licence verdict. The effect discards a
superseded request now (its assets with it). The walk reads the card's own `data-fault` before
anything else, and a last check FORCES the stale answer to land last (a `page.route` delay on the
fault on screen), so the guard does not depend on the machine's timing to bite. The probe, re-run
forced against the fixed build, keeps the addressed card.

**5. A fourth copy of the table survives, in a file this package does not own.**
`StyleRecord.jsx:18` declares `CARRIES = { descends_from: 1, regional_of: 1 }` and line 228 colours
each DESCENDANT by it, so a style that took this one's kit through a `hybridizes_with` edge is drawn
as though it took nothing. And it cannot simply read the flag: `/api/styles/{id}`'s `descendants`
serve `{id, type}` and no `inherits_kit`. The file is WP-14.12's to replace and its lineage section is
to be EXTRACTED unchanged, so the defect travels into the dossier unless the server serves the flag
on each descendant and the extracted section reads it. Not done here; named for WP-14.12.

**6. The Phylogeny's panel shows no edge note and the Style Record's does.** `/api/phylogeny`
serves no `note` on an edge, so the same edge carries its note on one surface and not the other.
`glyphEdge` passes a note through where one is served. Not changed.

**7. A scoped edge's slot list can be a paragraph.** `octagon-house → italianate-american` names
seventeen slots, each a link with its id beside it; in the Phylogeny's narrow panel it reads as a
dense block. Every slot is a real, followable record and none is hidden. Not folded.

**8. Two comments of mine overclaimed.** They said the `member-of` record "says both halves" — that
filing is not lineage and that it is not inert. It says the first and claims nothing about the
second, which is why its word is the right one to print; the second is `section-members`'. Found by
reading the record again while writing this report; corrected in `9cdffbb`.

## III. What was deliberately not done

- `README.md:24` and `docs/model.md:16` — §II.2.
- The Style Record's descendant colouring and the server's descendants payload — §II.5.
- Edge notes on `/api/phylogeny`, and folding a long slot list — §II.6, §II.7.
- No server route, no fault or style record, and no file owned by WP-14.9, 14.10 or 14.12 was
  touched beyond the one `StyleRecord.jsx` line. `FaultCorpus.jsx` was touched because the verdict
  this package prints is only honest on the fault the address names.
- The section labels "the right way" and "how to spot it" are app-written, as the card's other
  section labels are; they are not glossary records.
- No new open question. §II.2 and §II.5 are defects with an obvious repair and an owner, not
  questions needing a ruling.
