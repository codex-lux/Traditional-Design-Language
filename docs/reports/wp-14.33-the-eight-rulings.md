### VI.3 Found while fixing, and not by any auditor

- **Three test files stripped comments with one regex that read a string as a comment.** In
  `Transcription.jsx`, `accept="image/` + `*"` opened a "comment" that ran to the next star-slash.
  79 of its 576 lines went unread by the title, count, prose, history and ink scanners. This is

- **And the new lexer had a hole of its own, which shipped in `6625b64` and was fixed in
  `5155347`.** Looking back from a `<`, it read a comment's closing slash as a division, so JSX after
  a comment in expression position went unread: 7 elements in 4 files. The first Babel comparison
  checked paragraphs, and none of the seven held one, so it agreed. `6625b64`'s message says the
  comparison proved "the lexing and the element tree"; it had not compared elements. The refusal
  guard found it, because Transcription's refused ingest was one of the seven. The comparison now
  counts elements: all 2,496 agree, as do all 2,867 comments.
- **The clickable reader's first version could not see FindingRow's
  `createElement(onCite ? "button" : "span", …)`.** Its own first run found this.
- **SlotRow's and FindingRow's first conversions** kept a conditional colour that beat the link
  class's hover. The override check found them.
- **The walk on the audited tree went red on a check about code nothing had touched**:
  *"picking a candidate's column writes it in the address"*, WP-14.27's. It passed in five earlier
  walks. It is a race in the instrument and not a defect. `nav.select` pushes with
  `location.hash = …`, and the column is marked on the asynchronous `hashchange` that follows, so
  the address is written a frame before the page. The check waited on the hash and read the page
  ONCE. A probe composed a set and picked each column four times. The mark was absent at that
  instant in 15 of 16 picks and present about 20 ms later in all 16. No pick was left unmarked.
  The check now waits for the mark, bounded at 5 s. With the mark mutated away and the app
  rebuilt, the waited read reports "never selected" on 4 of 4 picks, so it still bites. The file
  was restored byte for byte and rebuilt. Swept: this is the only check in the walk that waits on
  the address and then reads the page once. Every other pick check waits for the page and reads
  the address, which is safe because the address is written first.
