# WP-14.0 — the control, before anything moves

*Phase 14, package 0. Measured 20 September 2026 on an isolated `git archive a0c4fca` checkout.*

**Six test ids in four files are RED on this branch before Phase 14 touches anything.** This
package establishes which, with each failure's own message, so that every later package in the
phase can be attributed against it rather than against a memory of it.

The reason this is a package and not a paragraph is `CLAUDE.md`'s own finding, recorded against
WP-13.5: **a test already red for cause A cannot report cause B.** WP-13.5 attributed its reds to
the previous package by name, and in doing so absorbed a second, different regression in silence.
A phase that is about to move every published composer figure cannot afford that.

## The measurement

    cd <git archive a0c4fca checkout>
    python3 -m pytest tests/test_composer.py tests/test_score.py \
                      tests/test_parti_composability.py tests/test_solver.py -q --no-header -rf

    6 failed, 74 passed, 2 skipped in 810.27s (0:13:30)

**It was run twice and the second run is the one quoted.** The first ran in the working tree and
straddled my own edits to `build/compose.py`; this repository records that trap in its own words
(*"the first full run straddled this package's own doc edits and was killed rather than quoted"*),
so it was re-run on a checkout nothing could touch. The two agree exactly — same six ids, same
messages, 814.51 s against 810.27 s. **That agreement is the finding, not the pass:** a
contaminated run that happens to be right is indistinguishable from one that is wrong, and the
only way to tell was to spend the thirteen minutes.

## What each one is, and it is not one cause

Rows 2, 3 and 4 are **one finding through three readers** and it is already recorded:
`oq/the-composer-returns-a-set-that-satisfies-neither-must-have-room`'s amendment traces
`centre-passage-double-pile` from fatal 0 at `840c7f1` to fatal 4 at `1392439` and measures it out
of the returned set entirely. The composer still computes the right answer (69.7 against the
returned leader's 56.5) and no longer returns it, because `_sort_key`'s primary key is the fatal
count and Phase 13 raised that count on exactly the native diagram. Counting these as three
regressions would triple one.

Row 1 is the same cause one step earlier — the fatal count on a directly instantiated parti, not a
returned one.

Row 5 is `oq/a-side-hall-front-is-convicted-by-a-band-written-for-centred-fronts` and row 6 is
upstream's reworded `CARRIED` constant, which `CLAUDE.md` records against the 16 September merge:
the message moved and the pinned literal did not. **Neither is Phase 14's and neither may be made
green by weakening what it asserts.**

## What this licenses

Any later package in this phase may say *"not mine"* about one of these six **only** by quoting
the row above and showing the message is character-identical. A seventh red, or one of these six
with a different message, is the package's until proved otherwise.

It also sets a prediction WP-14.2 has to meet. WP-14.2 changes `compose()`'s **revised** path
only; rows 2, 3 and 4 call `compose(..., revise=False)`, row 1 calls `instantiate` and
`PC.check` directly, row 5 shells out to `check_partis.py` and row 6 is the solver. **All six
should be unmoved, to the character.** That is measured in WP-14.2's own report rather than
assumed here.
