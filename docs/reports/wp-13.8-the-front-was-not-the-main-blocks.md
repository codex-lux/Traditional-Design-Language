# WP-13.8 — the entrance front's population was not the main block's

*17 September 2026. Branch `claude/chomsky-plan-coherence-u6s9wv`. Every figure below was measured
on this tree against a `git archive HEAD` control run through the same harness; nothing is quoted
from another report. Cite this report by filename (OQ 90).*

## What was wrong

`axis.front_openings` swept every room on the level and kept every window and exterior door whose
`wall` is the entrance front, **with no element filter of any kind**. That was harmless for as
long as every plan in the corpus was one rectangle. WP-13.5 tagged
`plans/tidewater-georgian-careful.json` with a west dependency, and from that commit the wing's
four south-facing openings were part of the main block's front:

    breakfast  window  -27.905 ft      main block: x 0 .. 45, centre 22.5
    kitchen    window  -18.405 ft      hyphen:     x -7 .. 0
    kitchen    door    -14.405 ft      dependency: x -34 .. -7
    kitchen    window  -10.405 ft

Every coordinate negative, on a block that starts at 0. Two layers convicted them:

- **`axis.mirror`** reflected each about `footprint_centre` (22.5 ft), found that the twin would
  have to stand between 55 and 73 ft on a 45 ft block, and returned all four as `unmatched`.
  `elevation.py:1646` turns that count into
  `count_of_openings_without_a_mirror_twin_about_the_facade_centreline`, which
  `faults/one-bay-symmetry-break.json` tests `at-most 0` at severity **fatal**.
- **`facade.compare`** emitted four `front-opening-in-no-bay` minors naming the same four, each
  saying truthfully that the opening is *"more than half a bay from every one of the 5 bay centres
  the plan implies"* — true, and not a fact about the house.

A wing's window measured against the main block's centre line is a defect reported where none is
possible: the OQ 52 family, and the ninth site of the same blindness
(`oq/the-facade-layer-counts-a-dependencys-windows-as-bays-of-the-front`, raised by WP-13.5).

**`footprint_centre` IS NOT TOUCHED AND MUST NOT BE.** Its own docstring says it reads the main
block *"ON PURPOSE and is not in that list"* — a centre-door diagram's centre line is the block's,
and a centre taken over the built extent would move with the wing. The centre line was always
right. What was wrong was the population measured against it. Reading that docstring before
touching the file is what kept this package to one function.

## What was built

`build/axis.py` loads `build/elements.py` — the corpus's one reader of which massing element a
room stands in, a pure leaf (it imports `math` and nothing else), already read by `openings.py`,
`structure.py`, `export_ifc.py` and `render_plan.py`. `front_openings` decides the bucket **once
per room** and returns three populations rather than one:

| key | what it is |
|---|---|
| `openings` | the main block's front — what every caller judges |
| `off_the_main_block` | each opening with the element it stands in — **reported, not judged** |
| `element_unresolved` | a room the element model cannot place — neither, and never defaulted |

`declared_but_unplaced` is bucketed the same way, with the wing's counted separately, so the two
numbers on one row mean one thing each.

Three consumers inherit the corrected population with no change of their own: `facade.compare`,
`elevation.py`'s mirror measurement, and `plan_check.py`'s findings. Two needed a change:

- **`axis.door_bay`** now has two messages where it had one. A house with no front door and a
  house whose only front door stands in a wing are different situations, and handing the second
  *"no exterior door is placed on the S front"* is a true sentence about a different house —
  WP-11.4's *"a refusal with one message for three causes has stopped being one"*.
- **`build/diagnose_sheet.py` carried a SECOND SPELLING** of the population — same field, same
  default, same `positions_ft` rule, same blindness — so its table over-counted the ground front
  by the wing's four. It takes `axis.front_openings`' answer now and keeps its own per-storey rows
  and storey-over-storey alignment, which `axis` does not compute. One rule, one spelling; a
  different question keeps its own code. It **reports** what it set aside rather than quietly
  shrinking, because a diagnostic whose count falls in silence is the fake-unjudged shape in the
  one surface a reader opens to find out what the sheet shows.

## What it did NOT do, measured before the work and confirmed after

**The fatal does not clear on any record.** This was predicted by simulation before a line of code
changed, and the prediction reproduced exactly:

| record | population | mirror `unmatched` (fatal at `at-most 0`) |
|---|---|---|
| shipped `tidewater-georgian-careful` (heuristic) | 9 → 5 | **7 → 3**, still fires |
| composed `centre-passage-double-pile` (placed heuristic) | 5 → 4 | **3 → 2**, still fires |
| composed `side-hall-townhouse` | 6 → 6 (one element) | 4 → 4, unmoved |

The main block's own front really is asymmetric on the search placement — 10.95, 16.95, 27.21,
35.98 and 40.49 about a centre of 22.5, where only 16.95 ↔ 27.21 pairs within the 1 ft tolerance —
and the fault is right about that. **Removing a false conviction is not the same as clearing a
true one.** The plan this package was written to said the fix would remove "half of what pushed
`centre-passage-double-pile` out of the composer's set"; that was wrong, it is corrected here, and
the diagram does **not** return to the set. Its fatal count is unchanged at 4.

## The corpus control

Per-plan findings digest on `engine="heuristic"` (deterministic), same harness on a
`git archive HEAD` checkout and on the working tree:

**15 of 16 shipped plans byte-identical.** The one that moves is `tidewater-georgian-careful`, the
only one of the sixteen that carries element tags — 209 → 205 findings, **minor 107 → 103**, with
fatal, serious and info all unmoved. Every moved row attributed by name rather than by count:

    REMOVED  minor|drawn|front-opening-in-no-bay|breakfast  @ -27.905
    REMOVED  minor|drawn|front-opening-in-no-bay|kitchen    @ -18.405
    REMOVED  minor|drawn|front-opening-in-no-bay|kitchen    @ -14.405  (the door)
    REMOVED  minor|drawn|front-opening-in-no-bay|kitchen    @ -10.405
    CHANGED  fatal|fault|The Bay That Broke the Symmetry:  7 against at-most 0  ->  3
    CHANGED  info |drawn|drawn-facade-symmetry-unjudged:   3 undrawn unit(s)   ->  1

The last two are the richer half and were not visible in the counts: two findings' **figures** are
corrected. Two of the three declared-but-undrawn front windows the `info` line was counting were
the wing's, so a reader was being told the main block's symmetry could not be judged for units
that are not on it.

`front-bay-with-no-opening` is **unmoved at 2 on the ground and 3 above**, which answers the open
question's third question: the wing's openings were never within half a bay of any of the block's
centres, so they filled nothing and their departure empties nothing.

## The ruling, and the corpus sentence that argues against it

The open question's own *"What must not be done"* reads *"Do not silence the finding by filtering
`front_openings` to untagged rooms before the ruling"*, on the grounds that
`groupings/dependency-and-hyphen.json` states *"The dependency repeats the main block's window
proportion and cornice at reduced scale. It is subordinate, not different."*

The question was put to Lucas and answered — reported, not judged, chosen over a rhythm per
element and over dropping them silently — so the ruling exists. **But it was put without that
sentence in front of him, and that is this package's own defect.** It is written into the
question's amendment rather than left in a paragraph nobody re-reads, with the reading this
package acts on stated so it can be attacked: the sentence is about a window's PROPORTION and the
CORNICE, and says nothing about bay rhythm or about mirroring; *subordinate, not different* is a
claim about likeness, not about a shared bay grid. Nothing here touches proportion or cornice.

Reversing it is cheap — one function, two additive keys, 15 of 16 plans already byte-identical —
and `off_the_main_block` is exactly the population the other reading would need.

## Guards

`tests/test_front_population.py`, ten assertions, all driven: fifteen of sixteen shipped plans are
one rectangle, so the branch that matters is unreachable on them and a guard that runs only where
the bug cannot occur is not a guard. The fixtures are hand-built on WP-11.10's precedent with the
**dependency at negative x on purpose** — the defect published negative coordinates, and a fixture
with both elements at positive x lets a wrong answer look plausible. The main block's two front
windows are placed symmetrically about its own centre, so a falling unmatched count can only be
the wing leaving.

Three guards are worth naming:

- **`_blind_sweep`** is an independent element-blind reader kept in the test file, so the
  one-rectangle assertion compares against something that is **not** the function under test.
- **`test_a_record_with_no_footprint_is_not_filtered_rather_than_filtered_to_nothing`** — refusing
  to filter is not the same as filtering to nothing, and the difference is a whole front. Without
  the guard, `elements()` returns `[]` on a record stating no width, every room falls to
  `element_of() is None`, and the front comes back EMPTY: a new defect of exactly the kind this
  package removes, introduced by its own fix.
- **`test_some_shipped_plan_states_a_container_so_these_fixtures_are_not_redundant`** asserts the
  premise. Until WP-13.5 no shipped plan carried a tag and this whole file would have been about a
  case the corpus cannot reach; if that stops being true again, it says so rather than going
  quietly redundant.

**Six mutations, all RED from a green baseline, none blind**, each asserted to have landed by
read-back and each file restored against a sha256 taken first: the filter reverted; a room in no
element defaulted into the main block; a footprint-less record filtered to nothing; the off-block
openings dropped rather than reported (the answer Lucas declined); `door_bay`'s wing branch
removed; and `diagnose_sheet` spelling the population again. The first turns 7 of 10 red, which is
the shape a real revert should have.

## Deliberately not done

- **The other three fatals stay, and they are not this package's.** *The Front With No Centre*
  rides on `upper_floor_opening_count`, which `elevation.py` derives over the main block's face —
  `oq/the-elevation-draws-the-main-blocks-face-and-not-the-buildings`, where what an elevation of a
  five-part house IS needs a ruling and not a repair. *The Truss Default* at 0.4066 is
  `oq/the-depth-a-roof-needs-is-known-and-cannot-be-enforced`.
- **`compose._sort_key` is untouched**, and so is every fault band, threshold and severity.
  Whether a fatal from an instrument with an open question against it may disqualify a candidate
  at all is Lucas's, and is the open half of
  `oq/the-composer-returns-a-set-that-satisfies-neither-must-have-room`.
- **No gate row re-baselined, no ratchet loosened, no test made green by weakening it.**
