# WP-14.18 — proportions served whole

**Status: built, on the worktree branch `worktree-agent-af7312a9f5c5d8856`, cut from `f0dc52a`.** Every figure below was measured on that
base plus this package's working tree, on 25 Sep 2026, unless it says otherwise. The contract is
`docs/prd/phase-14-tranche-2.md` §C.3 and §C.4, on the three rulings of 25 Sep recorded in
`oq/mcp-proportions-serve-no-assemblies-for-non-order-packs`,
`oq/which-packs-module-is-a-building-input` and `oq/casings-are-measured-across-and-drawn-upright`.

**THE FREEZE THIS PACKAGE LIFTS, BY NAME.** Tranche 1 held every MCP payload byte-stable. The 25
Sep ruling lifts that for ONE payload and this package changes it: the `tdl_get_proportions`
payload (`mcp_server/core.py::get_proportions`) for a pack with no order stack. It also changes
that tool's signature and docstring (`mcp_server/server.py`) and the workbench's
`/api/proportions/{pack_id}` route (`workbench/server/app.py`), which are the same payload served
two ways. **Every stacked pack's payload is byte-identical to the base**, and a digest pin holds
that (§III). No other frozen surface is touched.

## I. What was built

1. **The schema.** `schema/proportion-pack.schema.json`'s assembly object admits `axis`
   (`up-the-wall` | `across-from-the-jamb`, absent meaning up-the-wall) and `zones`
   (`[{name, to_parts}]`, at least two, each ending at a running member total in parts).
   `additionalProperties` stays false. `module.equals` widens from `ceiling_height` to
   `ceiling_height`, `storey_height`, `room_width` and `opening_width`, the four building
   dimensions the engine binds, and its description is general now rather than
   `trim-classical`'s. **The schema carries no version field**, so the version bump the casings
   question's answer 1 anticipated had nothing to bump. Both new fields are optional, and no order
   pack declares either.
2. **The checker.** `build/check_orders.py::assembly_declaration_errors(pack)` sits beside the
   assembly sum check, which already reads every pack, and `check_pack` calls it. It holds four
   rules. Zones strictly increase. Every `to_parts` is a running member total at a member
   boundary. The last zone ends at the assembly's whole height in parts. An assembly with
   `sums_check: false` declares no zones. Every error names the pack, the assembly and the zone,
   and the member-boundary error prints the running totals it was held against. 57 packs, 0 errors.
3. **The data**, only where the pack's own words give it:
   - `trim-classical`'s three casings take `across-from-the-jamb`. The basis is each reveal
     member's own note, quoted in full:
     `casing_georgian`, *"This assembly is measured ACROSS the casing from the jamb outward rather
     than vertically; height_parts is therefore a width."*; `casing_federal`, *"Measured across
     the casing, as in the Georgian assembly."*; `casing_greek_revival`, *"Measured across the
     casing, as in the other two families."*
   - `wall_section_georgian` takes zones pedestal 4, wall field 16, entablature 19, from the
     module note's *"Pedestal 4, wall field 12, entablature 3."* (and the pack's `notes`,
     *"the wall divides 4 : 12 : 3, in nineteenths"*, and its invariant `4 + 12 + 3 = 19`). The
     boundaries were verified before they were written: the running totals pass through 4
     (after `geo_surbase_listel`), 16 (after `geo_wall_field`) and 19 (after
     `geo_cornice_fillet`).
   - `room-harmonic` declares `module.equals: room_width` (§II.1).
4. **MCP parity** (`mcp_server/core.py`):
   - **One spelling of the module binding**, `module_binding(pk, ...)`. `get_proportions` reads
     it, and so does `workbench/server/corpus.py::proportions_with_members`, whose own inline
     copy of the ceiling rule it replaces. An unbound pack is dimensioned exactly as before. A
     bound pack is dimensioned at the caller's figure for the dimension it IS, else at the
     caller's `module` read as that dimension, else at its own `default_size_in`, and the payload
     states which (`module_bound_to`, `module_from`). A contradictory call is refused by name:
     a column diameter on a bound pack, or a `module` differing from the figure given for the
     dimension it is. The workbench route answers 422, not `_ok`'s 404.
   - **A stackless pack lists every one of its own assemblies**, each dimensioned on its own
     (`include=[aid]`, the workbench plate's own call), as
     `{id, height_modules, height_in, members: <count>, axis?, zones?}`. `_assembly_row` is the
     one row builder for both paths, so the stacked and stackless rows cannot drift.
   - **The hint names the pack's own assembly ids.** A pack with none says so, and a stacked
     pack keeps its old sentence byte for byte.
   - **`lower_diameter_in` is withheld** on a pack with neither a stack nor a column, in `core`.
     `build/proportion_engine.py` is unchanged.
   - `tdl_get_proportions` and the route take `storey_height` and `room_width`. The route passes
     `None` for anything not given and lets `module_binding` say what a missing input means, so
     it stopped forcing 108 and 36 on a pack whose module IS the ceiling.
5. **The workbench members route** passes `axis` and `zones` through on each assembly row
   (`corpus._wall_assemblies`) exactly where the pack declares them, and adds the bound dimension
   to `at` where it is not the ceiling or the opening, so a slider driven by `module_bound_to`
   finds its own figure there.
6. **Three glossary records**, glossary 0.1.0 fields only, every one editorial, with its basis
   quoting the schema descriptions this package wrote (and the pack's own notes). They are
   `zone` (proportion, order 11), `assembly-axis` (proportion, order 12) and `figure-drawn-turned`
   (figure, order 2, for the caption WP-14.24 will draw). `check_glossary.py`: 124 records, 490
   quotations verified. Two of the quotes were mutated on a copy of the directory and both were
   refused, one of them under the key path it names as well as by text.
7. **Two new questions, one closed, two amended** (§V).

## II. What was found

**1. Check 19 passes on one of the three class-A packs, and the other two are refused by one rule
each.** `room-harmonic` declares `room_width`. Its name is the room's *"breadth"*, its three
vaulted-ceiling means read `room_width` and `room_length` alone, and every other rule reads
`module` or no variable at all. `storey-graduation` is refused on `belt_course.height =
storey_height + part * 0.6`, and `opening-pointed` on `window_lite_pattern.count = max(2,
round(opening_width / (part * 5)))`. Each rule reads the input and `part` together, and declared,
`part` becomes the input over the parts. **This was measured before it was called a refusal, and
the check is right.** At storeys of 90, 120, 160 and 200 in the belt course sits 96/126/166/206 in
undeclared, 6 in above every storey (the rule's own note says *"about six inches above the top of
the first storey"*), and 94.5/126/168/210 declared, an offset of 5 per cent of the storey. At openings of 27,
36, 48 and 60 in the light count is 2/2/3/4 undeclared and **2/2/2/2 declared**: the rule would be
constant and could never reach its own range of 2 to 4. Both could be dissolved by rewriting the
rule on a fixed length (6 in, 15 in), but each figure exists only as a consequence of the pack's
default module, so writing it would author a number. Stopped there, as ruled, and filed as
`oq/two-class-a-modules-are-refused-for-a-rule-that-reads-the-input-and-its-part`.
`tests/test_module_equals.py::TestTheClassAOutcome` holds the REASON: a copy of each refused pack
with the declaration added is refused on the named rule and on nothing else, so the day a rule
changes the question is named rather than silently overtaken.

**2. The 108-against-114 disagreement was measured on the base before it was declared settled.**
On a `git archive` of `f0dc52a`, `core.get_proportions("trim-classical")` dimensioned the pack's
members at 114 in and evaluated its rules at a ceiling of 108, so the base board rule
(`ceiling_height * 1.5 / 19`) read **8.5263 in** beside members drawn at a 6 in part. On this
tree it reads **9.0** at 114 on both surfaces, the payload saying `module_bound_to:
ceiling_height`, `module_from: default`.

**3. Of the three wall sections, only the Georgian can take the division the pack states.** The
pack states its division once, and it is true of the Georgian wall alone. The Federal section's
pedestal ends at 3.75 parts and its field at 16.25, and no sentence gives its own division, so it
takes none. The Greek Revival's base ends at 1.9 parts because, in the pack's words, *"the dado
has been abandoned and the pedestal has collapsed into the base board"*. That states the collapse
and not a figure, so a zone there would be read back off the members, which the schema's own
description forbids. (The same pack says the Greek base is *"10 1/4 in of plain board"* finished
with *"one small member"*, and records a 10.2 in plinth under two cap members. That is noted, and
nothing was changed for it.) `tests/test_assembly_zones.py` holds the premise both ways: the
Georgian running totals pass through 4, 16 and 19, and the Federal's do not pass through 4 or 16.

**4. Six ORDER assemblies state a division too, and none was given zones.** A finder over every
pack's prose, for number sequences whose running sums land on member boundaries and whose total is
the assembly's, returns six in stacked packs besides the Georgian wall. Four are one-to-one: each
stated part is one member (`vignola-composite` entablature 27/27/36, `benjamin-corinthian`
entablature 31/41/48, `gibbs-doric` cornice 2/4/4/4/4, `gibbs-tuscan` entablature 12/12/18). Two
are substantive: `vignola-corinthian`'s capital (12 : 12 : 12 : 6, the abacus three members) and
its cornice (14.4, 7.2, 14.4 over thirteen members). They were not authored, because `_assembly_row`
would carry them onto a stacked payload and move the pin the ruling asks for. Mutation D5 in §IV
shows it: a VALID zone set on the Corinthian capital passes `check_orders` and turns the pin red.
Filed as `oq/six-order-assemblies-state-a-division-and-carry-no-zones`.

**5. `benjamin-corinthian`'s stack draws Vignola's entablature and its totals report Benjamin's.**
Found while classifying those six: its own `entablature` is 4 modules (28 in) divided 31 : 41 : 48,
while its stack takes `architrave`, `frieze` and `cornice` from `vignola-corinthian` at 1.5 + 1.5 +
2 modules (35 in), and `totals.entablature_height_in` reports 28. One payload holds two
entablatures. That is outside this package and is not touched. It is handed to the lead as a separate task
(the session's task tool timed out twice).

**6. `room-harmonic`'s length is a second quantity nobody binds.** Its width rules generate the
room's length from the module (`module * 4 / 3` and the rest), while its vaulted-ceiling means
read a `room_length` binding that nothing sets and that defaults to 288 in, which is 192 x 3/2
and no other ratio. The declaration did not create this: before it, the module stayed at 192
whatever breadth was given, so the means and the widths already disagreed. It is recorded in the
class-A question's amendment and nothing was changed for it.

**7. Three new glossary records moved the search index, and one of the four prose sites that
state its size is outside this lane.** `check_counts.py` reads the index at 765 against a claimed
762 (3 new records, 0 stale on the base, measured). `workbench/README.md` and `docs/workbench.md`
are corrected. `CLAUDE.md` is not, because this lane may not edit it (§VII).

**8. A slug wrapped across a newline in this package's own new docstring**, the exact shape
`CLAUDE.md` records for the WP-8.5 code span. `check_citations.py` read the left half as a
dangling citation. The docstring now puts the slug on one line.

## III. The digest pin

`workbench/server/tests/test_pack_plates.py::test_every_stacked_packs_mcp_payload_is_byte_identical_to_the_base`
hashes `json.dumps(core.get_proportions(pid, **kw), ensure_ascii=False, indent=1)`, the serializer
the MCP server uses, for each of the **25** stacked packs at seven call shapes: none, a column
diameter, a module, a ceiling with an opening, `assembly='cornice'`, `assembly='capital'` with a
diameter, and `include_rules=False`. That is 175 payloads, pinned at **`7ac8e89730301b1d`**. **The
value was derived first on a `git archive` of `f0dc52a`**, with the same harness and before this
package's core changes existed, and it was reproduced on this tree. The pin's premise is asserted:
the payload count must equal the stacked packs times the shapes. `test_the_pin_can_fail` adds
one key to one stacked payload and requires the digest to move. Mutations C8 and D5 in §IV move it
from the code side and from the data side.

**WP-14.4's guard was re-cut, not re-pinned.** It asserted the MCP payload for `trim-classical`
kept `assemblies == []` and said in its own message that a change had to be ruled in the MCP
question. The ruling came on 25 Sep. The guard fired on this package's first run exactly as
written, and it is replaced by the ruled properties: the stackless listing, the hint, the withheld
diameter, no workbench-only key leaking into the MCP payload, and the tool reading 0 as not given.
