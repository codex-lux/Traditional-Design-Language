# WP-11.15 — the phantom storey the disclosure invented

*8 September 2026. Found while costing WP-11.16 (the record edit that tags the shipped
Tidewater), by tagging the record in a scratch copy and reading what came out.*

`geometry._disclose_spans` published a **30 ft clear span on the upper floor of a single-storey
wing**. The wing has no upper floor. The span is over open sky.

Nothing in the corpus could see it: no shipped plan carries a `block` tag, so
`len(_els) > 1` is false on all sixteen and the defective branch is unreachable.

## I. The defect

WP-11.9 established the rule in one sentence — **an element with no rooms on a level has no
walls on that level** — and its own comment records finding it the hard way, "12 exterior walls
over 0 dependency rooms, phantom structure of exactly the kind this package removes, one level
up."

`_disclose_spans` is WP-11.12's, written three packages later. It built its element map like
this:

```python
els = ({idx: [(e["x"], e["y"], e["W"], e["H"]) for e in _els]
        for idx in rooms_by_level} if len(_els) > 1 else None)
```

Every level, every element. `spans_over_capacity` takes that map **keyed by level** precisely so
this cannot happen, and says so in its own comment two hundred lines above:

> handing level 1 a dependency envelope with no rooms inside it would manufacture exactly the
> phantom span that package removes.

The call site did the one thing the function it calls forbids in writing.

## II. What it published, on a record that tags the Tidewater's service wing

| | level | span | from → to |
|---|---|---|---|
| | 0 | 23.0 ft | −30.0 → −7.0 |
| | 0 | 40.0 ft | 0.0 → 40.0 |
| **phantom** | **1** | **30.0 ft** | **−37.0 → −7.0** |
| **dropped** | 1 | 29.9 ft | 0.0 → 29.9 |

The dependency occupies x −37 → −7. On level 1 it holds nothing: the placer reads a `block` tag
on the ground level only, and every upper room is in the main block at 0 → 40.

## III. THE COUNT DID NOT MOVE, WHICH IS WHY NOTHING CAUGHT IT

The phantom span **replaced** a real one rather than adding to it. Measured three ways on one
placement:

| | n | worst |
|---|---|---|
| as published (all elements, every level) | 4 | 40.0 ft |
| as charged (the search's own map) | 4 | 40.0 ft |
| per level (elements that hold rooms) | 4 | 40.0 ft |

`over_capacity`, `len(marks)` and `worst_span_ft` are **identical** across the defect. Only the
contents differ — and the contents are what `plan_check` names in a finding, what
`critique` classes as `placement`, and what the plate prints in its margin schedule. **A ratchet
on the count could never have failed here**, which is why every assertion in
`tests/test_elements_on_level.py` is about *where* a mark is and none is about how many.

`published == charged` and `charged == per-level` were both measured directly; the first was
False and the second True, which is the whole proof.

## IV. It falsified the promise the function was written to make

WP-11.12's report states the design rule in as many words:

> The finding READS `geometry_report.span_capacity.marks` and does not recompute: these are the
> spans `SPAN_W` charged, and a second computation could convict a placement on numbers it was
> not chosen by.

`_disclose_spans` **is** a second computation — the search builds its own map at
`geometry.py:1984` and this one built a different map from the same elements. So the record
carried a list the placement was not chosen by, under a docstring promising the opposite. The
guard that now holds them together asserts equality against the search's own map rather than
against a remembered number.

## V. FIVE spellings of one rule, one of them wrong and one of them invisible

**This section said "four" until the audit; the fifth is the one that matters**, because the
guard written to assert there were no more reported zero offenders while it sat in the tree.

| reader | before | correct? |
|---|---|---|
| `structure.build_section` | its own comprehension | yes |
| `export_ifc` slab loop | its own comprehension | yes |
| `geometry` search (`_span_elements`) | `{0: [...]}` | yes — the placer tags the ground only |
| `geometry._disclose_spans` | `{idx: all}` | **no — the phantom storey** |
| `render_plan._blocks_here` | a hand-rolled containment test, own `0.5` literal | found by the audit |

`elements.elements_on_level(plan, level_rooms, els=None)` is the one spelling now, a LEAF
function beside `bounds_index`, and four readers were rewired onto it. The search keeps its own
map deliberately: it runs *before* a record exists and holds raw blocks rather than placed
rooms, so it is a different input shape, not another copy of the same expression.

`render_plan._blocks_here` never called `element_of` at all — it compared coordinates directly —
so no guard that looks for that call could ever have seen it. `test_no_module_rederives_element_
membership_in_a_nested_loop` reads the AST for the `element_of(...) is <element>` shape, and
`test_the_renderer_draws_no_element_on_a_level_it_has_no_rooms_on` renders a two-element,
two-level record and asserts the upper plate draws no dependency ring — the property, which is
what a hand-rolled copy can still be caught by.

**The empty-set policy is NOT uniform across the readers, and that is stated rather than
fixed.** `geometry._disclose_spans` charges every element and discloses; `render_plan` falls
back to every block with no disclosure; `structure.build_section` falls back to the main block;
`export_ifc` emits no slab at all. The last two are pre-existing and moving them moves output on
a multi-element record, which is WP-11.16's to measure — but a reader should know the four
disagree, because this package's own comment states a principle only one of them follows.

## VI. The guarantee

**The whole shipped corpus is byte-identical.** All sixteen plans, `engine="heuristic"`,
23 span marks over 13 plans, digest `10c5577097b5ec0e` before and after — measured on the
pristine tree and again on the working tree, not asserted. `over_capacity == len(marks)` on
every one. This is provable rather than lucky: `len(_els) > 1` guards the branch and no shipped
plan has a second element, so the fix cannot reach them.

That is also the reason this is its own package. WP-11.13 ruled that tagging the shipped record
"is a record edit and its own package", and WP-11.9's lesson is that a package which teaches a
layer *and* moves a shipped placement has done two things. This one changes no shipped output at
all; **WP-11.16 is the record edit**, and it can now publish honest spans.

## VII. Guards

`tests/test_elements_on_level.py`, **10 tests** over hand-built two-element records — the
shipped corpus cannot exercise the branch, which is WP-11.10's stated precedent for a hand-built
fixture. The dependency is placed at **negative x** on purpose: the defect published a span at
−37..−7, and a fixture with both elements at positive x would let a wrong answer look plausible.

`test_the_fixture_really_exercises_the_multi_element_branch` asserts both that the fixture has
more than one element and that **no shipped plan carries a `block` tag** — so when WP-11.16
tags one, that assertion fires and sends the next reader here rather than letting the fixture
quietly stop being the only route to the branch.

Mutations, each **asserted to have landed** before the suite was run — a mutation that silently
fails to apply looks exactly like a guard that works, and one of these DID report
"MUTATION DID NOT LAND" after the code moved under it, which is the harness doing its job:

| mutation | result |

| a room in no element votes for the main block | BITES |

## VIII. The full suite came back with one failure and it was not this package's

`check_all` ran **1 of 50 checks failed** — `tests/test_shape_pins.py::test_no_room_is_drawn_
outside_its_own_band_when_the_pins_hold`, on `engine="auto"`. It would have been very easy to
call that nondeterminism and re-roll. It was measured instead.

Sixteen runs of that test alone, **alternating trees to control for machine load**:

| tree | runs | failures |
|---|---|---|
| pristine `85ba5e0` (no WP-11.15) | 8 | **2** |
| working (WP-11.15 applied) | 8 | **2** |

The same rate on both, and the first pristine run in the alternating pass was a failure. The
change cannot reach the placement in any case: its three call sites are `_disclose_spans` (which
runs *after* the solve), `structure.build_section` and `export_ifc`; on a one-rectangle house
`elements_on_level` returns exactly what the comprehensions it replaced returned; and
`CORPUS_PLACEMENT_SHA` and `CORPUS_OPENINGS_SHA` both passed in the same run.

**The discriminator is the solver status, not the machine.** Over five captured solves:

| status | verdict |
|---|---|
| `FEASIBLE — kept polish from the heuristic hint` | passes (4 of 5) |
| `OPTIMAL (hard-only) — kept hard-only phase A` | **fails** |

On the failing solve `chamber3` is drawn **315 sf against 208 declared (+51%)** at a ratio of
1.40 against a 1.35 band — **while `downgraded_shape_pins` is EMPTY**. The record states that
every proportion pin held and two rooms are drawn outside the band those pins assert.

`_absorb` is **not** the grower, which is worth saying because it has undone a proof four times
and would be the obvious suspect: it is called once with `ratios=` populated for every
non-downgraded room, and its `_fits` test would refuse 21 × 15 against a 1.35 ceiling (limit
20.26). The hard-only phase A placement already had that rectangle.

Whether phase A asserts the shape pin **at all** is not established here, and that is the
question's first item: if it does not, the empty `downgraded_shape_pins` is *unjudged reported as
passed* in a new place. Raised as
`oq/a-held-shape-pin-is-not-held-on-the-hard-only-path`, with the measurement, and deliberately
not fixed here — every plausible fix moves a placement, and this package's guarantee is that
nothing shipped moves.

## IX. The adversarial audit, and the five things it found in this package's own work

Four independent read-only auditors were run over the diff — edge cases and call chains, test
meaningfulness by mutation, second-order risk, and a hunt for the same pattern elsewhere. None
was the author of the code. **Every one of the five findings below is in work this session
wrote, and three of them are in the guards rather than the fix.**

**1. `[] or None` dropped a real span, silently. FIXED.** The first draft of this very fix ended
`...] or None`. On a level where every room fails `element_of` the empty list became `None`,
`structure.wall_lines` took its `elements or [(0,0,W,H)]` default — the main block — and a
dependency's own 30 ft over-capacity span **vanished**. Measured: correct 3 marks, the draft 2.
Reachable at 0.51 ft of overshoot, since `elements.TOL` is 0.5 and `_absorb` is documented to
grow a room past its element. **The code this replaced got it right by accident**, never having
produced an empty list at all. An unresolvable level now charges EVERY element and states
`element_membership_unresolved`: over-reporting is the only safe direction, because a false
positive is visible on the plate and a false negative is invisible everywhere. That is this
package's own subject — a false measurement — reintroduced by its own fix, in the opposite
direction.

**2. The anti-duplication guard was a text selector, and a live fifth spelling already existed.
FIXED.** `test_no_module_rebuilds_the_per_level_element_comprehension` matched the source
substring `" is e "` — a **loop variable name with a trailing space**. Three separate evasions
were demonstrated: `structure.py`'s original wraps the line right after `is e`, so the pattern
never matched the copy it policed; renaming `e` to `_el` evaded it; and a fresh copy in another
module passed all eight tests. Its docstring claimed to read the property. **And
`render_plan.py::_blocks_here` was a live fifth spelling all along** — a hand-rolled containment
test with its own `0.5` literal, written by WP-11.9 and citing the very rule it duplicated —
while the guard reported zero offenders. It reads the AST now (an `element_of` call in an
identity comparison, nested in two loops), narrowed to the `is` shape because a first version
convicted `multi_element_disclosure`, which asks the different question "which rooms belong to
each element". `_blocks_here` reads the one spelling, and a **behavioural** test renders a
two-element, two-level record and asserts the upper plate draws no dependency ring.

**3. The element-box branch of `_edge_of` was guarded by nothing (WP-11.14). FIXED.** Deleting it
outright left Python 9/9 and JS 17/17 green: the fixture's kitchen fills its element exactly, so
element face and room face are both 33.0 on all four walls. A room set back 0.4 ft — inside
`_boundary_wall`'s 0.6 ft tolerance — now distinguishes them (33.0 against 32.6), and the window
is not merely moved but **recovered**, which is WP-11.14's own claim reproduced on two
rectangles. Both spellings get the fixture; deleting either branch now bites.

**4. The two renderers disagreed by 50× on what "inside an element" means. FIXED.**
`Sheet.jsx` transcribed the containment test at **0.01 ft** under a comment claiming it was
"`build/elements.py::element_of`'s own rule". `elements.TOL` is **0.5**. Any room 0.01–0.50 ft
outside its block was in its element for `render_plan.py` and in **no** element for the workbench
sheet — the two renderers answering differently the one question WP-11.14 exists to make them
answer once.

**5. And the two spellings rounded differently, found by a guard written for something else.
FIXED.** `render_plan.py` writes every `edge_ft` through `round(edge, 3)`; `derive.js` wrote the
raw float. A room set back a non-binary fraction gave **32.6** in one renderer and
**32.599999999999994** in the other. Live only where a room does not tile its element exactly —
so, again, only past WP-11.16. `edge3()` is the one rounding now.

**What the audit did NOT find:** no performance regression (`elements_on_level` is called **0**
times on shipped plans — the conditional short-circuits; `element_of` counts are 52 before and 52
after; `bounds_index` is once per level, not per room), no new crash through the validated
routes, and no way to break the fix itself. All sixteen plans still hash byte-identically.

**And one deferred item is a precondition for the NEXT package rather than a curiosity.**
`geometry_cp._score` calls `_span_charge` with no `elements=`, so on a CP placement
`over_capacity` and `charge` are computed footprint-wide while `marks` is per element — measured
3 against 4 on a two-element fixture, and on the tagged Tidewater the CP-style charge invents a
30 ft span straight across the hyphen gap. `plan_check` publishes CP's count beside one finding
per mark, and `tests/test_span_findings.py` asserts `len(findings) == over_capacity`, so **it
goes red the moment a tagged plan is CP-solved**. Not fixed here because passing `elements` into
the CP charge changes the prover's objective on multi-element plans, which is a placement change;
WP-11.16 must settle it before it tags the record. The comment in `_disclose_spans` now states
the promise as true of the search path only, rather than of both.

**Deferred, with the reasoning, because each is pre-existing and moves shipped output:** the
pattern hunt found the same *shape* — an element property computed from the footprint with no
reader asking what the other elements do — in `render_plan.opening_gaps`, `Sheet.jsx`'s single
poché ring, `elements.boundary_walls` (no notion of an abutting neighbour), `appendages`,
`threshold`'s stoop, and the roof note. **All are unreachable today and all become live the
moment WP-11.16 tags a record**; that package must budget for them. One is live NOW and was
verified here independently rather than taken on a subagent's word: **the DXF draws 16
ground-floor windows where the sheet draws 15** on the shipped record, because `export_dxf`
spaces windows evenly and tests boundaries against the footprint instead of reading
`positions_ft` — `oq/the-dxf-draws-its-own-windows`.

## X. What this package does NOT do

- **It does not tag the shipped record.** That is WP-11.16. Measured while costing this one and
  recorded here so the next package starts from a number rather than a memory: tagging takes
  `engine="cp"` from **FEASIBLE at the 40 s budget to OPTIMAL in 8.9 s**, objective 541.2 →
  407.8, wall pins downgraded 9 → 7 and shape pins 0 → **1**; on `engine="heuristic"`,
  fatal 8 → 7, serious 65 → 54, minor 83 → 82. **WP-11.13's published "zero pins downgraded" is
  not reproduced** — this tagging downgrades eight — and WP-11.16 must re-derive it rather than
  quote it. It also opens a new fatal (`unreachable: butlers`) and a severed entrance sequence,
  neither of which is a reason not to tag but both of which are that package's work.
- **It does not change the count of anything.** §III; the count was never the defect.
- **It does not touch `SPAN_W`, the 20 ft capacity, or `bearing_lines`' 0.75 ft tolerance.**
- **It does not close OQ 98.** The measurement half stands: `span_check` still credits a bearing
  line across the whole plate however short the wall runs, so every count here is still a floor,
  and `span_capacity.understated` still says so.
- **No new checker**; `TOTAL_CHECKS` does not move.
