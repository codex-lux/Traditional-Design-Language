## I. The verdict

**For what Phase 16 changed: deployment-ready, yes.** Nothing that blocks deployment or is worth
fixing is left unfixed.

- **Five auditors** read and mutated the phase as pushed. Every finding was reproduced first and
  fixed against a clean control, and each fix is guarded by a test that a mutation turns red:
  - sixteen blocking rows and twenty-three minor ones;
  - three more found while attributing the audit's own movement, and one by its whole build. Three
    of those four are fixed (F1, F2, F4), and the fourth (F3) is raised.
- **The rulings are executed as ruled, with one correction.** The placer's order (A1) was no
  ruling's, and it ran R5a backwards.
- **The readings this audit took where no ruling spoke**, U8 to U15, were taken as recommended
  under Lucas's standing instruction of 1 Oct 2026 and never put to him. Each is said where it is
  executed.
- **Deferred, each with its reason:** B7 and B8, the DXF-to-sheet census row, and the plates.
  **Raised:** the census's reach, and the water table above the floor.
- **The whole build is `2 of 54 checks failed`**, the same two checks as at every package since
  WP-13.3. All 20 known ids are red. The two other reds are this package's own, fixed (F4), and a
  prover-band row that passed six times of six alone, alternating the control and this tree.
- **The plates still wait on the network.** All eight hosts refused this workspace again (§VI).

## II. How it was run

- **Five auditors worked `e604955`**, the whole of Phase 16 as pushed, each from its own angle:
  - **A**: the rulings held to the code, one by one;
  - **B**: the verdicts, the measurements and the refusals;
  - **C**: one house on every surface: the sheet, the DXF, the plan, the section, the roof plan,
    the scene and the bench;
  - **D**: what the phase wrote down: records, reports, counts and the derived files;
  - **E**: 45 mutations of the phase's code, in its own worktree, 49 runs with escalations.

  Four read and one mutated, each in its own tree. Each worktree's `git status` was empty when its
  auditor finished. **Every finding was reproduced before anything was touched**, with the
  auditor's own probe or one written for it.
- **The fixes were made in one tree, measured against a control.** The fix tree was a worktree of
  `e604955` plus the edits; the control a clean worktree of `e604955`; and the suites ran in a third
  tree, a byte-for-byte snapshot of the fix tree (`sha256` per file), so a mutation in the fix tree
  could never land under a running suite.
- **What was measured against the control:**
  - every sheet the corpus draws, hashed with `tests/render_digest.py` (208 sheets);
  - every fault verdict on the sixteen shipped plans (3,273);
  - the composer's returned and scored sets on both briefs (`tests/compose_sets.py`), and every
    verdict on the 13 composed Georgian candidates;
  - the census diff against the pinned known disagreements;
  - the placement, openings, sheet and roof digests, each re-derived per plan or per entry on a
    harness first proved to reproduce the old value.
- **Every new or re-cut guard was mutation-checked**: each mutation asserted to land, each file
  restored by its sha256 (§IV).
- **The whole build** ran in fresh `git worktree`s of the final tree, sharded, and every red was
  attributed by test id. Then the server suite, the app suite, the npm build and the walk (§V).

## VII. Traps worth carrying

1. **A fix can carry its own false line, and only a diff against the control found it (F1).** C6
   taught the scene to name the bands it does not build, and named a belt course on six one-storey
   houses. Every assertion about the scene passed. Diffing each moved scene against the control,
   during the attribution and not the fix, is what showed it.
2. **A deferred row in an older report is a finding nobody re-reads (F2).** WP-15.8's audit deferred
   the CAD elevation's missing water table and belt course as row 24, *"out of the phase's scope"*.
   Nothing read the row again until this audit attributed a moved DXF and found no band in it.
3. **A picture is an instrument too.** The first renders of the new DXF bands used ezdxf's drawing
   add-on under a BLACK and a COLOR_NEGATIVE policy. Both painted the wipeouts black and left the
   colour-7 lines invisible, which read as broken masks. The default configuration showed the masks
   correct. Look at the drawing, and then check what drew the picture.
4. **The corpus's one specimen of a state can reach the answer by the other branch (B5).** The only
   hipped house's kit forbids its return, so a hip measured zero returns for the forbidden reason
   and the silent-kit branch was never exercised. WP-11.15's *a fixture where both branches return
   the same number guards neither*, met in a shipped plan.
5. **Keeping a refusal in the drawing is not measuring the feature absent (B1).** A3 keeps a dated
   ban on an undated house, which is right for what is drawn. A count that rests on that refusal is
   not a measured zero. Read as one, it decided `sidelights-as-storefront-glass` on all 13 composed
   Georgian candidates, and convicted undated houses of three first-period styles under
   `return-that-never-returns` (U15).
6. **`node --test workbench/app` is not the app suite.** It reported *"tests 1, fail 1"*. The suite
   is `cd workbench/app && node --test src/*.test.mjs`, as `check_all.py` runs it: 766 of 766.
7. **A re-cut that disables a block with `if False:` can leave its `else` running.** The first
   re-cut of `test_detection.py` did. The old block was removed whole.
8. **A guard that reads every test file's source belongs in every targeted run (F4).**
   `test_determinism.py` scans the tests for a patch-then-solve without a private cache, so a change
   to any test file can redden it. The targeted runs took the files this package touched and not
   that one, and the whole build is what found it: WP-14.33's patch-then-solve trap, met again.
