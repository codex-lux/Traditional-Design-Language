# WP-11.9 — the prose, executed: sixty records state an aspect and nothing read one

*6 September 2026. Branch `claude/georgian-tidewater-layout-diagnosis-sq78o4`.*

Part VI of `docs/reports/tidewater-layout-diagnosis-2026-09-04.md` is a table of twenty statements
the corpus already makes and can execute none of, introduced as *"the cheapest list in the
document: none of it needs a source, because the source is already cited on the record it lives
in."* This package works that table. It is cheap in the sense the diagnosis meant — no new claim
about the world is made here, only readings of claims already in the tree — and it was not cheap
in the sense of small, because the first of the four compass rules turned out to be one of sixty.

---

## I. What was found before anything was built

**Four of the twenty are compass rules on room records. All sixty room records state an aspect,
and nothing in this tree read a single one.**

`daylight.orientation` is a required-shaped field carried by every record in `rooms/`. It is where
the library's *"NORTH, AND FOR TWO REASONS THAT POINT THE SAME WAY"* lives, and the kitchen's
*"EAST for the morning, and this is one of the oldest orientation rules in domestic building"*,
and the larder's *"NORTH, and it is not a preference"*. `grep -rn "daylight" build/*.py` returns
readers of `depth_multiplier`, `sides_lit`, `glazing_fraction`, `depth_governs` and `note`.
`orientation` has none — and the sweep was Python AND JavaScript, because a reader could have
lived in the workbench app: every `orientation` in `workbench/app/src` is an SVG or splitter
attribute. **The one false hit a grep gives is `check_kits.py:149`**, where `"orientation"` is a
member of the closed `RULE_KINDS` enum for pack rules and has nothing to do with this field; a
later reader checking this claim will find it, which is why it is named here. Sixty sentences,
zero readers, since the records were written.

That is the same shape as the finding WP-9.2 recorded about `structural_logic` (zero readers) and
`grows_by` (one, which echoes it) — a corpus that says the right thing in a field nobody opens.

## II. What was built

### II.1 `daylight.aspect` — the reading, authored beside the prose

A regex over `daylight.orientation` was refused, and the reason is one layer over: WP-11.4's
`opening_width_in` searched `servicing.heat` for `NN in` and took the first hit, and
`rooms/closet.json` — which opens *"None required and none wanted"* — published a **30.0 in
measured fireplace opening** taken from a sentence about a drywall access hatch. The register
entry for that is `oq/a-room-records-prose-states-a-floor-its-own-band-does-not`, and its finding
is that four different jobs share one syntax in this prose. They share it here too:

| the record | what its sentence is doing |
|---|---|
| `larder` | *"NORTH, and it is not a preference"* — a governing aspect |
| `terrace` | *"South-east in cold climates …; east or north in hot ones"* — an aspect CONDITIONED on an axis this checker does not have, whose two branches point opposite ways |
| `breezeway`, `cross-passage` | *"The passage runs ACROSS the prevailing summer breeze"* — an axis of DOORS, not of glass |
| `garage` | *"Any"* — a refusal, which is an ANSWER and not a silence |

A pattern cannot tell those apart, and tightening one until the number looks right is the move
`check_grouping_rules.py`'s prose meter exists to refuse. So the reading is **authored**: a
`daylight.aspect` object beside each sentence, quoting the sentence it read.

```json
"aspect": {
  "applies": true,
  "strength": "preferred",
  "prefer": ["N", "NE"],
  "avoid": ["S", "W"],
  "basis": "A north or north-east library is the historic preference and the correct one.",
  "judgment": true
}
```

**`basis` is checked.** `build/check_rooms.py` holds it against that record's own
`daylight.orientation` and errors where it is not verbatim — `openings/grammar.json`'s rule, one
layer over, where every editorial rule quotes the room prose it reads and a citation that cannot
be checked is a guess wearing a citation. It was written that way from the start rather than added
after, and the authoring script asserted every one of the sixty **before writing any file**, which
is WP-11.6's own lesson about a multi-edit script that asserts between its edits.

**The split, all sixty read by hand:**

| | records |
|---|---|
| state a compass aspect | **35** |
| of those, `hard` | **5** — `larder`, `piazza`, `morning-room`, `sleeping-porch`, `sunroom` |
| answer with something that is not a compass | **25** |
| unstated | **0** |

`strength: hard` is taken only where the record's own words make it one — *"and it is not a
preference"*, *"HARD CONSTRAINT: within 45 degrees of south-west"*, *"EAST TO SOUTH-EAST, HARD"*.
**A capitalised preference is still a preference**, and the library is the case that settles it:
its NORTH is shouted and then licensed two sentences later (*"Where the room must face south or
west, the books go on the wall the sun cannot reach"*). Typography is not severity.

**`applies: false` is a verdict, not a gap** — WP-11.4's `wants_a_hearth` lesson, where the
`none` state is the one a two-state reader loses and the centre passage gets hunted for a fire the
corpus positively refuses it. Twenty-five records here answer the orientation question with
something that is not a compass, and each carries a `note` saying which. **The first version of
that check exempted the short ones** — a basis beginning "Any" or "None" was treated as
self-explaining — and it was a bad instrument for the reason this repository keeps meeting: the
exemption was a list of five literal strings, so it fitted the corpus that existed rather than
stating a rule. Five notes were written and the exemption deleted. A refusal's value is its
reason, with no exceptions for the brief ones.

### II.2 `build/compass.py` — plan north, in one place

**Ruled by Lucas, 5 September 2026: plan-N IS true-N unless a bearing says otherwise.** It is the
convention `render_plan.py` has printed on the plate as **NORTH IS UP** since WP-2.4, made a rule.

`site.street_bearing_deg` is the bearing that says otherwise; `context.entrance_faces` says which
plan face is the front; the rotation is the difference and every plan face turns with it. **Where
a bearing is stated and the front is not, every reading is COULD NOT EVALUATE** — taking
`axis.DEFAULT_FRONT` there would be an assumption stacked on an assumption, silently turning a
real house by whatever the difference happened to be.

`SECTOR_TOL_DEG = 22.5` is **editorial and marked so**. It decides nothing on an unrotated plan —
every face lands exactly on a cardinal, so the match is plain equality — and matters only under a
stated bearing, where it is the coarseness of the eight-point compass the records are written in.
It is also the only route by which an intercardinal is reachable at all: a window's `wall` enum is
`N/E/S/W`, so `NE` cannot be written on a wall and can only arrive by rotation.

**THE RULING'S STATED COST IS HONOURED IN THE FINDING, NOT IN THE CODE.** `compass.assumption()`
returns one sentence and every finding this layer causes carries it:

> Library is glazed on an aspect its own record rules out: plan-S is S, and rooms/library.json
> avoids S/W — "A north or north-east library is the historic preference and the correct one."
> (preferred). **plan-N is read as true-N: this record states no site.street_bearing_deg, and
> north is up on every plate this tree draws.**

A reader told a library faces south deserves to know whether the record said so or whether the
checker assumed it. `test_the_assumption_is_printed_in_the_finding_and_not_merely_held` is the
guard, and deleting the sentence turns the suite red.

### II.3 The layer is the ROOM layer, and that was a decision

WP-11.4's rule is *ask what a check READS before choosing its layer*, and it cost that package a
hearth check written into the one layer that could not run it. **A window's `wall` is AUTHORED**;
a door's is solver output — CLAUDE.md records the DXF round-trip failure that established the
difference. So the aspect is a fact of the DECLARED record, and it belongs beside the other
record-reading layers rather than in `drawn`.

The consequence is the good one: **the check speaks on all sixteen plan records**, not on the two
that carry a placement, and it does not join
`oq/fifteen-of-sixteen-plans-name-no-parti` and `oq/fourteen-of-sixteen-plans-name-no-massing` in
being silent on most of the corpus. Whether the placement could SEAT those windows where the
author put them is a different question and `drawn-window-off-the-placed-wall` already answers it.

### II.4 Two grouping rules given a test

Two more of the twenty, both DECLARED facts and therefore both answerable without a placement.

**`passage_ends_with_a_door at-least 2`.** An end counts as doored where the door reaches outdoors,
directly or through a threshold room. **The second clause is not a loosening**: the Tidewater
passage's front door is `to: porch`, because the porch is a room in this model and the front door
is between the two — so a reader counting only `to: exterior` would find one end where the record
states two, and would report the diagnosis's own B4 against a record that does not commit it.

**The rule was SPLIT**, because it bundled two quantities: *"Both ends of the passage have doors,
and they are aligned"*. The count the declared record answers; the alignment is a relation between
two PLACED doors and only the drawn layer may read a placement (OQ 54). The alignment half is now
its own rule, carrying no test and named to the reader — which is what stops the count passing
from reading as the alignment passing too. This is the move `centre-passage-core` rule 2 already
made when the passage's 8 ft floor was split out of its facade-share ratio.

**`stair_hall_opens_off_the_passage at-least 1`.** *"The stair rises in the passage or in a hall
opening off it, never through a room."* The **first half is true by construction**:
`openings.stair_pass` places a stair in a room of type `stair-hall` and nowhere else, so a test of
it would be an instrument that cannot fail, which this repository rates worse than a test that
cannot fail. The second half is failable and is what is tested. The relation is read in **either
direction**, because the passage carries the door on the Tidewater record and the stair hall could
carry it on another — reading one way would convict half a corpus of a drafting convention.

### II.5 The finding that came out of building those two

**28 of the corpus's 86 grouping `internal_rules` were emitting nothing at all.**

The grouping layer's no-test branch read `elif hard`. A hard rule with no machine test was handed
to a human by name; a rule with a `measures.reported_by` said so (WP-11.7); and **every `strong`
and `preferred` rule with neither was silent** — no evaluation, no note, no hand-off. A rule
nobody executes and nobody is told about reads exactly like a rule that passed.

| | rules |
|---|---|
| carry a `test` | 28 |
| report (`measures.reported_by`) | 1 |
| handed to a human by name | **29 → 57** |
| SILENT | **28 → 0** |

It was found by a test asserting the split rule's untested half was named, which came back empty.
The branch now speaks for every rule and names the severity, because that is what a reader needs
to know how hard to look.

### II.6 And a refusal with one message for a cause it was not written for

All nine aspect findings on the Tidewater plan reached the critique as `architect` — which is the
right class, because rotating a house is not a move and moving a room's glass to another of its
walls recomposes an elevation the author drew — **carrying the reason "the depth rule does not
govern this room type"**. That is the `daylight` layer's fall-through in `critique._intended_move`,
a true sentence about a different rule handed to a finding it was not written for: WP-11.4's *a
refusal with one message for three causes tells most of its readers the wrong thing*, in a new
place, arriving the moment a second kind joined that layer.

Both aspect kinds have their own reason now, and both are honest refusals rather than absent
moves. **This is what a new finding kind costs beyond the check itself**, and it was found by
running `classify` on the plan rather than by reading the file.

## III. What it measures

**63 findings over the sixteen plan records — 40 taking none of the light the record asks for, 23
glazed on an aspect it rules out.** Deterministic: nothing here reads a placement, so these are
ratchet-able in the sense WP-9.6 established, unlike an `auto` figure that drifts by ±3.

**One `serious` in the whole corpus, and it is true.** `good-04-rambling-porch-farmhouse`'s
enclosed porch is a NORTH sunroom, and `rooms/sunroom.json` says *"North is a cold glass box with
no compensating gain — pleasant in July, unusable in January"*. The other 62 are `minor`, because
the records they read are preferences.

**The two shipped plans, and the counts are fully accounted for:**

| | serious | minor | fatal | info |
|---|---|---|---|---|
| `tidewater-georgian-careful` before | 29 | 65 | 0 | 22 |
| after | **29** | **74** (+9 aspect) | **0** | **29** (+7 rules that had been silent) |
| `spec-builder-colonial` before | 57 | 75 | 4 | 17 |
| after | **57** | **80** (+5 aspect) | **4** | **25** (+8) |

**Serious and fatal are unmoved on both**, as they were for WP-9.6's furniture split and
WP-11.4's hearth — three packages running now. That is the evidence
that a new layer surfaced facts rather than re-graded anything; every movement is a `minor` or an
`info` and every one is attributed above.

A note found on the way, because a number in prose beside a pin is exactly where these drift:
`test_plan_validator.py`'s WP-9.6 comment says **"Serious 30 and fatal 0 are UNMOVED"** for the
Tidewater plan and the measured figure is **29**, before this package and after. Nothing pins the
serious count there, so it drifted and nobody could notice. The sentence is left as written —
it records what that package measured — with the correction beside it.

**The library on the Tidewater plan is convicted, and it is the diagnosis's own C4.** *"C4: the
library faces south."* Stated in prose on 4 September and computable on 6 September.

**Both grouping tests PASS on the Tidewater record, and that is the finding.** The diagnosis's B4
— *a centre passage whose rear door read as a window* — is a defect of the DRAWING, not of the
record: `passage_ends_with_a_door` is 2.0 and `stair_hall_opens_off_the_passage` is 1.0. WP-6.1
fixed the drawing; the record was never wrong. A package that had assumed the record was at fault
would have "fixed" a correct record.

### The nine, each with the fact that would have to exist first

- **Row 16, the closet's front elevation.** Conditioned on *"In a symmetrical style"*, and there
  is no machine-readable symmetry fact: `four-over-four`'s *"Facade symmetry is a hard
  constraint"* lives in `massings/catalog.json`'s `constraints`, which is an array of prose. Only
  three of the forty massings mention symmetry at all, so authoring a `facade_symmetry` field
  would author silence into thirty-seven, and a prose reader is refused for §II.1's reason.
  `oq/a-licence-conditioned-on-the-wrong-axis`'s family.
- **Row 17, the primary bedroom's wing.** *"In a double-pile block it does not fit without a
  wing"* is a claim about the MASSING, and `oq/fourteen-of-sixteen-plans-name-no-massing` records
  that 14 of 16 plan records state none. A test would be unjudged on 87.5% of the corpus, and the
  register entry for that question expressly forbids closing it by deriving the massing.
- **Row 3, four fireplaces per floor.** Same obstacle from the other side: WP-11.4's own entry
  records 42 of 60 room records `unstated` about a fire, and the massing is needed to know that
  paired end stacks are drawn at all.
- **Row 19, the stair setback ceiling.** The figure is in the Georgian kit and the quantity is a
  placed one — the run against the hall it stands in. It belongs in the drawn layer beside the
  stair, and `openings.stair_pass` already computes the run; wiring it is a package, not a line.
- **Row 10, the stair window.** The `stair` object (plan schema 0.3.0) has no window field and no
  record in this corpus states one. A test would report could-not-evaluate on 16 of 16 — honest,
  and not worth a schema change until something can supply the fact.
- **Row 9, the entry sequence.** Three of its four conditions (level, enclosure, direction) are
  placement facts and the fourth is stated by almost nothing. Drawn layer, own package.
- **Row 12, the enfilade's direction.** Answerable in principle from the declared areas along the
  door chain, and not built: the enfilade's ORDER is stated nowhere, so deriving it from the door
  graph would author a sequence the record does not carry — the same objection
  `oq/fourteen-of-sixteen-plans-name-no-massing` makes about deriving a massing from a parti.
- **Row 6, the flanking rooms.** *"Equal or near-equal"* has no tolerance anywhere, and choosing
  one would be authoring the rule rather than executing it — WP-11.3 had to have its half-a-bay
  tolerance RULED for exactly this reason, and no ruling covers this one.
- **Row 18's dimensional half.** `rooms/centre-passage.json`'s Tidewater `style_variation` says
  12 to 14 ft where the catalogue band is 8 to 14 and the grouping's hard test is 8 to 14. That is
  a THIRD statement of one quantity and it belongs to
  `oq/a-grouping-rule-and-a-room-record-can-disagree`, whose ruling is explicit that no number
  there may be reconciled to make a checker green.

**A refusal is only worth its reason.** Each above names what would have to exist, and none of
them is "it was not got to".

## V. The open question raised

`oq/no-plan-record-states-its-bearing`. **0 of 16 records state `site.street_bearing_deg` and 16 of
16 are judged under the assumption.** The convention is ruled and is not in doubt; what is open is
what a finding under it is worth, and there are two readings the corpus cannot separate: that a
window authored on `S` states south (making the 63 real), or that these records were authored
before any layer read a compass and their walls were chosen to make a drawing legible (making the
check convict them of a fact nobody meant to assert — the shape `exterior_walls` already has). The
entry names what a ruling must decide and what must not be done to close it, chief among them:
**do not default a bearing**, because zero is not a measured north.

## VI. What was mutation-checked

Eight mutations of the compass, every one caught, each with the match count asserted before the
colour was believed — WP-9.6's rule, learned when a mutation matched an earlier occurrence in a
6,000-line kit file and never touched the parameter under test.

| mutation | caught by |
|---|---|
| `SECTOR_TOL_DEG` widened to 90 | the sector test |
| the stated bearing ignored (`rot = 0.0`) | the rotation test |
| a declining record hunted for an aspect | the `garage` test |
| a windowless room read as satisfied | the unjudged test |
| the `avoid` list never fires | the south-library test |
| the `prefer` list never fires | the south-study test |
| a hard reading downgraded to minor | the severity test |
| the assumption dropped from a finding | the ruling's own guard |

Six more against the two grouping rules, all caught:

| mutation | why it matters |
|---|---|
| the BEST passage reported instead of the worst | reporting the best is the flattering direction — the OQ 52 family |
| a front door through a porch stops counting | the Tidewater passage's front door is `to: porch`; this is B4 reported against an innocent record |
| the stair relation read in one direction only | convicts half a corpus of a drafting convention |
| the two passage types pooled | judges a service run as if it were the centre passage |
| the upper passage asked for its ends | the Tidewater record carries a second `centre-passage` a storey up |
| the silent-rule branch narrowed back to `elif hard` | 28 rules go quiet again |

Four more against `check_rooms.py`'s citation check — a basis edited by one word, `judgment` set
false, an `avoid` list made to collide with `prefer`, a declining record flipped to `applies:
true` — all four caught, all four with an asserted single match.

**The one guard that had to be widened rather than written**: `test_every_grouping_rule_speaks`
counts the three states across all 86 rules rather than asserting one rule is named, because
WP-11.7's own lesson is that a removed finding and an added one cancel in a total (63 stayed 63
while two things changed).
