# WP-11.2 — the pen ladder, and the wall the record states

*4 September 2026. Phase 11, package 2. Branch `claude/georgian-tidewater-plan-analysis-qbwmqs`.*

## Why

WP-11.1 put `build/render_plan.py` into Graphic Standard No. 1. The workbench's own sheet —
`workbench/app/src/sheet/Sheet.jsx`, which is the surface a person actually reads — was still
drawing in numbers of its own, and the two renderers of one record had drifted in the way the
sheet-symbol fixture exists to stop.

**Two findings, and the second is the sharper one.**

- **Not one of the standard's five line weights was in use.** `tokens.css` has carried the ladder
  since WP-5.2 — construction .7, fine 1.05, medium 1.6, heavy 2.4, cut 3 — with the rule that
  weight and tone fall together. `Sheet.jsx` carried **nineteen inline stroke widths**, none of
  them one of the five: 2.6 for the cut line, 1.4 for both a partition and a door leaf, .8 for a
  swing arc, .45 for a triangle. In a system whose entire grammar is line weight.
- **The wall was two literals and neither was a reading of anything.** `derive.js` had
  `WALL_T = 0.75` and `PART_T = 0.42` — 9 in of envelope and 5 in of partition, drawn on every
  house whatever it was built of, and **matching no assembly in
  `construction/wall-assemblies.json`**. The Tidewater plan declares `solid-masonry-two-wythe`,
  which is 15.5 and 4.5.

## What was built

### `sheet/pen.js` — the ladder, once

`PEN.cut`, `.profile`, `.medium`, `.fine`, `.construction`, `.dim`, plus `POCHE.masonry` /
`POCHE.partition` and `inked(pen, token)` for a mark whose INK is a duty (the drag handle in gilt,
a selected room in salmon) while its weight still comes from the ladder.

**They are `style` objects and not attributes, and that is the mechanical point.**
`var(--lw-cut)` does not resolve inside an SVG presentation attribute — `strokeWidth="var(…)"` is
an invalid attribute value and the browser drops it, so every stroke on the sheet would have
fallen back to 1 px in silence. It resolves in a style declaration.
`vectorEffect="non-scaling-stroke"` stays an attribute on every mark: it is not a weight, it is
what makes a weight a weight, and `walk.mjs`'s pen check reads computed style so it is indifferent
to which carries it.

`src/pen.test.mjs` reads the SOURCE and holds it to the ladder — the shape of guard
`test_parti_confinement.py` uses to stop a fourth copy of a path join appearing, for the same
reason. It reads source rather than a rendered DOM on purpose: the rendered sheet resolves every
`var()` to a number, so a DOM check would see 3 px whether it came from the ladder or from a
literal that happened to match. **One exemption, and it is not a loophole**: a mark inside a
`<pattern>` is in PATTERN units, so a pixel weight from the ladder would be meaningless there —
`walk.mjs` already makes exactly this exemption for exactly this reason, spelled the same way so
the two cannot drift. A second test pins the exemption at exactly one mark.

### `build/assemblies.py` — a leaf, so the drawing can have the number

`wall_thickness` lived in `structure.py`, which loads `plan_check.py` and `geometry.py` at module
level — and `geometry.py` calls `openings.stair_pass`, so anything in the placement or drawing
path that reached for `structure` closed an import cycle. **WP-9.6 met this exact problem and
answered it exactly this way**, moving the storey derivation into `build/storeys.py`; its header
states the rule this file follows and re-exports under the old names so there is one
implementation. `structure.py` re-exports `wall_thickness`, `load_construction` and
`DEFAULT_CONSTRUCTION_TYPE`, and `tests/test_structure.py` is untouched.

`build/openings.py::place` writes `footprint.wall` (plan schema **0.5.1**), so both renderers read
one number. `wallOf(footprint)` in `derive.js` is the single reader; the fallback is kept and is
**not silent** — a record placed before 0.5.1 gets `stated: false` and the plate says *"The record
states no wall assembly, so the walls are drawn at this sheet's conventional 9 in and 5 in — a
convention, not a reading."* Where the assembly was DEFAULTED rather than declared, its own note
is printed too.

## The browser walk ran, and it caught a defect the unit tests could not

**`workbench/app/e2e/walk.mjs` had never been run in a session on this branch** — `node_modules`
is not in the tree and the walk needs a built app and a live server. `npm install` reaches the
registry from here, `uvicorn` installs, and Chromium is already at `/opt/pw-browsers`, so it ran:
**green on the pristine tree, red on this change.**

It failed at `svg[role="img"]` never becoming visible on the Plan Workbench. There was **no
console error and no page error** at first, because the throw only happens on the render that has
a placement — so it arrived twenty seconds after the click, after the walk had already timed out.
Instrumented (a probe that logs `pageerror` and every `/api/` response and polls for a minute) it
was one line: **`ReferenceError: LABEL_PAD is not defined`** — a third use of the constant I had
replaced with a function of the wall, in the divergence mark for a room too small to carry its
dimension string. 81 unit tests passed with it. The build passed with it. Only the browser found
it.

**And the build's own warning had a second one in it**: the drag handle ended up with two `style`
attributes, so React kept the last and the gilt stroke was dropped — the affordance would have
gone invisible. Vite warns and still builds, which is exactly the kind of warning that gets
scrolled past.

Two things follow, and both are recorded in CLAUDE.md:
- **`npm install` + `pip install uvicorn` makes the walk runnable here.** It is the only guard in
  this repository that measures the drawing in a browser, and it is worth the two minutes.
- **A guard that reads a selector rather than a property goes blind on the next edit.** The walk's
  drag-preview check filtered on the `stroke` ATTRIBUTE containing "gilt"; once the ladder moved
  strokes into `style=`, `getAttribute('stroke')` returns null on every mark and the check would
  have counted zero previews on a working drag. It reads computed style now. The pen check thirty
  lines below it carries the same lesson in its own comment, from WP-5.7.

## What was deliberately not done

- **OQ 64 is not closed.** The loupe still magnifies the pen with the drawing. WP-11.2 makes it
  *closable* — every width is now a `var()`, so a counter-scale is one `--pen-scale` factor
  instead of nineteen computed values — and changing it reaches the whole instrument, which is a
  ruling rather than a side effect of a restyle.
- **The wall bands are not in the sheet-symbol fixture yet.** `tests/fixtures/sheet_symbols/`
  freezes what openings the two renderers derive; the Python sheet computes wall BODIES and the
  JS sheet still computes partitions its own way. Adding `expected.walls` is the next honest step
  and it belongs with the JS sheet learning `wall_bands`' bearing/partition distinction, which it
  does not yet draw.
- **The JS sheet does not yet distinguish a bearing wall from a partition.** The Python sheet does,
  from `structure.bearing_lines`. `derive.js` derives partitions from shared room edges and has no
  view of the bay grid.
