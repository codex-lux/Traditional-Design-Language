# WP-13.6 — furniture to its own grammar

*16 September 2026. Branch `wp136-furniture`, on `57e7b72`.*

Every figure in this report is `engine="heuristic"`, which is deterministic and identical on
cold runs, measured on the tree named beside it. The control is a `git worktree` checkout of
`57e7b72`, and where an attribution mattered a second checkout of `1c2ac80` and `31a7373`.

---

## I. What was built

`furniture/grammar.json` had ten rules of which FOUR were executed — a placement default, a
wall run, a corner, a centre — and `build/furniture.py` seated every item by packing it against
the first wall with a clear run. Twenty drawable items state their POSITION in their own name
or note and the packer read none of them. It reads them now.

**Nine positioned rules**, each stated by another thing already on the floor or in the record,
each executed in `arrange_room` after the wall items and before the freestanding ones, and each
REFUSING BY NAME where its stated relation has nothing to stand on:

| rule | seated by | grade | corpus: placed / refused |
|---|---|---|---|
| `fg-at-the-foot` | the bed's foot edge, centred, back to the bed | editorial-from-prose | 8 / 1 |
| `fg-beside-the-bed` | the bed's side, inside its aisle | editorial-from-prose | 33 / 4 |
| `fg-between-the-windows` | a pier between two PLACED sashes | editorial-from-prose | 1 / 1 |
| `fg-flanking-the-chimney-breast` | a breast the hearth pass DREW | editorial-from-prose | 0 / 18 |
| `fg-opposite-the-bed` | the wall opposite the bed's, and no other | editorial-from-prose | 0 / 0 |
| `fg-on-the-end-wall` | one of the room's two END walls | editorial-from-prose | 0 / 0 |
| `fg-facing-down-the-hall` | an end wall of the hall | editorial-from-prose | 0 / 1 |
| `fg-pair-facing` | the hearth's axis, else the room's centre line | **reading** | 2 / 2 |
| `fg-chairs-around-the-table` | the table's own edges, ends first | editorial-from-prose | 83 / 6 |

**Three modifiers**, which tag no entry with a rule id of their own and are measurable in what
they do: `fg-count` (a catalogue item authored `footprint_of: piece` with a `count` is drawn
that many times), `fg-clear-in-front` (a wall-seated item reserves the floor its record asks
for) and `fg-bed-aisle` (a bed's clearance is an aisle EACH SIDE, not floor in front).

**Two schema layers.** `schema/room.schema.json` gains `footprint_of` (piece | group) and
`count`; `schema/plan.schema.json` **0.12.0** gains `furniture_layout[].piece`, `of`, `by` and
`back`. The catalogue: 278 items, **17 `piece`, 9 `group`**, 252 stating neither because their
name counts nothing; **10 items carry a `count`, 20 pieces in all**.

**The plate keys a set once.** `render_plan.py::_key_groups` and `sheet/furnitureKey.js::
keyEntries` group consecutive drawn pieces of one item into ONE key line and ONE numeral stood
on every piece — which is how a draughtsman keys a set of chairs, and what keeps a dining room's
key eight lines shorter than its chairs. The line says `x8`, or `x5 OF 8` where the record asked
for eight and five could be seated: the shortfall is in the line a reader looks at.

## III. The ratchet that did NOT move, and why that is a measurement

`tests/test_furniture_drawn.py` pins `DRAWN_SHORT_CEILING = 68` / `DRAWN_LONG_CEILING = 82` and
**both are unchanged**. That is not luck and it is worth stating, because CLAUDE.md records
three separate causes for that one pair and warns the next reader not to assume the last cause
is the cause.

`_sweep()` calls `plan_check.furniture_shortfalls(room_type, drawn_width, drawn_length)`: it
reads the room TYPE's catalogue (`footprint_in`, `clearance_in`) against the DRAWN RECTANGLE.
This package changed neither. The catalogue edits add `footprint_of` and `count` and touch no
footprint and no clearance; the placement is byte-identical. **So the layer that would have
moved it — catalogue or placement — was not touched by this package at all, and the third
layer, the packer, is not one that pair reads.** The pair measures whether a room is big enough
for its furniture; this package is about where the furniture goes inside it.

## IV. What was found

### 1. The schema forbade four fields the placer writes, and the first commit had already shipped that defect once

`31a7373` wrote `corner: true` and admitted nothing, and thirteen of the sixteen placed plans
stopped validating against their own schema; `57e7b72` fixed it. This package writes four more
(`piece`, `of`, `by`, `back`) and admitted them **before** the commit, because the package's own
gate now solves all sixteen plans on the deterministic engine and validates each PLACED record
with `jsonschema`. **16 of 16 valid**, stated here as the gate rather than discovered by a
reader. A checker reads the AUTHORED record; only three tests in this repository validate a
placed one.

### 2. The corpus sheet hash had been red for three commits and the movement was WP-13.6's own

`test_no_shipped_sheet_moves` was already failing on `57e7b72`. Bisected with the test's own
loop on `git worktree` checkouts:

    1c2ac80  (before WP-13.6)      01771d3656231ba9 / 0fd105825eda19e0   == the pin
    31a7373  (WP-13.6 commit 1)    41314f5e3f8ba600 / 4fa5209dca42afb8
    bc48e5d … 57e7b72              unchanged
    this commit                    1a63f71dda3b6bee / 4413ad13a9e35766

So WP-13.6's own first commit moved all sixteen sheets and did not re-pin, and four commits
shipped on a red assertion, none of which had touched a renderer. It is the schema finding one
layer out and it is WP-12.4's precedent word for word. **The harness was proved before the
re-pin**: run on a checkout of `1c2ac80` it reproduces the retired pair to the character.

### 3. `executed_but_unreached_in_the_corpus` named three rules and the measurement says two

`fg-flanking-the-chimney-breast` was on that list. It is **reached** — nine living rooms over
nine of the sixteen plans carry the item, it is a pair, and all **eighteen** pieces are refused
by name because not one of those rooms draws a chimney breast. Eighteen refusals are eighteen
entries on the record and eighteen lines a reader can see; calling a rule that produces them
unreached is the fake-unjudged shape one layer out. What no shipped plan reaches is its PLACING
branch, which is a different claim and is now made in that rule's own note.

The two that really are unreached are `fg-opposite-the-bed` and `fg-on-the-end-wall`, and the
reason is the same for both: the one catalogue item stating each is a **4 in television** and a
**3 in mirror**, and `fg-too-thin-to-draw` refuses each before any placement rule is consulted.
**The positions the record states most plainly are on things the plan never draws** —
`oq/a-stated-position-on-an-item-too-thin-to-draw`.

`tests/test_furniture_grammar.py` holds the list to the corpus IN BOTH DIRECTIONS: every id on
it emits nothing over the sixteen plans, and every positioned rule off it emits something. Each
direction catches a different lie, and both mutations bite.

### 4. `fg-clear-in-front`'s rule text claimed something the code does not do

It read *"no later WALL-SEATED or POSITIONED item may be seated in that strip"*. The strips are
computed AFTER the whole wall pack, so within the wall pack no strip applies; the reservation
reaches the positioned items and nothing else.

**Two wider readings were built and measured before both were refused, and the measurement is a
LADDER whose rungs are each named**, on the sixteen plans on the deterministic engine and on the
committed tree:

| scope | placed | refused | drawn items lost against A |
|---|---|---|---|
| **A — later POSITIONED items only (shipped)** | **648** | **152** | — |
| B — and the freestanding items and the table's chairs | 569 | 203 | **79 over 39 rooms** |
| C — and the wall pack too (`front_ft`, gated as `aisle_ft` is) | 560 | 212 | **88 over 44 rooms** |

C's losses are 32 dining chairs, 7 hall chairs, 4 dining tables, 4 coffee tables, 4 games
tables and the rest; B's include the living room's coffee table, against its own sentence, which
is why a freestanding item is exempt. Both were REVERTED and the rule reworded to A, for the
reason the freestanding exemption already gives: the figure is a reading and the scope is not, a
chest's 36 in and a sofa's 30 in overlap across any room under about 7 ft, and no record says
that is forbidden.

**AND THE FIRST TWO FIGURES THIS PACKAGE PUBLISHED FOR THIS HAD NO SCOPE ON THEM.** A "41" it
inherited from the pass before, and an "87 over 43 rooms / 648 → 561" measured with the
`front_ft` field alone — which also leaks the strips into `placed` and so silently blocked the
freestanding items too, making it neither B nor C. Both are superseded by the table above and
the commit that introduced the second one (`ce80895`) carries it. **A figure without its scope
is a figure the next reader applies to the wrong one**, which is this file's own
number-is-a-statement-about-a-tree rule one axis over. The measurement is published rather than
netted off, and
`oq/a-clearance-is-sometimes-a-companions-place-and-sometimes-a-prohibition` carries the three
things that would have to be authored to settle it.

### 5. The packer dropped `piece`/`of`, and no shipped plan can reach the line

`pack_against_walls` copied `symbol`, `rule`, `grade` onto every entry and not the two fields
that say which piece of a set an entry is. Swept: **every counted catalogue item in the corpus
resolves to `fg-freestanding` or to a positioned rule**, so the packer is handed no counted spec
by any of the sixteen plans and all 205 piece entries are written elsewhere. The lift is
byte-identical on all sixteen placed records, which is how it was shown to be unreachable — and
it is DRIVEN by a test, because without it the key draws one numeral per hall chair instead of
one numeral on a pair.

### 6. A refusal that publishes a count it did not read

`fg-chairs-around-the-table`'s no-table branch first said *"nothing for the chairs"* with no
number; the obvious repair was to name the catalogue's own `count`. **Measured, that is wrong**:
the branch is reached twice in the corpus (`bad-07-octagon-dinette-colonial` and
`good-04-rambling-porch-farmhouse`, both where the table itself could not be seated) and both
times the catalogue states ONE uncounted `dining chair`, which is not the number of chairs
anybody was refused. The count of chairs is the TABLE's, read from its own name; with no table
placed it is **unjudged**, and the reason says so in those words. A mutation that publishes the
catalogue figure goes red.

### 7. One argument, two meanings, coinciding

The breasts reach the furniture through `openings.furniture_pass`, because `build/furniture.py`
is a LEAF and may read no sibling. That pass's `level_index` now carries the RECORD's own
`index`, because `threshold.hearth_pass` writes `{"level": lv.get("index")}` on every breast and
`_place_windows` beside it already took it that way. The one other reader of that argument is
the stair well, and `stair_pass` writes a **literal** `level: 0` meaning the ground level. Two
meanings in one argument — `at_ft`'s defect (WP-11.14) one layer out — coinciding only because
every level of all sixteen plans has an `index` equal to its position. Measured; the premise is
asserted by a test, so the day a record states otherwise (a cellar at `index: -1` is what the
plan schema documents and nothing uses) the suite says so rather than a well quietly ceasing to
block. Not restructured here: the honest fix changes `stair_pass`'s own contract, and a package
doing two things can only be reasoned about as one.

## V. What was deliberately NOT done

* **The two wider `fg-clear-in-front` scopes**, refused above with the cost of each.
* **A thin item is not given a position or a line.** `oq/a-stated-position-on-an-item-too-thin-to-draw`
  sets out the two readings; both need a ruling and one needs a new symbol primitive. Nothing
  was thickened to clear a rule.
* **`fg-hall-high-table-one-side`'s dais half stays unexecuted.** Which end of a hall is the
  dais end is a fact no plan record carries. Only the FACING half is executed, as
  `fg-facing-down-the-hall`, and that rule says in its own text that the end it takes is the
  packer's order and not a reading.
* **`fg-library-table-in-the-middle` and `fg-parlor-peripheral` stay unexecuted.** The parlor's
  *"six to eight side chairs"* was authored `footprint_of: piece` and **no `count`**, because a
  band is not a count; the peripheral arrangement of a number nobody stated stays with the
  architect.
* **The morning room's *"two easy chairs and a small sofa"* at `[60, 32]` is left unauthored** —
  it is either one small sofa or a group of three, and the record does not say.
* **Nothing in `rooms/` gained or lost a footprint or a clearance.** Every catalogue edit is a
  `footprint_of` or a `count` read off the item's own name.
* **`openings.furniture_pass`'s two-meaning `level_index` was not split** (§IV.7).
* **`plan_check.furniture_shortfalls` was not touched**, so the drawn-shortfall ratchet measures
  the same thing it measured before (§III).

## VI. The guards, and the mutations that bite

`tests/test_furniture_grammar.py` — 26 tests, all driven by hand from a catalogue built in the
file rather than off a shipped plan, because a shipped plan is a statement about one placement
and two of the rules are unreachable from every one of them.
`workbench/app/src/furnitureKey.test.mjs` gains the counted-item guard, on a fixture spelled in
both files in the same words, which is the parity mechanism this repo already uses.

**Twenty-nine Python mutations, every one asserted to have LANDED before its colour was
believed and every file restored byte-for-byte in a `finally`; all twenty-nine RED from a green
baseline.** Three more against `sheet/furnitureKey.js`, all three turning `node --test` red.

Two of the twenty-nine are `build/check_rooms.py`'s new rules — a `count` on a GROUP footprint,
a `count` on a name stating a band. **No shipped record breaks either**, so a guard over
`rooms/` would be green with both deleted, which is the state a reader mistakes for a verdict;
both are driven on a hand-mutated copy of `rooms/primary-bedroom.json`, with the CONTROL
asserted first (the sound record raises neither).

**Three were BLIND on their first run and each is a named class:**

1. *the chairs are counted from the catalogue and not the table* stayed GREEN, because the first
   draft of the fixture gave the chair item `count: 8` and the table `seats 8` — **a fixture
   where both branches return the same number guards neither**, WP-11.15's rule met again. The
   chair's count is **4** now and the table still seats 8, and the test asserts that
   discriminator as well as the result.
2. *the browser sheet stops grouping the pieces* stayed GREEN because the guard was a **grep of
   the JS source** and the mutation reworded the line rather than removing the behaviour. The
   behavioural guard lives in the JS suite now and the Python side holds the two files to one
   FIXTURE; mutating the JS source turns `node --test` red three different ways.
3. *the second nightstand takes the same side as the first* stayed green under
   `side_first = True`, and the reason is a small finding: the piece index only decides which
   side is TRIED first, and for a pair the second piece falls through to the other side anyway.
   `side_first` is inert wherever both sides are free. The mutation that bites offers only ONE
   side.

A fourth mutation reported NO MATCH on its first run, which is the harness working: an
assertion that a mutation landed is the only reason the other twenty-six colours mean anything.

## VII. One red that was not this package's

`tests/test_determinism.py::test_corpus_globs_are_sorted` was failing on
`tests/test_typefacts.py`, which `af8acff` (WP-13.3) added. The LIST is deterministic — an outer
`sorted()` covers the whole concatenation — and the guard reads LINE BY LINE, so a sort opening
on the line above reads to it as an unsorted glob. That is the trap
`tests/test_furniture_drawn.py`'s own comment already records. Fixed here, with the value proved
identical both ways, because a red build nobody can act on is where the next real failure hides;
attributed to its own commit rather than absorbed.
