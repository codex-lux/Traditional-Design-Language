# WP-11.9 — the six layers that read one rectangle

*5–6 September 2026. Gated on four rulings, all four taken before any code was written:
per-element envelope with the union reported beside it; the lot cap on the built extent, gap
excluded; a hyphen is an element and abutment becomes a constraint; `touches` is measured
against the room's own element's face.*

OQ 40 ruled a dependency a second massing ELEMENT, and `geometry.blocks_for` has placed one and
both renderers have drawn one since 3 September. An adversarial audit then measured **six layers
below the placer still reading `footprint.width_ft`/`depth_ft` as the whole building**, each
wrong in its own direction on a dependency room. This teaches all six, in a stated order, with a
measurement after each — and refuses the last item of its own plan, with the number that refuses
it.

---

## I. The guarantee, first, because everything else is read against it

Every plan in this corpus is one rectangle. So a package that teaches six layers about elements
must be **invisible on all sixteen**, or it has done two things and can only be reasoned about as
one.

| hashed over all 16 plans, `engine="heuristic"` | before | after |
|---|---|---|
| room geometry + footprint | `151126d0269bbc61` | **unchanged** |
| doors, windows, fixtures, furniture, stair | `f7c7430ec31dae3c` | **unchanged** |
| corpus findings (fatal / serious / minor) | 136 / 681 / 992 | **unchanged** |

Measured on a `git archive HEAD` checkout before the package and on the working tree after it.
`geometry_report` is deliberately **not** hashed: it grew a `lot_extent` key, which is the
disclosure, and hashing it would fail for the one reason it should not.
`tests/test_elements.py` pins both digests.

---

## II. `build/elements.py`, and why it is a leaf

`geometry.py` loads `plan_check.py` at import time and `structure.py` loads `geometry.py`, so
the six layers that must agree about this sit on three different rungs of one import ladder.
`elements.py` imports no sibling — `storeys.py`, `assemblies.py`, `furniture.py` and
`stacking.py`'s precedent, and the fourth time that shape has been needed.

**The join is geometric and that is not a shortcut.** `footprint.blocks` rows carry no room list
(`blocks_record` drops the one `blocks_for` builds), and a room's own `block` tag names the
DEPENDENCY, not the hyphen element beside it — so the tag alone cannot place a hyphen room.
Containment is exact because the slicer tiles each element with its own rooms and nothing else.

**A room that lands in no element is UNJUDGED, never assigned to the main block.** Defaulting to
element zero is precisely what all six layers already did; it is right for the whole shipped
corpus and wrong for the one record that motivated the work.

## III. The six, in order, each measured

Measured on a hand-tagged `tidewater-georgian-careful` — six service rooms as a west dependency,
the back hall as its hyphen — because the composer writes no `block` tag and a hand-tagged
record is the only way to reach this state.

**1 · `openings`.** `_boundary_walls` took the main block's `(W, H)`, so a garage at x 84–105 on
a 70 ft block reported its east face as a footprint boundary and both renderers drew the window
fourteen feet from the room. It takes the room's own element now, through
`elements.boundary_walls` — one body, because ruling 4 makes the drawn layer's `touches` the same
question and it had its own transcription one file over.

> Outward openings placed on a real face of their own element **18 → 23**; refusals **11 → 6**.
> Five authored windows (the breakfast room's E and S, the butler's pantry's N, the pantry's N,
> the kitchen's S) go from *"the placement puts this room on no such boundary wall"* to placed.
> Every dependency room had reported a spurious **W** boundary, because a room at x = −37
> satisfies `x <= 0.6`.

**2 · `structure`.** `wall_lines` swept every placed room into one envelope: a dependency
partition on the bay grid became a bearing line beyond `W` and `span_check` manufactured a clear
span across the hyphen gap, while the dependency itself got no envelope at all — wrong in both
directions from one reading. It takes an `elements=` list and emits four exterior walls per
element.

> Ground level: exterior walls **4 → 12** on a three-element house. Upper level: **4**, unchanged.

That second figure is the finding inside the finding. The first version of the line handed every
level all three elements, so the upper storey grew a dependency envelope with nothing inside it —
**12 exterior walls over 0 dependency rooms**, phantom structure of exactly the kind this package
removes, one level up. Caught by reading the counts per level rather than in total. An element
with no rooms on a storey has no walls on that storey, and `export_ifc` takes the same rule.

**3 · `vertical_score`.** It read every ground wall line, so a dependency wall 37 ft west counted
as support for an upper wall above the main block — where there is no upper floor at all.

> Isolated on ONE placement, with only the instrument changed: unsupported upper wall lines
> **20 → 27**. Seven upper walls were being credited to walls under no upper floor.

The test is containment in the upper level's own extent rather than element membership,
deliberately: it is the same answer on a tagged plan and it is also right for a dependency that
does carry an upper storey, which membership alone would not be.

**4 · the lot cap** (ruling 2). Two halves, and the second was not in the question.

*The cap*: `derive_footprint` capped the MAIN BLOCK, and a house was measured `lot_capped: true`
at 34 ft wider than its lot. The dependency's own width and its hyphen are reserved out of the
lot budget before the main block's bay count is taken from what is left — from `dependency_sizes`,
extracted so `blocks_for` and `derive_footprint` cannot disagree about a width.

*The half nobody had noticed*: **the main block was sized for rooms that go in the dependency.**
`a0` summed every ground room including the tagged ones, so the tagged plan got a 60 × 40 main
block for the whole 2,405 sf programme AND a 30 × 23 dependency beside it. `blocks_for`'s own
docstring has always said a dependency is sized from its own rooms *"never from a share of the
main block's"*; this is that sentence applied to the main block, which is the other half of the
same rule and was missing.

> Main block **60 → 40 ft**; built extent **97 → 77 ft**.

`geometry_report.lot_extent` states the built extent, the union bounding box, the lot and the
verdict, in `_disclose` so both record writers carry it. It reports **COULD NOT EVALUATE** where
a plan states no lot. `lot_capped` beside it is unchanged and answers a different question — that
the main block's bay count was reduced — and the note says so.

**5 · `plan_check.drawn`** (ruling 4). The four `touches` tests measured against the main block,
so a dependency room with authored windows was convicted of *"drawn in the middle of the house:
it reaches no exterior wall on any side"* while both renderers drew that same wall as an exterior
envelope. **The critic and the drawing wrong in opposite directions about one wall.**

> Isolated on ONE record, only the instrument changed: rooms reaching no exterior wall
> **8 → 1**, and seven rooms' exterior faces change — the butler's pantry from none to NW, the
> back hall from none to SNWE, the breakfast room from none to SE.

Exterior is exterior: a face on the dependency's own boundary carries a window, a sill, a load
and the weather. A face across the hyphen gap is exterior too, and is counted separately as
`faces_across_a_gap` so a later ruling has the number without this one baking an answer in.

**6 · `export_ifc`.** One slab, `W + 2·t_ext`, centred on the main block, so a dependency's
IfcSpaces floated clear of the slab under them. One slab per element per storey now, each
carrying `massing_element` and `massing_role`, and none for an element with no rooms on that
storey. The roof planes take the **union bounding box**, which is ruling 1's *"union reported
beside it"* made real: the roof spans something and that something is not an element.

> `export_ifc selftest`: 2 and 4 slabs on the two shipped plans, unchanged.

## IV. Ruling 3, and the honest thing to say about it

The abutment constraint is built: `elements.unabutted_hyphens` joins the search's first key,
beside the proportion band and the area floor that WP-11.8 put there. It is a ranking and not a
rejection, for the same reason the bands are — this engine has no conflict set and cannot decline
to place.

**And it is inert on everything the placer produces, which is the finding rather than a
disappointment.** The open question records a hyphen missing its neighbour by 0.64 ft with both
its doors unplaced and the hyphen itself fatal-unreachable. Reproducing it through `blocks_for`
was tried at five hyphen depths on the hand-tagged Tidewater and on a **composed
`five-part-palladian` with two dependencies and two hyphens** — five elements — and the count is
zero every time. Deleting the term changes no outcome on any fixture in the tree; the mutation was
run and it is silent.

The reason is structural: `blocks_for` clamps the hyphen's depth to the dependency's
(`hh = min(H, …)`) and centres all three elements on one axis, so the hyphen's y-range lies
inside both neighbours', and the slicer tiles each element exactly — a shared wall exists by
construction. So the term is a **guard against a regression in `blocks_for`**, not a fix for a
live defect, and `tests/test_elements.py` says that in the name of the test that pins it. The
detector itself is shown to bite on a hand-built record where the hyphen room misses both
neighbours, because a term that cannot fail is worse than no term.

## V. The last item of the plan is refused, with the number that refuses it

`PLAN-OF-ACTION.md` ends WP-11.9 with *"then the tags on the shipped record"*. Measured, tagging
is now an improvement on nearly every axis — which is the package's real result, because WP-10.1
measured the same tags **trebling the fatals** before the six layers were taught:

| `tidewater-georgian-careful`, `heuristic` | untagged | tagged |
|---|---|---|
| fatal | 9 | **6** |
| serious | 61 | **53** |
| minor | 83 | 85 |
| relaxations | 8 | **6** |
| rooms outside their own band | 6 | **2** |
| service rooms drawn ≥10% off their declared area | 5 / 6 | **3 / 6** |
| built extent | 60 ft | 77 ft |

**And it is still not authored, for one reason:** `geometry_cp.py` builds every room as
`x = NewIntVar(0, Wi)` — one rectangle, one non-negative coordinate space — and REFUSES a
multi-element plan outright. Verified on the tagged record: `engine="cp"` returns *"this plan has
more than one massing element … Use the hill-climb"*, and `auto` falls back naming the reason.
`tidewater-georgian-careful` is one of the two plans this corpus PROVES. Tagging it trades a
proved reference plan for a searched one, and that is not a trade this package may make on its
own — it is a precondition, not a cost.

`oq/the-proving-engine-cannot-place-a-second-massing-element` is raised for it, and WP-11.10 (the
terrace at grade) is gated behind the same fact.

## VI. What was found on the way

**A duplicated function definition, and the second one won.** Rewriting
`multi_element_disclosure` left two `def`s in `geometry.py` — the new text above the old, and
Python took the last. The record went on carrying `not_element_aware: [openings, structure, …]`
under a docstring explaining that all six had been taught, and `dep.py` printed the OLD text
while the edit had unambiguously landed. This file already records *"assert that an edit landed
and then re-read the file"*; the corollary is **assert that it landed ONCE**.
`test_the_disclosure_says_what_was_taught_rather_than_what_was_not` counts the definitions.

**The disclosure had to be rewritten, not extended.** It listed all six layers as
`not_element_aware` with COULD NOT EVALUATE beside them — true when written, false on 5 September.
Leaving it would be WP-6.4's own finding in the place that finding is about: a record asserting an
unreliability the code no longer has. It names what was taught, and the shorter list of what was
not: the roof (spans the union, a stated approximation), `engine=cp` (refuses), the composer
(writes no tag).

**The renderers were ahead of the structure layer.** `render_plan.py` has drawn the exterior
envelope **per element** since WP-11.1's poché — `band(... "exterior envelope", True, bi)`, one
ring per element, with its element's index on every band. So for two phases the drawing knew
something `structure.wall_lines` did not, and the critic contradicted both.

**And it was ahead in one direction and wrong in the other, which only LOOKING found.** The
tagged sheet was rendered and opened, and its UPPER plate carried a 30 ft poché rectangle
enclosing nothing: the renderer drew every element's ring on every level. An envelope around no
rooms says the house has a storey it does not have. **This is the third place that one defect
lived** — `structure.build_section` and `export_ifc` had both been given the per-level scoping
hours earlier, each caught by reading a count — and it is the only one of the three no count
would have caught, because the renderer publishes no counts. Fixed with the same rule; all
sixteen shipped sheets hash byte-identical across it (`61c8e1c2955b8421`).

What the sheet still shows, named rather than fixed: a 7 ft hyphen is narrower than its own
room label, so `BACK HALL (HYPHEN)` wraps and crowds, and four narrow service rooms in a row
carry labels that touch. Both are label-fitting on a hand-tagged record that ships nowhere, and
neither is a claim about the building.

## VII. What this package does NOT do

The roof is not modelled per element; it spans the union bounding box and says so. The CP engine
is untouched and still refuses a multi-element plan. The composer still writes no `block` tag, so
the only route in remains a caller-supplied or hand-tagged record. No shipped record is tagged.
`STACK_W`, `SHAPE_W`, the 20 ft span capacity and `bearing_lines`' 0.75 ft tolerance are all
unchanged.
