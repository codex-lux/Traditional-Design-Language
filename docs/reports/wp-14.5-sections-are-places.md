# WP-14.5 — sections are places

*24 September 2026. Branch `wp-14.5`, built on `3976e94`. Scope: `workbench/app/src/citations.js`,
`workbench/app/src/router.js`, `workbench/app/src/state/nav.js`, `workbench/app/e2e/router-unit.mjs`
and this report, nothing else. The contracts are
`docs/prd/phase-14-the-dossier-and-the-journey.md` §0.1, §D, §E and §J; the analysis they answer is
`docs/reports/ux-first-principles-2026-09-24.md`. Every figure below was measured on this tree, in
this worktree; nothing is quoted from another report. Cite this report by filename.*

## What it is for

The rebuilt workbench reads one style whole, in a dossier of nine sections, and it needs those
sections to be addresses before any surface draws them: a reader has to be able to send
`#/style/craftsman/lineage` to a colleague, and a citation the corpus writes has to be able to
open a section rather than a record's top. Two addresses the tree already had were wrong or
missing. **A constraint citation routed to the Plan Workbench, which reads no `constraint` from
its selection and never has** — every `constraint:` chip the rail has drawn landed the reader on
the bench with nothing on it about the rule. And there was no address for a glossary term at all.

The analysis also measured that every hop drops the style the reader is holding: a reader
studying Craftsman who follows a link to a pack or a fault arrives holding nothing. This package
gives the router the one rule for what may travel with a citation, and gives `nav.cite` the
argument to carry it.

It is **additive**. The kit surface and the `kit:`/`slot:` routes are exactly as they were; the
package that moves the kit into the dossier re-cuts them. No regex moved.

## I. What was built

**`citations.js`**

- `export const DOSSIER_SECTIONS = Object.freeze(['identify', 'members', 'lineage', 'kit', 'proportions', 'plans', 'rules', 'faults', 'evidence']);`
  on one line, in exactly §D.1's form, because the server's twin is held to it by a test that
  READS this file.
- `routeCite('style:<id>#<fragment>')`: a fragment in the vocabulary opens that section,
  `{surface: 'style', selection: {style, section}}`; `#identify` is an **alias** and routes with
  **no section key**, `{style}`; a fragment that is not a section — a slot id, or a word nothing
  knows — is dropped exactly as before.
- `routeCite('constraint:<id>')` → `{surface: 'style', selection: {style: <text before the last
  '.'>, section: 'rules', constraint: <id>}}`, or `null` for an id with no dot (or an empty style,
  `.c01`), because landing an unresolvable constraint on an arbitrary style is worse than not
  moving.
- `routeCite('term:<id>')` → `{surface: 'glossary', selection: {term}}`.
- `citeFor('style', s)`, in this order: `s.constraint` → `constraint:<id>`; no `s.style` → `null`;
  `s.section` in the vocabulary and not `identify` → `style:<id>#<section>`; otherwise
  `style:<id>`. **It never mints `style:x#identify`.** §E.3's second branch (the kit section,
  `kit:`/`slot:`) belongs to the package that moves the kit and is not here.
- `citeFor('glossary', s)` → `s.term ? 'term:' + s.term : null`.

**`router.js`**

- `SURFACE_PATHS.style.keys` is `['style', 'section', 'slot']`, so `#/style/<id>/<section>` and
  `#/style/<id>/kit/<slot>` are both addresses, with the existing `-` placeholder holding an
  absent style (`#/style/-/kit/cornice`).
- `SURFACE_PATHS.glossary = {path: 'glossary', keys: ['term']}`.
- `SELECTION_KEYS` gains `'section'` and `'term'`, **appended after `'asset'`**, because
  `formatHash` writes query keys in that list's order and a key inserted in the middle would
  reorder the query of every existing link carrying two of them.
- `export const CONTEXT_KEYS = Object.freeze({proportions: ['style'], faults: ['style'], brief: ['style']})`
  (inner arrays frozen as well — §V).
- `export function withContext(target, ctx)` → a new target whose selection gains `ctx[k]` for each
  `k` its surface lists, where `ctx[k]` is a non-empty string and the target names no value of its
  own for `k`. The target always wins; unlisted keys are dropped; a surface with no entry returns
  the target unchanged; a null target returns `null`; nothing is mutated.
- `export function hrefFor(cite, ctx)` → `formatHash` of `withContext(routeCite(cite), ctx)` with no
  params, or `null`. §E.5 and §K list it beside `withContext`; it is the anchor's half of the same
  rule, so a link drawn and a link clicked land in one place.

**`state/nav.js`**

- `cite(ref, ctx)` is `write(withContext(routeCite(ref), ctx))` with no params. With no `ctx` it
  is the call it always was, which is what every existing caller makes.
- `go(surface, selection)` is unchanged and its comment now says why it takes no context: a rail
  link carries exactly the selection it names.

**`e2e/router-unit.mjs`** — 63 checks before, **124** after.

- The constraint pin is **re-cut, not re-pinned**: the parse half is untouched and the route half
  now asserts the constraint lands on its own style's rules section and that `citeFor` names it
  again from there.
- `KINDS` gains `style:craftsman#lineage` and `term:judgment-unjudged`; the identity, the URL round
  trip and the `#/cite/` form all hold for both.
- The **alias** is asserted apart from `KINDS`, never in it: `style:craftsman#identify` routes to
  `{style}` with no section, its address is `#/style/craftsman`, and a hand-typed
  `#/style/craftsman/identify` is read and cited as `style:craftsman`. A test fails if an alias ever
  enters the identity list.
- Every `DOSSIER_SECTIONS` value round-trips through a URL: the selection survives `formatHash` →
  `parseHash` exactly, and every section but `identify` is its own citation, routes back to the same
  selection and draws the same address. The vocabulary is asserted by its **properties** (frozen, no
  duplicate, `identify` first, every id a fragment the grammar can carry and a path segment needing
  no escape) and **not** by its words, because a third spelling of the list in a test is one more
  thing to drift.
- `#/style/tidewater-georgian/rules?constraint=tidewater-georgian.c01` parses to the rules section
  with the constraint selected, inverts to `constraint:tidewater-georgian.c01`, is the canonical
  form `formatHash` writes, and is what `hrefFor` draws for that citation.
- **A corpus sweep**: every constraint every style node states must route to THAT node. This reads
  `styles/` from the checkout, deliberately — *"a constraint opens its own style"* is a claim about
  the corpus, and a constraint filed under one style with another style's prefix would otherwise
  route silently to the wrong dossier. It asserts its premise (files read, constraints seen) so a
  moved directory cannot pass it over nothing.
- **Context carry**: every surface in `SURFACE_PATHS`, from an empty selection, gains exactly the
  keys `CONTEXT_KEYS` lists for it and nothing else, against a context carrying eight keys of which
  one may travel; the three contracted targets take the style by citation; the kit, the phylogeny,
  a style section, a constraint, a term, a candidate and a plan room take nothing — the kit and the
  phylogeny carry `style` in their own paths, which is exactly where a carried value would silently
  change which record is shown; the target wins; only a non-empty string travels; a null target
  stays null; nothing is mutated; and the carried key survives the address while the page is still
  cited by the pack alone.
- **The join**: `withContext` being right says nothing about whether `nav.cite` calls it, so section
  7 imports `state/nav.js` behind a stand-in `location` (the module reaches `location`, `history`
  and `window` only behind `typeof` guards and follows a citation with `location.hash = …`) and
  drives it: `nav.cite` carries the style onto a pack, carries nothing onto the kit, is unchanged
  with no context, does not move on an unresolvable citation, and `nav.go` carries nothing across a
  surface boundary; then, for every kind, the address a click reaches is the address `hrefFor`
  draws.
- The table-agreement checks are kept verbatim and hold because `SELECTION_KEYS` gained `section`
  and `term`; a new one holds `CONTEXT_KEYS` to surfaces that have a route and keys the URL can
  carry.

## IV. What was found

**1. The constraint route pointed at a surface that reads nothing, and the pin guarding it
asserted exactly that.** `router-unit.mjs` held `routeCite('constraint:…')` to
`{surface: 'workbench', selection: {constraint}}` under a comment about the dot in the id — a
correct regression pin for the parse, attached to a route no surface honoured. It went red on the
change at once, which is a guard moving with its subject; the re-cut keeps the parse half verbatim
and states the route's property. Nothing in the tree still writes a `#/workbench?constraint=`
address (swept); one written before this package still parses to the bench, and `citeFor` names it
by the constraint, which now opens where the rule is stated. It is not canonicalised, because
nothing produces it.

**2. My own byte-identity instrument read DIFFERS on an unchanged file.** Comparing the grammar's
four definitions against `3976e94`, the first run reported three of four different. They were not:
the script compiled every pattern with `re.S`, so `.*$` ran to the end of the document on the three
one-line definitions and compared everything after them. Fixed, it read identical — and that was
not believed until the same instrument was pointed at a copy with `ID_CHARS` narrowed by one
character and reported exactly that one line. An instrument's first answer is a reading of the
instrument; it had to be made to fail correctly once before its "identical" meant anything.

**3. Between this merge and WP-14.8's, `#/glossary` draws the bench.** Measured, not read:
`App.jsx:158` falls back to `PlanWorkbench` for an id its `SURFACES` map does not hold, the page
throws nothing, and the rail marks no item current — the one honest signal that the reader is not
on the bench's own address. §E.1 records this interim and nothing links there; it is stated here so
a reader who types the address is not surprised by it.

**4. There is a window in which this client can mint a citation the server's validator refuses.**
`citeFor` now writes `style:<id>#<section>` and `term:<id>`, and until WP-14.3 lands
`citations.validate` answers *"unknown slot fragment 'lineage'"* for the first and *"unknown
citation kind 'term'"* for the second — §0.1 row 13 records it. **Nothing emits either to the
server during that window**: `citeFor` and `citeForPlace` have no caller in the app today (swept),
and the rail's citations come from the server's own extractor and validator, which this package
does not touch.

**5. A constraint citation opens the right record and highlights nothing yet.** `StyleRecord`
reads only `selection.style`, so `#/cite/constraint:tidewater-georgian.c01` now shows Tidewater
Georgian's record at its head (measured in the browser) where it used to show an empty bench, with
the rules section and the constraint carried in the address for the dossier to honour. Drawing the
section and marking the constraint is WP-14.12's, per §E.2.

**6. The walk's reachability loop does not meet the new route.** It moves off the current item with
`Object.keys(SURFACE_PATHS).find((s) => s !== here)`, whose answer is `overview` or `phylogeny`, and
WP-14.7's report records deliberately not asserting that every route has a rail item. A route with
no rail item therefore adds no red, which is what a route arriving before its surface needs.

## V. Deviations from the contract

1. **`citeFor`'s section branch is gated on the vocabulary.** §E.3 reads *"`s.section` present and
   not `identify` → `style:<s.style>#<s.section>`"*; this writes the section only when it is in
   `DOSSIER_SECTIONS`, and returns the bare `style:<id>` for a section id the vocabulary does not
   hold. For every section any writer in the app produces the two are identical. They part only on a
   hand-typed `#/style/x/nonsense`, where the contract's reading would mint `style:x#nonsense` — a
   ref the server's validator refuses under §E.6's own rule, and one `routeCite` reads straight back
   as the bare style, so it would break the identity the two functions exist to keep. Asserted by
   M9, so a package re-transcribing §E.3 literally meets it.
2. **`CONTEXT_KEYS`' inner arrays are frozen too**; §E.5's literal freezes the outer object only.
   No reader that does not mutate the table can tell, and one that does would widen the carry for
   every caller at once.
3. **`hrefFor` is exported** although the brief named only `CONTEXT_KEYS` and `withContext`; §E.5 and
   §K both list it, and it is the anchor's half of `nav.cite`.
4. **`router-unit.mjs` is no longer only pure functions.** Its constraint sweep reads `styles/` and
   its section 7 imports `state/nav.js` behind a stand-in `location`; the file's header says both.
   There is still no DOM and no server, and `build/check_frontend.py` runs it unchanged.

## VI. What was deliberately not done

- **No regex, no fourth spelling.** `ID_CHARS`, `FRAG_CHARS`, `REF_RE` and `parseCite` are
  byte-identical to `3976e94`; the vocabulary is a frozen list and the constraint rule is a
  `lastIndexOf`.
- **The kit is untouched**: the `kit` surface and path, `kit:` and `slot:` routing, `citeFor('kit')`,
  and the existing `#/kit/…` shapes and their pins. `style:<id>#<slot>` is still dropped; routing it
  into the kit section, `LEGACY_PATHS` and the canonicalisation of `#/kit/…` are WP-14.12's.
- **`formatHash` does not special-case `identify`.** The rule that no writer emits
  `#/style/<id>/identify` is held where writers get their addresses — `routeCite` never produces the
  section and `citeFor` never mints it — rather than by a surface-specific branch in a generic
  serialiser. A surface handed `{section: 'identify'}` by hand would still write it; the dossier's
  section strip, when it exists, is where that is decided.
- **No test pins the section list's words** (see §I). The server's tuple and the agreement test
  that holds the two together are WP-14.3's.
- **No `App.jsx` edit.** The glossary's component, its `SURFACES` entry and anything that passes a
  context to `nav.cite` belong to later packages; today every caller passes none.
- **`walk.mjs` is untouched**; it was run, not edited.
- **`build/check_all.py` was not run whole** on this tree. The parts of it that read these four files
  were run: `check_frontend.py` (judged, after a build), the app suite (`npm test`), and the server
  and repository tests that read `citations.js` or `router-unit.mjs` by path
  (`test_grammar_agreement.py`, `test_citations.py`, `test_check_frontend.py`,
  `test_search_index.py`). Nothing outside `workbench/app` imports these modules.
