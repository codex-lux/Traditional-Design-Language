# Deployment-readiness review, 27 November 2026

Reviewed at `5f5a2a7` (main, the merge of PR #48). Written before any fix was made. Section VIII
records what the fixes changed.

The brief's context block arrived unfilled, so the target, the launch type and the load are read
off the repository: a Railway container (`docs/deployment.md`), one replica, a shared password, a
handful of readers. Where a finding depends on that reading, it says so.

## I. Verdict

**GO-WITH-CONDITIONS, for the deployment the repository describes: a private, password-gated
reference on one replica, used by a few people.** It is **NO-GO as an open public launch.** Nothing
found loses data (there is none to lose: no database, no volume), and no secret is in the tree or
its history. The server's attack surface has been audited several times and the probes run here
found it sound. The conditions are about what happens when configuration is wrong, what an
operator can see, and whether a build can be reproduced.

Conditions, in order:

1. **A password must gate any public bind.** Today a container started without
   `WORKBENCH_PASSWORD` serves everything, the assistant included, to anyone (DR-01). Fixed in
   this branch.
2. **A spend limit must be set on the Anthropic key in the Console.** The server's caps slow
   spend and cannot bound it (DR-09). Owner action.
3. **The Python dependencies must be pinned.** The image installs whatever `>=` resolves to on
   the day it is built, which is not what CI tested (DR-02). Fixed in this branch.
4. **Decide what "CI green" means before trusting the deploy gate.** The last five completed CI
   runs on `main` all failed, by standing rulings, so the gate cannot tell a regression from the
   known reds (DR-03). Owner decision.
5. **Keep it to one replica and expect about one concurrent editor.** Measured by the
   infrastructure audit, not by this review (DR-12).

## II. Blockers

A blocker here is something that would leak, cost money, or make a deploy unrecoverable.

### DR-01. A public bind with no password serves everything, and spends the operator's key

- **Evidence.** `workbench/server/auth.py:55` (`required()` is false when neither variable is
  set) and `:192` (`authorised` then returns true). `workbench/server/__main__.py:51` prints a
  note and starts. The Dockerfile sets `WORKBENCH_HOST=0.0.0.0` (`Dockerfile:25`).
- **Impact.** One forgotten variable on the platform and every `/api` route, `/mcp` and the
  assistant answer strangers. With `ANTHROPIC_API_KEY` set, anonymous callers spend it, up to
  the 200-turn daily ceiling.
- **Why it is a blocker.** The repository's own rule is that an absent check is not a passed
  one. `/api/health` does say the server is open, but only to someone who asks.
- **Fix.** Refuse to start on a non-loopback bind with no gate, unless `WORKBENCH_ALLOW_OPEN=1`
  says the operator means it. Local use on `127.0.0.1` is unchanged.

### DR-02. The image is built from unpinned dependencies

- **Evidence.** `workbench/requirements.txt` uses `>=` floors throughout. `Dockerfile:40`
  installs it. Resolved here today: fastapi 0.165, starlette 1.7, mcp 2.3, anthropic 1.17 (`pip
  list`). No lock file exists for Python. The npm side is locked (`package-lock.json`, `npm ci`).
- **Impact.** The CI `workbench` job and the image build resolve separately, so the image can
  ship versions no test ran against. The file's own comments record two such breaks already (the
  `mcp` 2.0 rename, `anthropic` 0.x). A rebuild of an old commit is not the old build.
- **Fix.** Commit a lock compiled for Python 3.11 and install it in the Dockerfile and in CI.

What was checked and found sound, so it is not a finding:

- **Secrets.** No key-shaped string in the tree or in `git log --all -p` (patterns for Anthropic,
  AWS, GitHub, Slack and PEM keys). `.gitignore` covers `.env`.
- **The gate.** Signed out, every `/api` path tried answered 401 except the three in
  `auth.OPEN_PATHS`, including `/api//overview`, a trailing slash, and `%2e%2e` forms. `/mcp`
  answers 401.
- **Path traversal.** Encoded traversal against `/`, `/assets`, `/corpus/assets/generated`,
  `/api/plans/examples` and `/api/partis` returned the shell or a 404, never a file.
- **The session cookie.** `HttpOnly`, `SameSite=lax`, `Secure` when the request is https. With
  `SameSite=lax` and JSON bodies, cross-site POSTs carry no session.
- **Login body handling.** A list body and a `text/plain` body both answer 422.
- **Dependencies.** `pip-audit` on the resolved set and `npm audit --omit=dev`: nothing known.
- **The assistant's model call.** `claude-sonnet-5` and `output_config.effort` are both valid
  against the current API reference.
- **Bounded memory.** The solve cache (64), the rate table (50,000 keys, reaped), the job store
  (30 minutes), the queue (8), the request body (8 MB).

## IV. System map

- **What it is.** A corpus of traditional-architecture rules as JSON in git, a Python toolchain
  over it (`build/`), and the Workbench: a FastAPI server (`workbench/server/`) with a React
  single-page app (`workbench/app/`, Vite). The same tools are served to agents over MCP at
  `/mcp`.
- **Stack.** Python 3.11 in CI and the image; FastAPI, uvicorn, OR-Tools, ezdxf, ifcopenshell,
  the Anthropic SDK, the MCP SDK. Node 20, React 18, three.js, Vite 5.
- **State.** None on disk. In memory: signed session cookies, rate counters, the job registry,
  solve caches. A restart loses jobs in flight and, without `WORKBENCH_SECRET`, sessions. Plans
  live in the browser's `localStorage`.
- **Outside services.** The Anthropic API (the assistant). Google Fonts (the shell). Nothing
  else: no database, no queue, no email, no payments, no analytics.
- **Entry points.** About 45 routes under `/api`, two event streams (compose jobs, the
  assistant), `/mcp`, static files, and `/api/health`.
- **Build and deploy.** `Dockerfile` in two stages; Railway builds from git; `/api/health` is the
  healthcheck; CI is `.github/workflows/ci.yml` (six corpus shards, a workbench job, an image
  build).
- **Critical journeys.**
  1. Open the site and sign in.
  2. Read the library: a style, its kit, a fault, the proportions.
  3. Brief to candidates (the compose job and its stream).
  4. Open a plan on the bench, evaluate it, drag a wall.
  5. Drawings and CAD export.
  6. Ask the assistant.
  7. An agent connects to `/mcp` with the bearer token.

## VI. Post-launch watch list, first 72 hours

| Watch | Where | Roll back or act when |
|---|---|---|
| Container restarts | platform | any restart not caused by a deploy |
| Memory | platform | steady growth past 80% of the plan |
| `/api/health` latency | external ping, every minute | over 5 s three times running |
| Errors logged by `tdl.jobs` and `tdl.rail` (after DR-05) | platform logs | more than a few an hour, or any repeated traceback |
| Anthropic spend | Console | over the expected daily figure by 3x |
| 401 and 429 rates on `/api/login` | platform logs (needs an access log, DR-07) | a burst of 401s from many addresses |
| Compose answers | by hand, once a day | a set that never returns, or `unknown job` |

Rollback is a redeploy of the previous image. Nothing is migrated, so nothing is stranded but
jobs in flight and, in browsers, plan documents written by the newer app.

## VII. What was not checked

- **The production host.** No access, by rule. Its variables, its proxy's forwarding headers, its
  CPU count and whether "Wait for CI" is on are all unknown.
- **The image.** Docker's daemon is not available in this environment, so the image was not
  built or started. DR-11 stands on reading.
- **A live assistant turn.** No key, and none was asked for. The model id and parameters were
  checked against the API reference; the error path was read.
- **The whole corpus suite.** About an hour, and its known reds are recorded in CLAUDE.md. The
  server suite and the app suite were run (section VIII).
- **Load.** Not re-measured. DR-12 quotes the August audit.
- **Accessibility, cross-browser, mobile layouts.** Not audited here. Phase 17 and 18 record
  contrast work and state that no rendered-contrast audit of the paper pages was run.
- **Email, payments, webhooks, migrations, backups.** The system has none.
- **Compliance regimes.** None was named.
